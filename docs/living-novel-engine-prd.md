## 2. 产品定位

### 2.1 一句话定位

未终章不是“帮你续写一段小说”的工具，而是一个会继续运行的故事世界：角色有记忆、有立场、有误判，读者干预会进入世界并留下后果，作者可以从世界演化中采纳新剧情。

### 2.2 产品定义

未终章将用户导入或创建的文本组织成可运行世界，包括世界规则、角色、关系、记忆、世界线、因果债、章节正文和作者采纳记录。用户既可以像读小说一样连续阅读，也可以像观察者一样看世界自演，还可以投放干预或作为作者采纳沙盘涌现剧情。

产品不要求用户理解 CLI、artifact 或工程面板。前端是产品入口，API 是能力层，CLI 只用于本地启动、自动化验证、批处理和开发者复跑。

### 2.3 与相邻产品的差异

| 类型 | 常见方式 | 未终章的差异 |
| --- | --- | --- |
| 传统小说 | 作者写定，读者阅读 | 读者可观察、干预和追踪分叉 |
| 互动小说 | 选择预设分支 | 用户输入自由变量，由世界吸收、抵抗或代偿 |
| AI 续写器 | 根据上文生成下文 | 先维护世界状态、角色记忆和因果债，再渲染正文 |
| AI NPC 对话 | 与单个角色聊天 | 以世界线、章节、多视角卷宗和作者采纳为核心 |
| 写作工作台 | 管理设定和章节 | 让角色行动和世界演化反过来提供可写材料 |

## 3. 当前主体验

主导航按“世界”组织，而不是按工程面板组织：

```text
世界书架
  -> 某个故事世界
      -> 天命书
      -> 世界沙盘
      -> 世界正史卷
      -> 主锚点卷
      -> 角色个人卷
      -> 势力卷
      -> 事件多视角
      -> 世界线
      -> 检查点
      -> 作者采纳台
```

“沙盘 / 阅读 / 干预 / 作者”只是同一个世界里的场景能力，不作为一级工作区。

### 3.1 导入或创建世界

用户可以通过三种方式开始：

- 导入已有文本：本地 txt/md/zip/epub 或原创稿，生成章节、记忆、正史账本和审计报告。
- 主题创世：输入题材、主题、主角和大致内容，生成可运行世界和第一章。
- 内置样例：用户没有素材时也能立即体验世界沙盘。

当前代码已更偏向导入路径；主题创世和内置样例仍应作为产品入口继续完善。

### 3.2 世界锚定

世界锚定的目标是让用户确认“这是什么世界、哪些规则不能乱破、谁是关键角色、当前伏笔和风险是什么”。

已经具备的底座包括导入报告、分层记忆、正史账本、实体别名、静态一致性审计、设定工作台和运行前体检。它们是世界沙盘的支撑材料，不应重新变成默认主线。

### 3.3 天命书

《天命书》是世界线宪法雏形，记录叙事吸引子、锚点状态、合约压力、候选天命承载者和干预边界。

用户体验上，它应该回答：

- 这个世界正在被什么命运吸引？
- 哪些角色、地点、谜团或势力是锚点？
- 哪些干预会被世界吸收，哪些会导致分叉或代偿？
- 当用户强行改命时，世界会付出什么代价？

### 3.4 世界沙盘

世界沙盘是核心引擎体验。每轮至少应体现：

- 角色依据私有目标、主观记忆和误判行动。
- 多角色之间形成信任、怀疑、试探、欺骗、妥协或反抗。
- 事件改变世界状态、传播信息、制造因果债。
- 结果可以成为章节素材、卷宗证据或下一轮沙盘入口。

当前已形成第一版链路；后续重点不是再补工程面板，而是让真实模型下的多 Agent 决策更少模板感、更像策略博弈。

### 3.5 读者干预

用户干预不是选择 A/B/C，而是向世界投放变量，例如低语、梦境、谣言、信件、资源、危机、新事件或异物入侵。

干预编译器应解释：

- 干预属于轻微偏移、重大分歧、时代改写还是世界级破坏。
- 世界会本土化吸收、生成 AU 分支、产生因果债，还是引发角色觉醒和反抗。
- 该干预会影响哪些角色记忆、锚点和后续章节素材。

### 3.6 世界自演

睡前启动后，用户醒来不应只看到 JSON 或工程报告，而应能从结果页直接进入：

- 最近关键检查点。
- 主角或关键角色个人卷。
- 关键事件多视角。
- 下一段连续阅读。

结果页必须说明为什么世界状态变了、谁记住了什么、哪条因果债正在发酵。当前已有 `readable_entry` 第一版，后续需要更小说化的醒来报告节奏和更清晰的长期阅读进度。

### 3.7 卷宗阅读

卷宗阅读页的默认体验是读小说，不是读素材表。

默认正文态应提供连续阅读；用户可以切换：

- 世界正史卷：世界层面的已发生事实。
- 主锚点卷：围绕主角或关键锚点的叙事线。
- 角色个人卷：角色以自身认知理解事件，允许误会和偏见。
- 势力卷：群体目标、资源和冲突。
- 事件多视角：同一事件下不同人的所见、误判和证据链。

证据链默认折叠，不打断正文。当前卷宗阅读页已完成第一版；后续重点是正文内锚点跳转、误会图谱、跨章节回收和更自然的长文风格。

### 3.8 作者采纳台

作者采纳台不是报告面板，而是把沙盘涌现转成可写材料的地方。

它应支持：

- 对比原大纲与沙盘涌现剧情。
- 采纳、部分采纳、另开分支或导出 brief。
- 查看 Reviewer 片段级问题、修改意图、建议改写和影响范围。
- 勾选局部重写建议，生成编辑后定稿。
- 将定稿确认入卷，并反哺下一章草稿和下一轮沙盘入口。

当前“局部重写 -> 作者采纳 -> 编辑后定稿 -> 确认入卷”已闭环第一版；后续重点是更强真实语义 Reviewer、整章风格润色和真实模型编辑器。

## 4. 用户价值

### 4.1 网文读者

- 续写断更文本。
- 拯救意难平角色。
- 探索不同世界线。
- 看角色是否会反抗自己的干预。

### 4.2 同人创作者

- 快速生成平行世界设定。
- 保持角色动机和关系一致。
- 将沙盘涌现剧情转成可继续加工的大纲和正文。

### 4.3 原创作者

- 压力测试大纲。
- 检查反派、配角和群像是否有独立行动逻辑。
- 从角色自主行动中发现新冲突和伏笔。

### 4.4 互动叙事爱好者

- 体验非预设分支。
- 观察世界自演。
- 像高维存在一样投放变量，同时承担世界代偿。

## 6. 当前真实未做项

这些是当前主线仍需深入的产品能力：

1. 真实 LLM 多 Agent 策略博弈：私有目标、信息差、误判、欺骗、反抗、妥协和长期关系还需要更稳定地影响行动。
2. 长正文与连续阅读质量：正文仍需减少卷宗/说明文痕迹，增强开场钩子、冲突递进、视角切换、伏笔回收和结尾悬念。
3. 正文内证据锚点与误会图谱：读者应能在不离开阅读流的情况下查看证据、认知偏差和不同角色的误解来源。
4. 更强真实语义 Reviewer：Reviewer 要像小说编辑一样判断人物动机、冲突张力、世界状态入文、视角稳定和章节好读度。
5. 整章风格润色与真实模型编辑器：当前局部重写可入卷，后续要支持整章语气、节奏、文风一致性和更自然的定稿闭环。
6. 角色/势力独立卷：当前主要由卷宗阅读 tab 承载，后续应有更完整的角色长期记忆、势力目标和事件索引。
7. 世界自演醒来报告文学化：结果页已经能串入口，但 timeline 摘要仍可更像小说世界发生过的一夜，而不是运行摘要。

## 7. 明确后置或支撑层

以下能力已经有支撑层证据或本地边界，但不作为默认下一刀：

- GraphRAG / Zep / 图数据库。
- 默认启用 hybrid vector 替换 BM25。
- provider spike 和模型路由扩张。
- OpenAPI / typed client 面板深化。
- 发行安装包、服务器在线体验、自动部署。
- 真实认证、对象存储、云端队列、配额执行、计费和商业化平台。
- 纯工程健康报告或继续往 `WorkspacePage` 堆只读面板。

只有当它们直接服务世界运行、角色自主、角色记忆、干预后果、角色反抗、世界代偿或章节生成时，才进入主线讨论。

## 8. 非目标

当前阶段不做：

- 未授权商业小说公开续写分发。
- 大规模社区分发。
- 真实 SaaS 多租户平台。
- 完整商业计费、发票、余额、webhook。
- 3D 可视化世界。
- 完全无人审稿的长篇自动连载。
- 以工程面板替代普通用户阅读和创作体验。

## 9. 验收口径

一个新切片不能只因为有 API、artifact、页面和 mock 测试就宣布产品完成。当前主线验收要看用户是否真实感到：

- 世界会继续运行。
- 角色会自主行动。
- 角色会记住并误解过去。
- 干预会留下后果。
- 角色可能反抗或曲解用户意图。
- 世界会代偿。
- 章节正文来自世界演化，而不是模板说明。
- 作者能把审稿意见转成可写材料。

涉及叙事生成、Agent 决策、多视角正文、Reviewer 或视觉生成质量的切片，除了 mock 回归外，应做小样本真实模型 smoke；不打印明文 key，不把真实外网调用放进默认全量 pytest。
