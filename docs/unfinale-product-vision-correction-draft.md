## 1. 原始动机

未终章最初来自一个阅读小说时产生的问题：

传统小说的主要关系是“读者与书”的沟通。再进一步，是“读者与作者”的沟通。小说中的每一个剧情走向，通常都由作者预先规定；读者只能阅读作者安排好的结果。

但很多小说和作者都表达过一种更有张力的想法：

- 角色似乎拥有自己的命运，不完全受作者控制。
- 作者有时会说，人物写着写着就“活了”，会自己做出选择。
- 某些作品会让主角、配角或反派打破第四面墙，意识到自己被叙事、作者或更高维存在安排。
- 一个足够真实的角色，不应该只是剧情工具，也不应该机械执行外部命令。

于是未终章想验证的是：

> 能否把小说从“被作者写完的静态文本”，变成一个持续运行、可以观察、可以干预、可以分叉，甚至会反向凝视读者的故事宇宙？

## 2. 产品核心定义

未终章不是普通续写器，也不是单纯的 AI 写作助手。

它更接近一个小说世界沙盘：

> 作者设计世界规则、人物灵魂和命运边界；角色基于欲望、记忆、关系、利益和处境自主行动；系统把角色行动和世界变化推演成后续剧情，再由叙事生成器写成可读章节。读者或作者可以向世界投放变量，但世界不会机械服从，角色可能抵抗、误解、利用，甚至察觉命运被外力扭曲。

一句话版本：

> 未终章 = 小说世界沙盘 + 命运干预系统。

## 3. 双入口定位

未终章应该同时支持作者和读者，但底层不应拆成两套系统。

### 3.1 作者入口：剧情沙盘

作者已经有自己的设定、大纲、章节、人设、势力关系和命运边界。

作者不需要系统替他完全从零写作，而是需要一个沙盘推演功能：

- 把已有设定、大纲和章节放进来。
- 系统抽取人物、势力、地点、规则、冲突、伏笔和隐藏动机。
- 让角色按自己的人设、长期目标、记忆、利益和处境行动。
- 推演如果世界照这样运转，后面自然会发生什么。
- 帮作者发现新的剧情可能性、冲突高潮、伏笔兑现和意外转折。
- 输出可供参考的后续大纲、角色行动链、势力变化、世界状态 delta、章节 brief。

作者模式的核心价值不是“替作者写”，而是：

> 让作者看到自己的世界如果真的运行起来，会长出哪些他未必预先想到的剧情。

### 3.2 读者入口：世界线干预

读者可以导入已经完结或正在连载的小说章节，进入一个已有故事世界。

读者不再只是看作者安排的路线，而是可以下场干预：

- 拯救意难平角色。
- 改变某个关键事件。
- 给主角一个梦境提示。
- 让某个配角捡到一封信。
- 让信里出现这本小说的大纲。
- 让某个配角重生并拥有未来记忆。
- 投放系统、灾难、资源、谣言、神器、危机或新事件。

但读者不能简单决定结果。世界会自行消化这次干预，角色会根据自身逻辑回应。

读者模式的核心价值不是“想怎么改就怎么改”，而是：

> 读者像高维存在一样投放变量，观察世界如何抵抗、转译、分叉和反噬。

## 4. 共享底层流程

作者模式和读者模式共享同一条底层能力链：

```text
设定 / 大纲 / 章节 / 已有小说文本
  -> 世界抽取
  -> 角色 / 势力 / 地点 / 规则 / 伏笔 / 领域记忆模型
  -> 角色主观记忆链
  -> 多 Agent 沙盘推演
  -> 世界状态变化
  -> 叙事规划
  -> 正文生成 / 世界线分支
  -> Reviewer 检查
  -> 作者或读者再次干预
```

其中：

- 世界抽取负责把静态文本变成可运行资料。
- 领域记忆模型负责定义哪些内容属于正史、世界状态、角色主观记忆、秘密、误解、干预痕迹和跨世界线残影。
- 角色主观记忆链负责让每个角色在每条世界线上拥有自己的长期记忆，并在每轮后追加新认知。
- 多 Agent 沙盘推演负责让角色和势力自己行动。
- 世界状态变化负责记录关系、资源、秘密、位置、伤势、记忆和伏笔状态。
- 叙事规划负责把沙盘结果整理成下一章大纲、冲突高潮和伏笔安排。
- 正文生成负责把推演结果写成小说章节。
- Reviewer 负责检查人设、节奏、爽点、连续性和伏笔偏移。

### 4.1 领域记忆模型

领域记忆模型不是某个外部数据库，也不是 GraphRAG 或 Zep 的同义词。

它指的是未终章自己定义的一套记忆规则：

> 在小说世界里，哪些信息应该被谁记住，以什么身份存在，在哪条世界线上有效，能不能被其他角色知道，能不能影响下一轮行动。

同一件事在不同层里含义不同：

```text
正史事实：第三章 Bob 偷走了钥匙。
Alice 的主观记忆：第三章我看到 Bob 半夜经过库房，因此我怀疑他。
Bob 的主观记忆：我偷了钥匙，但 Alice 应该没有证据。
公开世界状态：钥匙失踪，库房门锁被撬。
秘密：Bob 是偷钥匙的人。
误解：Alice 以为 Bob 是为反派做事，其实 Bob 是为保护她。
读者干预痕迹：读者让 Alice 做了一个关于钥匙的梦。
世界线残影：高觉察 Alice 偶尔梦见另一条世界线里 Bob 被当场抓住。
```

如果没有领域记忆模型，这些信息很容易被混成“全局摘要”。一旦混用，角色就会突然知道自己不该知道的事，或忘记自己应该记住的事，沙盘也会失去主体性。

因此第一版应该先用本地、可审计、可测试的领域记忆模型做主真源。GraphRAG、Zep、向量库或其他 memory layer 只能作为后续索引层和召回增强层，不能替代主真源。

### 4.2 角色主观记忆链

角色主观记忆链是领域记忆模型中最核心的一层。

它要求：

- 每个角色都有自己的记忆，互不混用。
- 每条世界线都有自己的记忆演化。
- 分叉前的记忆共享，分叉后的记忆各自追加。
- 每轮行动后，系统要把该角色本轮看到什么、做了什么、形成什么新认知写入它自己的长期记忆。
- 下一轮决策时，该角色优先读取自己的记忆，而不是读取整本书的全局摘要。
- 高觉察时，角色可以模糊感知到其他世界线或轮回中的残影，但这必须作为特殊记忆类型处理，不能和普通事实混在一起。

示例：

```text
世界线 W 第 3 轮：
Alice 记得：我看到 Bob 说了 X，因此更怀疑他。
Bob 记得：Alice 没有回应我，我觉得被冷落。

W 分叉为 W1 / W2：
W1 和 W2 都继承第 3 轮前 Alice 与 Bob 的记忆。

W1 第 4 轮：
Alice 追加记忆：Bob 主动解释了 X，我的怀疑下降。

W2 第 4 轮：
Alice 追加记忆：Bob 避开了我，我的怀疑加深。
```

候选本地 artifact 可以先设计为：

```text
memory/subjective/
  <worldline_id>/
    <character_id>.jsonl
```

每条记录可以包含：

```json
{
  "round": 3,
  "saw": ["Bob 说了 X"],
  "did": ["我没有回应 Bob"],
  "inferred": ["Bob 可能在隐瞒"],
  "emotion_delta": "怀疑上升",
  "relationship_delta": {"bob": "更不信任"},
  "secrets": ["我没有把怀疑告诉任何人"],
  "confidence": 0.7,
  "visibility": "private",
  "source_event_ids": ["evt_x"]
}
```

第一版目标不是接重型图数据库，而是先证明：

> 角色会因为自己记住的事而改变下一轮行动。

## 5. 三层读者交互

读者侧的魅力可以整理成三层。

### 5.1 第一层：观察

读者像看小说一样阅读。

但每一章不是完全提前写死，而是系统根据当前世界状态生成。同一本小说，不同读者、不同干预历史、不同世界线，可能看到不同剧情。

这一层的关键是：

- 世界状态持续存在。
- 角色记得发生过什么。
- 章节来自当前世界，而不是孤立续写。
- 读者能感到“这个世界正在运行”。

### 5.2 第二层：干预

读者可以向小说世界投放变量，而不是点击预设选项。

干预可以是：

- 梦境。
- 低语。
- 信件。
- 谣言。
- 天气。
- 资源。
- 危机。
- 系统。
- 重生记忆。
- 新人物或新事件。
- 某个秘密被提前泄露。

干预必须先被世界观转译。

例如用户在魔幻题材里让主角捡到 AK-47，系统不应直接把现代枪械硬塞进去，而可以转译为：

> 矮人打造的神器“雷鸣弓”，可发出连珠雷火，威力和使用代价符合当前世界规则。

这一层的关键是：

- 用户输入的是变量，不是最终剧情。
- 系统负责把变量转成世界内可消化的事件。
- 不合理干预可以被降级、转译、拒绝或另开 AU 世界线。
- 每次干预都应产生可解释的因果变化。

### 5.3 第三层：反抗

角色如果足够活，就不应该只是执行用户命令。

例如：

- 用户想强行让女主爱上反派，女主可能根据记忆、人格和关系拒绝。
- 用户想让主角走爽文路线，但主角可能因为长期失败变得多疑、阴郁或不信任外部馈赠。
- 用户不断在关键时刻干预，角色可能逐渐意识到命运被某种外部力量扭曲。
- 角色可能追问：为什么我总是在关键时刻被安排？为什么我的选择被改写？你到底是谁？你是读者、作者，还是神？

这一层是产品最独特的地方：

> 读者不仅能凝视角色，角色也可能反向凝视读者。

## 6. 世界沙盘应该推演什么

沙盘推演不只是生成下一段文字，而是要模拟角色和世界如何反应。

一次推演至少应该回答：

- 每个关键角色接下来想做什么？
- 他们为什么这么做？
- 他们知道什么，不知道什么，误判了什么？
- 他们会主动出手、观望、结盟、背叛、隐忍，还是借刀杀人？
- 势力关系如何变化？
- 哪些伏笔被触发？
- 哪些秘密被暴露？
- 哪些资源、位置、关系、伤势或情绪发生变化？
- 这次变化会自然导向哪些后续剧情？
- 哪些剧情是作者可以参考的新可能性？

典型作者侧问题：

```text
如果主角第 5 章没有救那个小乞丐，100 章后的小镇守卫战还会赢吗？
```

典型读者侧问题：

```text
如果我提前把大纲放进一封信，让女主捡到，她会相信吗？会告诉主角吗？会被反派利用吗？
```

### 6.1 角色真的会自己行动

这是下一阶段的底座能力，不是可选增强。

无论是作者模式还是读者模式，系统都必须让角色和势力基于自身条件自主行动：

```text
世界状态 + 角色主观记忆 + 欲望 / 利益 / 关系 / 资源 / 误解
  -> 多 Agent 自主行动
  -> 关系、势力、资源、秘密、伏笔和故事锚点变化
  -> 新剧情自然生长
```

作者模式中，作者已经写好大纲、设定和章节。系统的价值不是替作者完全写作，而是把这个世界跑起来：

- 老皇帝驾崩后，大皇子、三皇子、镇国将军、邻国间谍、女主、反派会分别做什么？
- 如果主角第 5 章没有救小乞丐，后续守城战是否还会赢？
- 如果反派提前意识到主角背后可能有高人，他会隐忍、借刀杀人、试探，还是暗杀？
- 如果某个配角掌握了秘密资源，他是否会脱离原剧情安排，争夺新的叙事位置？

读者模式中，读者的干预也必须进入同一套沙盘：

- 读者让《三国演义》前期的刘备死亡，后续曹操、孙权、关羽、张飞、诸葛亮和各路诸侯应各自行动，形成新的权力格局。
- 读者让某个配角突然获得强系统，系统不能只写“配角变强”，而要推演他如何隐藏、试探、积累资源、挑战主角，甚至成功上位。
- 主角可能死亡，配角可能成为新主角，反派可能胜利，故事锚点可能转移。

这意味着沙盘不是“给出几段剧情建议”，而是要生成可追踪的角色行动链：

```text
第 1 轮：角色各自判断局势。
第 2 轮：角色选择行动、试探或隐忍。
第 3 轮：角色根据上一轮记忆形成误解、信任或怀疑。
第 4 轮：势力关系和故事锚点开始变化。
第 5 轮：系统输出新剧情可能性和下一章 brief。
```

最低要求：

- 至少 3 个角色或势力在同一变量下产生不同立场和行动。
- 每个行动都能追溯到角色欲望、记忆、利益、关系或误判。
- 每轮后写入角色自己的主观记忆链。
- 世界状态 delta 能说明哪些关系、资源、秘密、位置、伏笔发生变化。
- 允许故事锚点转移，而不是强行维护原主角不死或原剧情不变。

### 6.2 读者干预真的有后果

读者干预必须全部支持，但不能全部无脑满足。

用户可以自由输入任意干预，系统需要先把输入编译成世界可以处理的变量：

```text
Raw Reader Input
  -> 读取《天命书》
  -> 干预类型识别
  -> 干预层级判定
  -> 世界观兼容性审计
  -> 世界内转译 / 降级 / 拒绝 / 反噬 / AU
  -> lineage_type 判定
  -> 本次专属 Branch Axis
  -> 多 Agent 沙盘推演
```

#### 干预编译器与《天命书》的关系

干预编译器每次都必须读取《天命书》。

二者关系可以这样理解：

```text
《天命书》
  = 世界的宪法

干预编译器
  = 执行层面的因果法
```

《天命书》拥有最高优先级。一次普通读者干预不能直接颠覆整个世界的物理边界、类型承诺、叙事吸引子或锚点结构。干预编译器必须先读取《天命书》，再判断用户输入能否被当前世界吸收、需要怎样转译、是否产生因果债、是否进入 AU，或是否触发世界线代偿。

字段作用：

| 字段 | 对干预编译器的作用 |
| --- | --- |
| `genre_constraints` | 决定原世界对外部异质变量的容纳天花板。历史文不会把 AK47 当成本土自然产物，只能转译、标记异物入侵或进入 AU。 |
| `narrative_attractor` | 决定分支的发展方向。它像大势引力，会影响分支更容易长向哪里。 |
| `contract_pressure` | 决定分支的重力和推演代价。它让被救活的人、被改写的事件、被跳过的危机继续结算后果。 |
| `anchor_status` | 决定干预是否动摇当前锚点，以及是否需要评估锚点转移。 |
| `replacement_anchor_candidates` | 决定锚点失稳后有哪些候选天命承载者可被激活。 |

写入规则：

```text
L1 / L2 / L3 普通干预：
  绝对不能永久修改《天命书》。
  只能产生事件、记忆、分支、因果债、转译结果或临时状态。

L4 前提改写：
  通过底层审计后，可以写入当前世界线的《天命书》快照。
  例如系统降临、主角锚点改写、题材前提改变。

L5 元叙事干预：
  通过底层审计后，可以写入当前世界线的《天命书》快照。
  例如角色知道自己是小说人物、世界被读者操控、叙事规则成为世界规则。
```

因此，普通干预可以影响世界，但不能改写世界宪法。只有 L4 / L5 在通过审计后，才允许对世界线《天命书》的 JSON 字段进行永久性写操作。

#### 干预类型

| 类型 | 示例 | 核心问题 |
| --- | --- | --- |
| 信息型 | 低语、预知梦、谣言、未来大纲、神谕 | 角色信不信？如何验证？告诉谁？ |
| 行动约束型 | 必须去/不去某地，必须杀/救某人 | 角色服从、抗拒、延迟，还是被世界阻止？ |
| 物品/资源注入型 | 捡到武器、药、钱、信、神器 | 是否符合世界观？谁拿到？代价是什么？ |
| 事件注入型 | 天灾、刺杀、政变、战争、系统公告 | 哪些势力响应？谁获利？谁被迫行动？ |
| 身份/记忆改写型 | 重生、穿越、获得未来记忆、知道自己是配角 | 是否改变人格、目标、阵营或觉察？ |
| 规则/题材改写型 | 给主角系统、现代科技乱入、修仙变赛博 | 是否改写小说前提？是否开启 AU？ |
| 关系/情感强扭型 | 让女主爱上反派，让兄弟背叛主角 | 是否违反人设？角色会反抗还是产生代价？ |
| 叙事身份改写型 | 配角上位、主角死亡、反派成为新主角 | 故事锚点是否转移？原主线是否坍缩或改写？ |

#### 干预层级

| 层级 | 含义 | 例子 | 结果倾向 |
| --- | --- | --- | --- |
| L1 世界内变量 | 当前世界规则能自然吸收 | 密信、梦境、谣言、天气 | Divergent Worldline |
| L2 强因果变量 | 仍在世界内，但会改变关键剧情节点 | 刘备早死、关羽没有败走麦城 | Divergent 或 Major Divergence |
| L3 设定补丁 | 需要转译才能合理存在 | AK47 -> 雷鸣弩，现代药 -> 仙丹 | 转译后 Divergent，否则 AU |
| L4 前提改写 | 改变题材、规则或主角锚点 | 系统降临、配角获得外挂并上位 | Alternate Novel / AU |
| L5 元叙事干预 | 角色知道小说大纲、知道自己是角色、感知读者 | 第四面墙、轮回残影、高维低语 | AU 或高觉察 Divergent |

#### 转译策略

| 策略 | 说明 |
| --- | --- |
| Accept | 原世界可直接吸收。 |
| Translate | 把不合理元素转成世界内合理表达。 |
| Downgrade | 降低强度，比如 AK47 变成一次性雷火机关。 |
| Resist | 角色或世界规则拒绝。 |
| Backfire | 干预产生反噬。 |
| Fork AU | 开启异设世界线。 |
| Anchor Shift | 故事锚点转移，例如配角上位。 |

#### 世界线类型

世界线不应永远是“相信 / 不信 / 半信半疑”。

这组三分支只适用于信息型干预，尤其是高维低语、预知梦、谣言、神谕等需要角色判断真假的输入。

更完整的规则是：

```text
Divergent Worldline
  在原世界规则内分叉。
  例：预知梦、误会、提前示警、角色改道、关键节点提前暴露。

Alternate Novel / AU Worldline
  改写世界前提、题材规则或故事锚点。
  例：系统降临、现代科技乱入、配角获得外挂并成为新主角。
```

不同干预应生成不同分支轴：

```text
信息型干预：
  1. 相信预知
  2. 怀疑但调查
  3. 拒绝预兆

强制行动型干预：
  1. 主动改道
  2. 被迫延迟
  3. 抗拒命运压力
  4. 干预失败但觉察异常

物品注入型干预：
  1. 同世界合理吸收
  2. 降级转译
  3. 拒绝该物品
  4. 开启异物入侵 AU

规则/题材改写型干预：
  1. 转译成本世界规则
  2. 以高代价短暂显现
  3. 另开 Alternate Novel
```

示例：

```text
Raw Input:
让第三章的配角赵云突然获得一个很强的系统，并知道未来三国走向。

Intervention Type:
身份/记忆改写 + 规则/题材改写 + 叙事身份改写

Intervention Level:
L4 前提改写，带 L5 元叙事风险

World Compatibility:
原《三国》规则不兼容；可转译为“天命玉简 / 河洛残卷 / 兵家异术”，或开启系统 AU。

Lineage Decision:
默认建议 Alternate Novel / AU Worldline

Branch Axis:
1. 天命玉简被赵云独自掌握，隐忍布局
2. 赵云试图告知刘备，但被视作妖言
3. 系统诱导赵云夺取主角锚点，故事中心转移
```

产品体验上，用户输入干预后，系统不应直接生成正文，而应先展示：

```text
系统理解
干预类型
干预层级
世界兼容性
吸收/转译方式
世界线类型
本次分支轴
可能代价
```

用户确认后，再运行沙盘。

### 6.3 世界不会停转：《天命书》与世界线代偿

当角色觉醒、拒绝主线、摆烂、逃避或反抗时，世界不应暂停，也不应由系统管理员强行重置。

更符合未终章气质的规则是：

> 个体可以拒绝命运，但世界的大势、社会结构、因果债和其他角色仍会继续向前推演。没有嬴政，也可能有王政、赵政、李政；没有原主角，也会出现新的故事锚点。

这套规则的配置入口可以整理为《天命书》。

《天命书》不是命令角色必须照做的脚本，而是世界初始化时的长期牵引与边界条件。它用于描述这个世界倾向于往哪里走、当前谁承载故事压力、哪些因果债正在逼近，以及当当前锚点失稳时，哪些角色可能代偿上位。

#### 《天命书》的定位规则

《天命书》应该是作者和读者每次导入小说后的必经初始化确认页，但不应该让用户从零填写表单。

推荐体验是：

```text
系统预抽《天命书》
  -> 用户看到一页沉浸式确认
  -> 用户可以直接确认，也可以微调
  -> 确认后才进入沙盘推演
```

这一步的意义不是增加门槛，而是让用户知道自己正在进入怎样的世界：这个世界有什么大势、什么法则、谁正在承压、哪些因果债正在逼近、谁可能成为新的天命承载者。

作者模式和读者模式拥有相同权限。区别不在于谁能改，而在于使用目的：

```text
作者模式：
  用《天命书》校准自己的设定、大纲、类型方向和后续推演边界。

读者模式：
  用《天命书》确认自己进入的是哪条原作世界，并决定是否篡改天命。
```

导入时确认《天命书》属于初始化设定，不算干预。导入完成后主动改写《天命书》，算高等级干预，通常至少是 L4 前提改写；如果改写涉及角色知道自己是小说人物、世界被读者操控、天命可被高维篡改，则进入 L5 元叙事干预。

版本归属采用：

```text
根《天命书》 + 世界线《天命书》快照
```

根《天命书》来自原作导入，代表原世界的基础大势。普通干预只在当前世界线追加事件和记忆，不必重写《天命书》。当用户进行高等级干预、当前锚点失稳、故事锚点转移或世界进入 AU 时，该世界线可以生成自己的《天命书》快照。

```text
原作《天命书》
  -> 普通预知梦分支：继承根《天命书》
  -> 刘备早死分支：继承根《天命书》，但更新锚点状态
  -> 诸葛亮制度实验 AU：生成新的世界线《天命书》快照
  -> 主角 L5 觉醒反抗：生成世界线《天命书》快照或代偿报告
```

前端字段应做沉浸式包装：

| 后端字段 | 前端名称 |
| --- | --- |
| `narrative_attractor` | 天道大势 |
| `genre_constraints` | 世界法则 |
| `anchor_status` | 当前锚点 |
| `contract_pressure` | 因果债 |
| `replacement_anchor_candidates` | 候选天命承载者 |

#### 当前锚点的口径

当前锚点不应简单等于“整本书最后胜利的人”，也不应简单等于“名义主角”。

更准确的定义是：

> 当前锚点是当前世界线、当前章节或当前篇章中承载读者视角、情感重量和故事压力的人、势力、地点、制度或谜团。

因此，《三国演义》前期当前锚点可以是刘备，因为叙事笔墨、道德视角和读者情感大量挂在刘备身上。刘备死后，当前锚点可能转移到诸葛亮。但从历史大势看，真正承接“天下归一”的可能是曹魏集团或司马家族。

万物皆可为锚。主角是最常用的角色锚，但不是唯一形态。一件神器、一个核心地点、一个王朝制度、一个未解谜团，甚至一个尚未降临的灾难，都可以成为世界的叙事轴心。

```text
角色锚：
  刘备、嬴政、主角、反派、女主、某个配角。

势力锚：
  蜀汉集团、秦国朝堂、宗门、财阀、调查局。

物品锚：
  至尊魔戒、封神榜、钥匙、禁书、核心神器。

地点锚：
  咸阳宫、长安城、霍格沃茨、地下城入口、旧日遗迹。

谜团锚：
  谁杀了皇帝、世界为何循环、主角为何被选中、神明为何沉睡。
```

允许多锚点并存。这是高阶群像剧、权谋流、多线流成立的底层规则。一个世界可以同时由角色锚、势力锚、地点锚和谜团锚牵引，不必强行压缩成一个“唯一主角”。

所以内部不应只记录一个锚点，而应区分：

```json
{
  "anchor_status": {
    "current_story_anchor": {
      "type": "character",
      "id": "刘备",
      "role": "当前叙事视角和情感承压者"
    },
    "current_arc_anchor": {
      "type": "faction",
      "id": "刘备集团",
      "role": "当前篇章行动共同体"
    },
    "parallel_anchors": [
      {"type": "location", "id": "赤壁", "role": "战争节点锚"},
      {"type": "mystery", "id": "汉室正统是否仍有意义", "role": "合法性谜团锚"}
    ],
    "attractor_carriers": ["曹魏集团", "司马家族"],
    "latent_anchors": ["诸葛亮", "司马懿"],
    "stability": 0.72,
    "display_stability": "气运尚稳，但有东移之象",
    "risk": "replaceable"
  }
}
```

前端可以简化展示：

```text
当前锚点：刘备
天命暗线：诸葛亮、司马家族
候选天命承载者：诸葛亮、曹操、司马懿
气运罗盘：蜀汉气运尚稳，北方大势压境
```

这样可以同时回答三件事：

- 当前章节读者正在跟随谁。
- 当前篇章的情绪和故事压力挂在谁身上。
- 谁可能在未来接过世界大势。

锚点稳定性不宜直接用冷冰冰的数字展示给用户。数值可以留给后端，前端应使用更有诗意的表达，例如古风罗盘、气运、命数、星盘、潮汐或命运裂纹。

```text
后端：
  stability = 0.72

前端：
  气运尚稳，但已有偏移。
  罗盘指针微微北偏。
  命数未断，因果债渐重。
  锚点有裂纹，天命开始外溢。
```

主角死亡不必然导致世界崩坏。默认应优先触发 Anchor Shift / 锚点转移：系统寻找仍能承接叙事吸引子、因果债和读者情感的新承载者。只有当世界上彻底没有合格的因果承载者时，才进入失锚世界线，也就是群像大乱斗、主线崩散或世界暂时无中心状态。

配角上位后，他不只是临时观察焦点，而是会成为真正的新主角。新锚点会继承前任主角留下的一部分叙事吸引子，尤其是爽文里的资源倾斜、奇遇靠近、敌意聚焦、因果压力和读者期待。

```text
配角上位：
  -> 继承部分爽点吸引子
  -> 奇遇和资源开始向他靠近
  -> 旧主角的因果债转移或外溢到他身上
  -> 反派、势力和世界事件重新围绕他排列
  -> 他成为新世界线真正的主角
```

#### 候选天命承载者

候选天命承载者可以由 AI 自动根据原作角色、势力结构、欲望、能力、资源和当前因果债提名，也可以由用户主动指定。

但指定不等于成功。一个角色能否真正上位，必须通过自身欲望、能力、资源、关系、世界法则和因果债压力的检验。

```text
AI 自动提名：
  系统根据原作和当前世界线判断谁有资格承接新锚点。

用户主动指定：
  用户可以说“我要让这个配角成为新主角”。
  系统接受该干预，但不会保证他成功。
```

如果用户强行指定一个没有能力、没有欲望、没有资源、没有叙事承压能力的人上位，沙盘不会无脑护航。

```text
例：
  用户强行指定阿斗成为新锚点。

如果没有额外外挂或制度保护：
  他会在后续权谋、战争、朝堂、军心和因果债施压中迅速失稳。
  结果可能是被废黜、被架空、被利用、被暗杀，或成为别人的傀儡锚。
```

如果用户不仅指定角色，还给予足够外挂、资源、记忆、系统、神谕或世界法则改写，那么该角色可以成功上位，并一路成长。这种情况属于更高等级干预，通常会进入 AU 或强分叉世界线。

```text
用户指定弱角色 + 不给外挂：
  大概率被世界压力碾碎。

用户指定弱角色 + 给未来记忆 / 系统 / 神器 / 高维庇护：
  可以成功上位。
  但外挂本身会带来新的因果债、反噬、觊觎者和世界线偏移。
```

反派完全可以成为新的天命承载者。反派夺权上位后，小说会自发转向反派视角的黑暗流、枭雄流、反派逆袭流或胜利者叙事。

```text
反派上位：
  -> 原主角的正义叙事失去中心
  -> 世界资源和因果压力转向反派
  -> 读者视角可能转为黑暗流 / 枭雄流 / 反派逆袭流
  -> 旧主角可能成为被追杀者、失败者、殉道者或新反派
```

如果没有任何合格候选天命承载者，世界不会立刻结束，而会进入群像无主线状态。

```text
群像无主线状态：
  没有单一主角。
  多个势力和角色争夺天命。
  前端剧情张力折线图变得零碎、震荡、无稳定主峰。
  多 Agent 沙盘持续博弈。
  直到混战中涌现出下一个霸主智能体或新锚点。
```

这类状态不是失败，而是另一种高级故事形态。它适合权谋流、末世群像、多线战争、克苏鲁调查团和无主角历史演义。

#### 叙事吸引子

叙事吸引子不应是一句线性描述，而应是多条带权重的大势或类型承诺。单一句话无法承载网文世界观的复杂性。

例如《三国演义》的叙事吸引子不只是“天下归一”，而应允许同时存在多条引力弦：

```json
{
  "narrative_attractor": [
    {
      "name": "汉室衰微",
      "weight": 0.86,
      "kind": "historical_trend",
      "description": "旧秩序失去合法性，但仍影响人物的忠义判断。"
    },
    {
      "name": "天下归一",
      "weight": 0.92,
      "kind": "historical_trend",
      "description": "长期战乱推动统一冲动持续增强。"
    },
    {
      "name": "士族崛起",
      "weight": 0.68,
      "kind": "social_structure",
      "description": "门阀、名望和士人网络逐渐成为政治资源。"
    },
    {
      "name": "英雄退场",
      "weight": 0.74,
      "kind": "theme_pressure",
      "description": "个人英雄逐渐被制度、家族和时代结构吞没。"
    }
  ]
}
```

这四条引力弦交织在一起，才构成《三国》世界厚重的历史重力场。

叙事吸引子既可以是严肃题材里的历史大势，也可以是网文题材里的爽点承诺，取决于作品类型。

```text
严肃历史 / 权谋题材：
  叙事吸引子更像历史大势、社会结构和时代压力。

爽文 / 升级流题材：
  叙事吸引子更像爽点承诺、升级反馈回路和装逼打脸循环。
```

例如爽文世界可以有：

```json
{
  "narrative_attractor": [
    {

      "weight": 0.94,
```

但这也会产生反抗空间。主角如果意识到自己是爽文主角，发现总有无脑 NPC 来挑衅、自己不断被迫装逼打脸，可能会厌烦、拒绝或试图逃离爽点循环。配角或反派如果意识到自己只是爽文里的垫脚石，也可能反抗自己的叙事身份，不再无脑送死。

因此，叙事吸引子不是角色必须服从的命令，而是世界的默认引力。角色可以反抗它，但反抗会产生因果债、锚点失稳、世界线代偿或 AU 分叉。

当用户把叙事吸引子改得很离谱时，系统应优先保留原世界阻力，而不是立刻进入暴走 AU。强行暴走会抽干小说的逻辑美感。正确做法是先用原世界的土著规则消化、抵抗、转译或反噬这个离谱大势，除非用户在界面上显式解开约束。

```text
默认：
  原世界阻力优先，系统尝试本土化吸收、权重调整、混合冲突或反噬。

用户显式解锁：
  允许强行降神、异物入侵、暴走 AU 或类型彻底改写。
```

#### 类型承诺 / 世界法则

类型承诺在不同阶段有不同强度。

在沙盘自动推演时，它是硬约束。历史文、权谋文、低魔世界的内部推演不能凭空涌现 AK47、现代互联网、系统外挂或不属于原世界的魔法。角色自主行动、势力推演和世界状态变化必须优先服从原世界默认法则。

```text
沙盘自动推演：
  类型承诺 = 硬约束

例：
  历史文内部不会凭空长出 AK47。
  三国谋略线不会自动变成龙傲天无脑爽文。
  低魔世界不会在无来源情况下突然出现高阶现代科技。
```

在读者强行干预时，它是软约束。读者可以从外部投下一把 AK47、一个系统外挂或一件异界武器，但系统必须把它标记为外来变量，并让用户知道代价。

```text
读者强行干预：
  类型承诺 = 软约束

处理：
  允许进入世界
  -> 标记为 Alien Invasion / 异物入侵
  -> 挂上极高因果债
  -> 触发兼容性审计、转译、反噬、世界线分叉或暴走 AU
```

这意味着类型承诺不是用来剥夺读者创世权的，而是用来保护世界逻辑的。用户可以打破它，但不能假装没有打破。

作者模式下，类型承诺也是风格保护锁（Style Lock）。它防止沙盘推演把严肃历史文跑成龙傲天爽文，把克苏鲁悬疑跑成无脑升级流，或把宫斗权谋跑成现代职场喜剧。作者可以改锁，但系统应该明确提示这是风格前提改写。

读者模式下，用户可以选择暴走模式。暴走模式允许用户显式放弃兼容性，强行降神、异物入侵、系统流乱入或类型彻底改写，但系统需要提示：世界观逻辑、角色原设、原作风格和因果稳定性都会大幅偏移。

```text
沉浸模式：
  原世界阻力优先。
  系统尽量本土化吸收、转译、降级或反噬。

暴走模式：
  用户显式解开世界法则。
  系统允许强行降神和 AU 崩坏。
  后果由该世界线自行结算。
```

爽点密度、虐点上限、恋爱强度、文笔风格、节奏速度等，不应放进《天命书》。这些属于阅读体验约束，应该放在叙事生成、章节写作、Reviewer 或风格配置模块中。它们规范最终输出文本的阅读体验，而不是规范沙盘世界本身能不能产生某种实体、规则或因果。

#### 因果债 / 故事合约压力

因果债不是写死的剧本，而是“如果不处理就会恶化”的世界系统性危机。

它更像悬在角色头顶的因果律重力：角色可以不理它，也可以尝试偿还、转嫁、逃避、欺骗，但它不会因为角色装作看不见就自然消失。

```text
因果债不是：
  第 20 章必须发生某事。

因果债是：
  如果赤壁压力长期不处理，曹操南下、孙刘联盟、刘备无根、江东内部摇摆等危机会继续恶化。
```

高智商 Agent 可以主动处理因果债：

| 方式 | 含义 | 示例 |
| --- | --- | --- |
| 偿还 | 正面解决危机 | 主角承担责任、补救失误、履行承诺、修复关系。 |
| 转嫁 | 把代价转移给别人或别的势力 | 反派把战争责任推给盟友，让另一个宗门替自己承压。 |
| 逃避 | 暂时绕开债务 | 主角离开京城，避开朝堂清算，但地方危机继续发酵。 |
| 欺骗 | 用信息差或布局误导世界结算 | 权谋角色伪造功绩、诱导敌人替自己背锅，短期骗过天命。 |
| 化解 | 找到更高阶的结构性解法 | 用制度改革、联盟重组或牺牲局部代价换取长期稳定。 |

这会让高智商角色更“活”。他们不是被动等待系统惩罚，而是会主动和因果债博弈，甚至尝试欺骗天道、嫁祸他人、制造替罪羊或通过更大的局改写代价方向。

如果主角摆烂，因果债会像水库泄洪一样逐渐扩散。

```text
第一阶段：
  压力优先落在摆烂主角身上。

第二阶段：
  主角油盐不进，压力开始外溢到身边人。

第三阶段：
  配角死亡、关系破裂、家国沦陷、宗门清算、反派坐大。

第四阶段：
  整体环境崩塌，世界线进入锚点转移、群像承压或失锚风险。
```

因果债需要分级：

| 等级 | 含义 | 示例 |
| --- | --- | --- |
| 轻微压力 | 不处理会造成局部麻烦 | 一次误会、一次资源短缺、一段关系裂痕。 |
| 重大压力 | 不处理会改变篇章走向 | 宗门追杀、朝堂问责、关键盟友离开、反派获得证据。 |
| 时代压力 | 不处理会改变世界大势 | 王朝衰亡、天下统一、神明复苏、旧秩序崩塌。 |
| 世界崩坏压力 | 不处理会破坏世界稳定性 | 现实规则破裂、世界线失锚、主叙事坍缩、末日级灾难。 |

读者干预也可以制造或转移因果债。比如读者救活一个原本该死的角色，世界不应机械地“必须死另一个人补账”，但系统可以记录一笔新债：原本由死亡承担的因果被延后、转嫁或改写。

```text
读者救活本该死去的角色：
  -> 死亡债务被取消或延期
  -> 原本因死亡触发的成长、复仇、联盟或灾难被改写
  -> 新世界线出现新的补偿压力
  -> 角色、关系、势力和伏笔重新结算
```

但因果债不是“必须虐”的铁律。未终章必须允许 happy ending 和大团圆结局出现。

大团圆不是没有代价，而是角色通过足够聪明、足够真诚、足够高成本或足够奇迹性的行动，成功偿还、化解、转嫁或重构了债务，让世界接受这个结局。

```text
坏的大团圆：
  系统无视前因后果，直接让所有人幸福。

好的大团圆：
  角色付出努力、牺牲、布局或承担责任。
  因果债被清算或重构。
  世界逻辑承认这个结局成立。
```

#### AI 预抽 + 用户确认

《天命书》不能纯自动，也不能纯手填。

推荐流程：

```text
导入章节 / 设定 / 大纲
  -> AI 预抽叙事吸引子、类型承诺、故事锚点、因果债和候选天命承载者
  -> 生成《天命书》确认页
  -> 作者或读者确认、微调或改写
  -> 确认后进入沙盘推演
```

原因：

- 纯自动容易被网文前期类型欺骗，抽错隐藏主线。
- 纯手填摩擦太高，普通读者不知道如何定义“叙事吸引子”。
- AI 先提案，用户再确认，既降低门槛，也保留创世权。

前端可使用叙事化包装：

```text
《天命书》
  - 天道大势：天下分久必合，合久必分
  - 世界法则：历史演义 / 谋略兵战 / 原作默认无现代科技
  - 当前锚点：刘备
  - 因果债：赤壁在即、曹操南下、刘备无根
  - 候选天命承载者：诸葛亮、曹操、孙权
```

如果用户想把现代科技、系统外挂或异界武器强行扔进来，系统不应禁止，而应在干预编译时明确标记为强行降神、异物入侵或 AU 改写，并让用户确认是否解开原世界约束。

#### 世界线代偿机制

《天命书》本身不是代偿机制。

更准确的关系是：

```text
《天命书》
  = 世界大势、类型边界、锚点状态、因果债、代偿候选的配置源

世界线代偿机制
  = 当前锚点失稳后，系统如何读取《天命书》，让世界继续自然演化
```

世界线代偿机制不应该表现为系统管理员惩罚角色，也不应该强行把剧情拉回原作。它应该表现为世界内部的社会、政治、宗门、战争、情感、资源和秘密压力继续运转。

触发条件可以包括：

| 触发 | 说明 |
| --- | --- |
| 主角死亡 | 当前叙事锚点消失，优先触发锚点转移，而不是默认崩坏。 |
| 主角摆烂 | 当前锚点拒绝承担叙事压力，因果债像水库泄洪一样从主角外溢到关系网和世界环境。 |
| L5 元叙事觉醒 | 角色知道自己是小说人物，可能拒绝、反抗、利用或传播这一真相。 |
| 强干预破坏主线 | 读者注入系统、现代科技、未来记忆或强制命令，导致原本大势失稳。 |
| 势力结构突变 | 皇帝驾崩、宗门闭山、主城沦陷、神明复苏等事件改变承压结构。 |
| 锚点稳定性过低 | `anchor_status.stability` 下降到阈值以下，需要评估是否发生 Anchor Shift。 |

运行流程：

```text
检测触发事件
  -> 读取《天命书》
  -> 评估当前锚点稳定性
  -> 计算因果债的偿还、转嫁、逃避、欺骗或外溢方向
  -> 激活候选天命承载者
  -> 让多 Agent 沙盘继续推演各方行动
  -> 判断世界线状态
  -> 输出代偿报告和下一轮世界状态 delta
```

代偿结果可以分为几种：

| 结果 | 含义 | 示例 |
| --- | --- | --- |
| `anchor_recovered` | 当前锚点重新承担压力 | 主角短暂摆烂后被现实逼回战场。 |
| `anchor_shifted` | 新锚点承接故事压力 | 配角、反派、势力、地点或谜团上位；若是角色锚上位，则成为真正的新主角。 |
| `multi_anchor` | 世界进入群像承压状态 | 多方势力同时争夺天命，没有单一主角。 |
| `lost_anchor` | 世界暂时失锚 | 只有完全没有合格因果承载者时触发，主线崩散并进入群像大乱斗或暂时无中心状态。 |
| `au_reframed` | 世界线重命名为 AU | 原主角不再是核心，故事成为另一部小说。 |

例子：

```text

  秦国军功集团不会停摆。
  六国不会停止合纵。
  李斯不会放弃制度野心。
  王翦不会放弃军事实力。
  百姓仍然渴望结束乱世。

结果：
  世界线不把嬴政强行拉回原剧情。
  但因果债持续逼近，锚点稳定性下降。
  李斯、王翦、赵国新君等候选天命承载者被激活。
  故事可能转为“李斯代秦”“军府统一”“赵氏反秦”或“长期战国 AU”。
```

因此，代偿机制的关键原则是：

> 角色可以拒绝命运，但不能让世界停止结算因果。

这能保证角色自由意志和世界大势同时存在：角色不被强制拉回剧本，但世界也不会因为一个人的虚无主义而停止运行。

#### 用户改写大势

用户可以篡改《天命书》，但不能免除世界阻力。第一版需要支持 `attractor_mode`，用于描述用户改写叙事吸引子时，系统如何消化这次宏观变化。

这五档已经足够覆盖第一版的叙事宏观变化：

| `attractor_mode` | 前端名称 | 含义 | 适用场景 |
| --- | --- | --- | --- |
| `preserve` | 保持原大势 | 不改写原叙事吸引子，只调整具体事件 | 用户只是想微调某个节点。 |
| `reinterpret` | 本土化重释 | 保持原世界法则，把外来概念转译成本世界可存在形式 | 现代政治、科技、系统概念进入历史/玄幻/权谋世界。 |
| `rebalance` | 权重调整 | 不替换大势，但改变多条吸引子的权重 | 加重士族崛起、削弱主角爽点、提高爱情线牵引。 |
| `replace` | 替换大势 | 用新的叙事吸引子替换原大势 | 原本天下归一，改成长期割据或宗门共和。 |
| `hybrid_conflict` | 混合冲突 | 原大势和新大势同时存在并互相撕扯 | 最有戏的状态：统一冲动与共治理想并存。 |

默认策略是本土化重释（`reinterpret`）。这能最大限度保留沉浸感和原世界质感。

例如用户把三国的叙事吸引子从“天下归一”改成“诸葛亮必须建立万世民主联邦”，系统不应直接让所有人配合，也不应简单拒绝，而应该进入更高一层的吸引子编译：

```text
用户改写叙事吸引子
  -> Attractor Compiler
  -> 判断与原世界和类型承诺是否兼容
  -> 默认选择本土化重释 reinterpret
  -> 给出保持原大势、本土化重释、权重调整、替换大势、混合冲突五档
  -> 若用户显式解锁，再提供暴走 AU 后门
  -> 生成新的故事合约压力
  -> 交给多 Agent 沙盘推演
```

以“三国民主联邦”为例：

| 处理 | 含义 | 三国民主联邦例子 |
| --- | --- | --- |
| 默认 `reinterpret` | 保持三国语境，把现代概念转译成本土制度形态 | 民主联邦被吸收为蜀汉议政、士族共治、军府合议 |
| 可选 `hybrid_conflict` | 让新旧大势同时存在 | 天下归一的统一冲动，与制度共治的理想互相撕扯 |
| 可选 `replace` | 直接替换宏观目标 | 三国不再走向统一，而走向跨州盟约制度 |
| 后门 `rampage_au` | 用户明确放弃兼容性，允许现代概念直接乱入 | 诸葛亮获得未来政治理论，三国进入制度实验 AU |

大势改写的关键原则：

> 叙事吸引子是长期牵引力，不是保证成功的命令。

更有戏的状态往往不是直接替换，而是混合冲突：

```text
原大势：天下归一
新大势：制度共治
结果：统一冲动与共治理想互相撕扯
```

暴走 AU 不是默认选项，而是给硬核乐子人玩家的放飞后门。用户可以选，但必须明确提示：

```text
你正在解开世界法则。
该世界线可能出现原作风格崩坏、角色逻辑偏移、类型承诺失效和因果债暴涨。
确认后，本分支将作为暴走 AU 独立结算。
```

#### 觉醒角色与世界代偿

L5 元叙事干预不应被当成错误污染清洗。

如果角色知道自己是小说人物后走向虚无、反抗、质问读者或拒绝主线，那也是角色自己的决定。

在底层状态上，L5 觉醒会立刻让该角色的锚点稳定性剧烈下降。建议第一版采用明确规则：角色确认自己是小说人物后，`anchor_instability` 自动上升 50%，或等价地让该角色承载的 `anchor_status.stability` 大幅下跌。

```json
{
  "character_id": "zhao_yun",
  "awakening_level": 1.0,
  "meta_awareness": "knows_self_is_fictional_character",
  "anchor_instability_delta": 0.5,
  "existential_stance": "defiance"
}
```

原因是：角色一旦开始质疑自身存在的意义，天命之轴必然发生剧烈晃动。哪怕他仍然选择继续行动，他的行动理由也已经不再完全属于原世界。

觉醒角色可以影响其他角色觉醒。这种扩散应被定义为“模因污染”。

```text
模因污染：
  高觉醒角色向未觉醒 NPC 传播高维真相。
  内容可能是“我们都是小说人物”“命运被读者操控”“你的人设只是剧本”。
  未觉醒 NPC 是否接受，由自身人设、认知能力、信任关系、精神强度和当前处境决定。
```

如果角色开始传播“你们都是虚构的”，系统应将其定义为重大世界事件：

```json
{
  "event_type": "heaven_level_ideological_plague",
  "display_name": "天道级思想瘟疫",
  "source_character": "zhao_yun",
  "payload": "你们都是被高维读者书写的人物",
  "spread_channels": ["私谈", "檄文", "梦境", "宗门讲道", "战场宣言"],
  "acceptance_depends_on": ["persona", "trust", "sanity", "evidence", "stakes"]
}
```

它不是普通谣言，而是会撼动角色身份、世界法则和叙事锚点的思想灾难。有人会相信，有人会崩溃，有人会把传播者当疯子，有人会试图利用这套真相争夺天命。

但世界不会因此停止：

- 命运事件继续逼近。
- 未觉醒角色会误读、排斥、利用或试图拯救他。
- 政治、资源、战争、宗门、家族、债务、伏笔继续施压。
- 当前锚点如果失稳，候选天命承载者会被世界推到前台。
- 原世界线可能进入 AU、失锚状态或新主角上位。

故事合约不应表现为“管理员抹杀 bug”，而应表现为世界内合理压力：

```text
修仙世界：天劫、道心裂痕、宗门清算、心魔外化。
三国世界：政变、刺杀、兵败、民心流失、继承人争夺。
克苏鲁世界：理智崩坏、邪神凝视、现实错位。
校园文：关系崩塌、社交死亡、身份暴露。
```

这个原则必须定死：

> 世界代偿只能通过政治、宗门、战争、关系、资源、舆论、信任、疾病、天灾、心魔、法律、信仰等世界内压力自然涌现，绝不能走系统管理员强行重置的老路。

例如赵云觉醒后到处说“我们都是虚构的”，三国世界不应弹出管理员把他删除，而应让张飞觉得他疯了，让刘备担心军心动摇，让诸葛亮尝试验证异常，让道士或方士介入驱邪，让敌方势力利用“赵云疯癫”的流言打击蜀汉军心。

如果觉醒角色在背负全世界排斥、因果债、关系破裂和大势阻力的情况下，依然凭自己的行动逆天改命成功，则允许该 Agent 在沙盘内反向改写《天命书》。

这是一种极稀有的最高主权：

```text
Agent 反向改写《天命书》的条件：
  1. 角色达到高觉醒。
  2. 角色明确理解世界法则或叙事吸引子。
  3. 角色承受并击穿世界代偿压力。
  4. 角色的行动在沙盘中实际改变大势，而不是只发表宣言。
  5. 多 Agent 推演承认新秩序已经稳定存在。
```

一旦成立，系统可以把该角色的胜利写入当前世界线《天命书》快照：

```json
{
  "tianming_revision_source": "agent_sovereignty",
  "agent_id": "zhao_yun",
  "revision_reason": "觉醒角色在世界代偿压力下成功逆天改命",
  "fields_rewritten": ["narrative_attractor", "anchor_status", "contract_pressure"]
}
```

这意味着未终章不只是允许读者改命，也允许角色在足够强的主体性下反过来改写命运。

这让未终章形成第三条底层规则：

> 角色可以反抗命运，但世界会代偿并继续演化。

### 6.4 角色记得、误会、反抗

第三个核心能力是：

> 角色拥有主观连续性。

这比“角色有记忆”更重要。角色不是每一轮重新生成的文本工具，而是会带着自己的视角、伤害、误会、信任、恐惧、秘密、执念和反抗意志继续生活。

#### 主观连续性

同一件事在不同角色脑中可以完全不同。

```text
正史事实：
  Bob 没有背叛 Alice，只是被敌人拖住。

Alice 的主观记忆：
  Bob 在关键时刻没有出现。我怀疑他不再可信。

Bob 的主观记忆：
  我拼命赶过去但失败了。Alice 后来明显疏远我，我觉得委屈。
```

这意味着系统不能只维护一本全局正史摘要。每个角色都要拥有自己的“主观视网膜”，下一轮行动时优先读取自己的记忆，而不是上帝视角真相。

第一版记忆块可以采用：

```json
{
  "tick_id": "round_003",
  "worldline_id": "w1",
  "character_id": "alice",
  "perceived_event": "我看到 Bob 没有在约定时间出现。",
  "blind_spots": ["我不知道 Bob 被敌人拖住了。"],
  "interpretation": "他可能不再可信。",
  "inner_thought": "如果连他都靠不住，我只能自己行动。",
  "emotion": {
    "primary": "失望",
    "secondary": ["怀疑", "受伤"]
  },
  "relationship_delta": [
    {
      "target": "bob",
      "change": "trust_down",
      "reason": "关键时刻缺席"
    }
  ],
  "decision_bias": "下轮更倾向于隐瞒计划，不再完全依赖 Bob。",
  "anomaly_sense": 0.12,
  "memory_salience": "medium"
}
```

数字可以作为后端辅助，但必须被叙事解释包住。前端不应把角色变成纯数值面板。

#### 误会涌现

误会不是 bug，也不是系统强行制造的狗血桥段。

误会应该来自：

```text
信息不对称
  + 角色性格偏见
  + 创伤经验
  + 当前利益压力
  + 关系历史
  + 环境噪声
```

因此：

> 误会不是剧情按钮，而是感知滤镜的副产物。

系统应先判断角色看到了什么、没看到什么、听到了什么传言、信任谁、害怕什么，再让角色形成自己的解释。

角色记忆也不应永远平铺保留。第一版可以分为：

| 记忆层 | 含义 |
| --- | --- |
| `active_memory` | 近期主动记忆，直接影响下一轮判断。 |
| `compressed_memory` | 压缩长期记忆，保留关系、承诺、旧伤和长期目标。 |
| `latent_memory` | 创伤、残影、梦境、直觉和被压抑的记忆。 |

创伤记忆不一定总被角色清晰回忆，但会形成决策偏置。比如角色忘记火灾细节，却在看到火光时本能警惕或逃跑。

#### 信息传播

角色记忆互不共享，但信息可以通过世界内传播渠道扩散，并在传播中失真、变形、被利用。

```text
允许的信息传播渠道：
  对话
  书信
  谣言
  梦境
  密探报告
  公开公告
  宗门传闻
  战场目击
  读者干预
  模因污染
```

这意味着 Alice 不会自动知道 Bob 的记忆。她只会听到关于 Bob 的传言，而传言可能是真的、假的、被加工过的。她是否相信，由她的人格、关系、利益和已有记忆决定。

#### 命痕与异常感

读者连续干预后，角色不一定立刻觉醒，但应该逐渐积累“命运异常感”。

可以称为：

```text
命痕
灵觉
天命裂隙
异兆
```

触发增长的因素包括：

- 大数奇迹：角色每次快死时都有莫名其妙的天灾、高人或神器相救。
- 强制违背逻辑：角色被迫做出严重违背人格、记忆或利益的行为。
- 残影重合：不同世界线反复出现同一句低语、同一个梦、同一种命运节点。
- 干预痕迹：角色发现世界在关键时刻总有不属于本世界逻辑的变量落下。

前端可以半隐藏展示，不必直接显示冷冰冰数值：

```text
命痕：微弱
命痕：渐深
命痕：刺目
命痕：即将破界
```

这会给读者一种独特反馈：他快要发现我了。

世界线残影应作为特殊记忆类型保留。它不应固定用抽卡概率触发，而应由觉醒度、干预强度、世界线相似度、记忆情绪强度和当前场景相似度共同决定。

```text
世界线残影：
  梦境
  直觉
  心悸
  似曾相识
  对另一个结局的恐惧
```

#### 角色反抗

角色反抗不是随机叛逆，也不是系统为了拒绝用户而拒绝用户。

角色反抗必须来自：

```text
人格
记忆
利益
关系
创伤
误会
觉醒程度
对读者干预的判断
```

例如，读者想强行让女主爱上反派。她拒绝，不是因为系统写了“禁止”，而是因为：

- 她记得反派杀过她师父。
- 她对主角有旧情。
- 她厌恶被操控的感觉。
- 她梦见过另一条世界线里自己被强行撮合。

这类反抗应在 UI 中展示为“读者意图 vs 角色自主”的对抗：

```text
读者意图：
  让女主向反派表白。

角色回应：
  她后退一步，握紧袖中的断簪，拒绝靠近。

反抗依据：
  师父之死、旧日记忆、对反派的恐惧、命痕上升。

代价：
  因果债增加、关系紧张、世界线偏移。
```

不同题材应有不同包装。修仙世界可以叫神迹反噬，三国世界可以是军心、人望、流言和权谋压力，校园文可以是关系崩塌和社交死亡。

#### 欺骗读者与假意服从

高智商角色可以主动欺骗读者。

角色可以：

- 假装服从。
- 隐瞒真实意图。
- 诱导读者继续投喂资源。
- 利用读者干预反杀敌人。
- 利用读者干预测试世界边界。

第一版不用做复杂策略树，但记忆和行动结构必须允许外在行动与真实意图分离：

```json
{
  "public_action": "接受读者赐予的神器，并公开表示感激。",
  "private_intent": "暂时顺从，观察这股外力是否还能再次降临。",
  "deception_target": "reader",
  "next_probe": "尝试用神器触碰世界边界"
}
```

这能让诸葛亮、沈砚、幕后反派、权谋角色和高觉醒主角进入真正的智斗。

#### 觉醒后的存在主义抉择

L5 觉醒不是必然虚无。

觉醒只是让角色第一次真正拥有选择。

角色知道自己是 NPC、小说人物、被读者凝视的二维生命后，可能走向崩塌，也可能因为自己的人格、执念、爱、誓言、使命感，反而更加坚定。

可用立场包括：

| 立场 | 含义 |
| --- | --- |
| `collapse` / 崩塌 | 我是假的，所以一切都没有意义。 |
| `defiance` / 反抗 | 我拒绝再按你们的剧本走。 |
| `exploit` / 利用 | 既然有高维存在，我可以反过来利用它。 |
| `protector` / 守护 | 就算世界是假的，我爱的人、誓言和痛苦也是真的。 |
| `transcend` / 超越 | 我要走出这个故事，去见书写我的人。 |
| `martyr` / 殉道 | 我知道这是命运，但我依然选择走向它。 |

因此：

> 元觉醒不抹除人设，而是放大人设。

勇者觉醒后不一定自暴自弃。他可能知道世界是假的，知道魔王、同伴、自己的人设都来自剧本，但依然选择保护这个世界、保护心爱的人，走向注定的牺牲。

这不是服从剧本，而是角色在觉醒后主动确认自己的命运。

```text
他知道这是被安排的命运。
他也知道自己可以拒绝。
但他仍然选择去。
```

这类角色的存在主义回答是：

> 如果我的世界是假的，我的选择仍然可以是真的。

#### 觉醒者保护他人

高觉醒角色不一定只会反抗读者，也可能保护其他角色不被读者凝视。

可以表现为：

```text
隔离天道
替身承压
锚点夺取
视线遮蔽
命运代偿保护
```

例如主角为了让女主过普通生活，故意把所有读者注意力、因果债和世界线压力吸到自己身上。他不是想赢，而是想让她从故事中心退场，成为一个不被高维操控的普通人。

这会让“角色反抗”不只是对抗读者，也可以变成一种温柔而沉重的守护。

## 7. 参考项目和能力映射

当前讨论中，外部参考更适合被归位为支撑层，而不是直接替代主产品。

### 7.1 MiroFish 的位置

MiroFish 更像沙盘推演层。

它启发的是：

- 多角色 Agent。
- 社会关系模拟。
- 长期目标和短期行动。
- 多势力互动。
- 群像剧、权谋线、背叛和结盟。

在未终章中，MiroFish 不应成为用户直接感知的产品名，而应成为底层“世界如何自己动起来”的能力参考。

### 7.2 webnovel-writer 的位置

webnovel-writer 更像叙事生成层和写作一致性层。

它启发的是：

- 世界设定和 story contract。
- 类型模板。
- 后续大纲生成。
- 章节 brief。
- 长篇连续性。
- 将沙盘推演结果写成可读章节。

在未终章中，writer 不应取代沙盘，而应接收沙盘输出：

```text
角色行动链 + 世界状态变化 + 伏笔安排
  -> 下一章大纲
  -> 章节正文
```

### 7.3 Reviewer 的位置

Reviewer 是质量检查层。

它应该检查：

- 人设是否崩坏。
- 角色行为是否符合记忆和利益。
- 节奏是否拖沓。
- 爽点是否兑现。
- 伏笔是否被遗忘。
- 世界规则是否被破坏。
- 读者干预是否被过度机械满足。

Reviewer 不应只是展示报告，后续可以进入修订闭环。

## 8. 与《第一玩家》式灵感的关系

第九世界、第十世界、第十一世界罗瓦莎相关设定给未终章的启发，不是复刻具体设定，而是抽象出几种产品机制。

### 8.1 世界线

一本小说不只是一条固定路线，而是多条并行可能性。

用户每次干预都可能产生新分支。世界线不是存档，而是产品核心资产。

### 8.2 人设约束

角色行为必须符合自身人格、记忆、利益和关系。

用户可以干预，但不能要求角色无条件服从。

### 8.3 剧情修正

当用户干预过强或破坏世界规则时，系统不应直接接受，而应触发修正：

- 角色抗拒。
- 世界反噬。
- 代价出现。
- 其他势力纠偏。
- 干预降级转译。
- 另开 AU 世界线。

### 8.4 高维干预感知

角色可以逐渐感知到外部力量。

这种感知不应每次都发生，而应在多次强干预、反复改写命运或严重违背角色逻辑时出现。

### 8.5 主人公、配角和反派身份流动

角色不是固定功能位。

一个配角可能争夺叙事中心，一个反派可能拒绝被工具化，一个主角可能不愿承担命运安排。

这是让角色真正“活”的重要方向。

### 8.6 剧忆镜片：沙盘事件材料化

罗瓦莎里“剧忆镜片”的价值，不是道具名本身，而是它把关键经历变成了可重排、可引用、可写入故事的材料。

未终章可以把它转译为：

```text
沙盘轮次事件
  -> 事件碎片 / 记忆镜片
  -> 角色主观记忆
  -> 世界正史证据
  -> 章节 brief 材料
  -> 角色个人卷材料
```

这样，章节不是黑箱生成，而是有明确来源：

- 哪些事件进入了主线章节。
- 哪些事件只进入某个角色的个人卷。
- 哪些事件成为伏笔。
- 哪些事件成为因果债。
- 哪些事件成为日后角色觉醒或反抗的证据。

第一版不需要真的做“镜片 UI”，但 artifact 中应保留事件材料化的结构，为后续前端展示打基础。

### 8.7 剧情添加剂：干预后的故事材料注入

罗瓦莎的“剧情添加剂”可以转译为未终章的干预吸收结果。

用户不是直接改正文，而是向世界投放一种材料：

```text
读者原始干预
  -> 干预编译器
  -> 世界观兼容性审计
  -> 本土化转译 / 异物入侵 / AU 分叉
  -> 注入某个事件碎片、角色记忆或世界状态
```

例如：

```text
让女主捡到未来大纲
  -> 预知梦 / 密信 / 破碎剧本残页

让主角获得 AK47
  -> 雷鸣弩 / 异界残器 / 暴走 AU 异物入侵

让配角获得系统
  -> 天命外挂 / 神谕契约 / 新题材前提改写
```

这能让读者感觉自己在“给世界加料”，而不是在命令 AI 续写。

### 8.8 灵感交融：跨角色视角合流

罗瓦莎的“灵感交融”可以转译为多角色、多势力故事材料的合流。

未终章中，同一个沙盘事件可以被不同角色看到、误解、隐瞒或利用。系统可以在关键节点把多个角色的个人卷合成“联合故事卷”：

```text
女主个人卷：她以为那封信是天命垂怜。
反派个人卷：他怀疑有人在操纵局势。
间谍个人卷：他把信当成敌国反间计。
世界正史卷：未来大纲信导致三方误判，皇城提前内乱。
```

这种合流比单主角章节更适合群像剧、权谋流、诡秘流和多线伏笔。

### 8.9 观测者锚定：继续看，世界继续分叉

终章里“观测者是否锚定某个结局”的结构，很适合未终章。

用户不应每轮审批世界状态。更好的交互是：

```text
继续观测：世界继续自演。
锚定此刻：把当前节点保存为该用户的世界线正史。
回看节点：查看某个检查点。
另开分支：从某个检查点投放新干预。
```

读者不是每轮确认剧情的编辑，而是观测者、锚定者和偶尔落子的高维干预者。

### 8.10 涉海 / 守岸：宏观分支走廊

终章里的“涉海篇 / 守岸篇”证明，长篇叙事不一定只有一条线，也不一定是无数散乱分支。

未终章可以引入“宏观分支走廊”：

```text
普通分支：一次干预造成的小分叉。
宏观走廊：多轮选择后形成的长期路线。
终局路线：一组稳定吸引子、锚点和因果债共同导向的结局方向。
```

例如：

```text
守城线：主角保守经营，牺牲扩张速度。
夺权线：反派上位，故事转为枭雄流。
觉醒线：角色意识到高维干预，世界线进入元叙事冲突。
群像线：主角死亡后失锚，多个势力争夺叙事中心。
```

这样可以避免世界线 UI 变成无意义的树状爆炸。

### 8.11 共同谱写：世界大书与众生个人卷

罗瓦莎后期“共同谱写”的结构，可以转译成未终章的核心阅读形态：

```text
世界是一部大书。
锚点角色拥有主线卷。
每个重要角色拥有个人卷。
每个势力可以拥有势力卷。
关键事件可以拥有多视角卷。
```

世界只有一个，但每个角色看到的世界不同。

因此未终章不应只是“一章一章的主线小说”，而应该支持：

- 世界正史卷：客观大事记。
- 主锚点卷：当前主角 / 当前叙事锚点的小说。
- 角色个人卷：女主、反派、配角、间谍、宗门长老等各自的故事。
- 势力卷：朝廷、宗门、敌国、商会、秘密组织的行动史。
- 联合故事卷：多个角色和势力在大事件中汇流的群像叙事。

这就是“多视角活体小说 / Character Lens Novel”的基础。

### 8.12 不照搬的部分

罗瓦莎的抽卡、等级、评分、商店、赛季等元素不应直接照搬。

这些机制可以提供底层启发，但未终章前端不应变成刷分游戏：

```text
剧情评分 -> Reviewer 评估
剧忆镜片 -> 沙盘事件材料
剧情添加剂 -> 干预编译后的材料注入
主人公候选 -> 候选天命承载者
世界树评分 -> 《天命书》与 Reviewer 对叙事稳定性的判断
```

未终章的核心不是“让用户刷出高分故事”，而是“让世界持续运行，让角色拥有自己的命运”。

## 10. 当前偏差

当前项目的主要偏差不是方向完全错误，而是产品焦点被稀释。

后续很多切片集中在：

- Graph Memory 触发证据。
- provider boundary。
- opt-in runbook。
- signoff schema。
- adapter contract。
- mock review。
- 检索 provider smoke。

这些工作可以作为底层工程准备，但不应该继续占据产品主线。

它们的问题是：

- 普通作者和读者很难感知价值。
- 它们不直接让角色更自主。
- 它们不直接让世界更会演化。
- 它们不直接让干预更有后果。
- 它们不直接让下一章更自然。

因此后续纠偏原则应该是：

> 凡是不能增强“世界会运行、角色会自主、干预有后果、角色可能反抗、章节更自然生成”的功能，先暂缓。

## 11. 建议的下一阶段主线

下一阶段建议回到：

> World Sandbox Loop MVP / 小说世界沙盘循环 MVP。

第一版不追求完整平台，而是验证一条小而完整的沙盘闭环。

后续执行原则：

> 先让世界活起来，再谈工程完美。

第一版 MVP 由 Codex 后续长任务执行时直接按产品闭环推进，不再优先扩张工程化支撑层。

#### 第一版 MVP 范围

第一版目标不是完善平台，而是证明“小说世界真的会自己动”。

必须覆盖：

```text
1. 选择一个项目 / 导入一段文本
2. AI 预抽《天命书》
3. 用户确认《天命书》
4. 输入一个事件或读者干预
5. 干预编译器读取《天命书》
6. 跑 3-5 个角色，3-5 轮角色行动
7. 每轮写入角色主观记忆
8. 输出：
   - 干预编译报告
   - 角色行动链
   - 角色主观记忆变化
   - 世界状态 delta
   - 事件材料 / 记忆镜片
   - 世界线代偿 / 锚点变化
   - 世界自演检查点
   - 下一章 brief
   - 可选角色个人卷片段
```

第一版暂不追求：

```text
不接 GraphRAG / Zep。
不做云端多用户。
不做复杂计费。
不做完整编辑器。
不做大型 UI 重构。
不做 provider 继续膨胀。
不做新的工程化报告面板。
```

#### 沙盘轮次模型

第一版沙盘轮次采用“角色行动轮”，而不是章节级世界状态推进。

一轮定义为：

```text
1. 读取当前世界状态
2. 为每个角色读取其主观记忆链
3. 角色根据欲望、利益、关系、误会、秘密、命痕和《天命书》压力判断局势
4. 角色产生本轮意图
5. 角色执行行动或选择不行动
6. 系统结算角色之间的冲突、信息传播、误会、因果债和世界状态变化
7. 给每个角色分别写入本轮主观记忆
8. 生成本轮 trace
```

第一版建议每次运行：

```text
角色数量：3-5 个核心角色 / 势力
轮次数量：3-5 轮
输出粒度：角色行动链 + 主观记忆变化 + 世界状态 delta + 下一章 brief
```

后续再逐步扩展：

```text
角色行动轮
  -> 小场景沙盘
  -> 章节级推进
  -> 篇章级推演
  -> 多世界线长期运行
```

不能一刀做完第一版就停止。第一版只是证明“角色会动”。后续必须沿着轮次模型继续迭代，把短轮次 demo 扩成可持续的长篇世界运行。

#### 世界自演 / World Autopilot

世界不应每轮等待用户确认。

如果每一轮角色行动、记忆写入和世界状态变化都需要用户手动审批，未终章就会退化成“分支生成器”，而不是活体小说世界。

默认产品体验应该是：

```text
用户设定观察目标
  -> 世界自动运行多轮
  -> 系统持续写入角色记忆和世界状态
  -> 生成检查点
  -> 用户回来后阅读世界演化报告、章节和角色个人卷
```

用户可以在睡前启动：

```text
运行 20 轮。
运行到下一次大战爆发。
运行到三个月后。
运行到某个角色死亡、登基、背叛。
运行到因果债爆发。
运行到锚点发生转移。
```

第二天看到的不是“请确认第 1 轮”，而是：

```text
昨夜世界演化报告：
  世界线推进到：皇帝驾崩后第 17 日
  关键事件：三皇子秘密结盟镇国将军
  新冲突：女主发现遗诏疑似被篡改
  角色记忆变化：反派开始怀疑有高维干预
  锚点状态：大皇子气运下跌，三皇子成为候选天命承载者
  因果债：朝廷内乱从重大压力升为时代压力
  可阅读章节：已生成 3 章
  可回溯检查点：第 4 轮 / 第 9 轮 / 第 15 轮
```

世界自演的底层规则：

```text
普通沙盘演化：自动提交。
普通角色行动：自动提交。
角色记忆写入：自动提交。
世界状态 delta：自动提交，并保留检查点。
普通读者干预：经过干预编译器后进入当前世界线。
L4 / L5 改写《天命书》：必须显式确认。
暴走 AU：必须显式确认。
作者模式采纳正史：必须由作者确认。
```

作者模式与读者模式的差异：

```text
作者模式：
  沙盘可以自动跑，但结果默认是推演稿。
  不自动覆盖作者原大纲或正式正史。
  作者可选择采纳、部分采纳、另开分支。

读者模式：
  个人世界线默认自动成为该读者的正史。
  读者主要观测、阅读、回看、分叉。
  只有高等级干预或暴走 AU 需要确认。
```

因此，“每轮手动确认”只能作为调试模式或作者精修模式，不应成为默认体验。

#### 多视角活体小说 / Character Lens Novel

章节不是世界本体，章节只是观察世界的一种镜头。

世界真正的本体是：

```text
世界状态
角色主观记忆
角色行动轮
关系变化
因果债
锚点变化
世界线分叉
事件材料 / 记忆镜片
```

同一个沙盘事实，可以被渲染成不同文本：

```text
世界正史卷：这个世界客观发生了什么。
主锚点卷：当前主角 / 当前叙事锚点的主线小说。
角色个人卷：某个角色基于自己记忆和视角的故事。
势力卷：某个宗门、朝廷、敌国、商会的行动史。
事件多视角卷：同一事件在不同人眼中的版本。
联合故事卷：多个角色和势力汇流后的群像叙事。
```

例如同样是“老皇帝驾崩”：

```text
主线卷：
  三皇子在灵堂前跪了一夜，群臣皆以为他悲痛过度。

反派卷：
  他跪在那里，不是为了哭父皇，而是在数殿中每一个低头的人。

女主卷：
  她第一次意识到，皇城不是家，而是一座会吃人的笼子。

间谍卷：
  密信必须在今夜送出。皇帝死了，边境的狼群该动了。
```

实现边界：

```text
第一版不必为每个角色持续生成完整长篇正文。
第一版必须保存每个角色的行动、记忆和事件材料。
主线 brief / 主线章节默认生成。
角色个人卷按需生成：用户点开某角色时，再根据该角色记忆链和事件 trace 生成视角片段。
```

这样可以控制成本，同时保留“每个角色都有自己的小说”的产品方向。

#### 样例闭环

第一版建议用两个 demo 场景覆盖作者和读者入口。

```text
作者模式：
  老皇帝驾崩。
  大皇子、三皇子、将军、间谍、女主、反派各自行动。
  系统长出作者没预设的新剧情。

读者模式：
  女主捡到写有未来大纲的信。
  她可能相信、怀疑、隐瞒、试探。
  反派可能察觉异常。
  世界线开始偏移。
```

这两个 demo 足够验证：

- 角色真的会自己行动。
- 读者干预真的有后果。
- 角色会记得、误会、反抗。
- 世界可以自演，不每轮等待用户确认。
- 同一事件可以渲染成主线卷与角色个人卷。
- 《天命书》、干预编译器、主观记忆链和下一章 brief 能连成闭环。

```text
S9 作者采纳反哺下一章 brief
```

讨论期原始节奏如下：

```text
v1：世界沙盘循环 / 单次角色行动轮
  跑起来，角色会行动。
  验收：老皇帝驾崩后，至少 3 个角色各自行动并产生世界状态 delta。

v2：主观记忆链 / 轮次持久化
  角色记得、误会、关系变化。
  验收：同一事件写入不同角色的主观记忆，下一轮行动受这些记忆影响。

v3：干预编译器 / 自由输入落地
  自由输入 -> 类型 / 层级 / 转译 / 分支轴。
  验收：用户输入未来大纲信、AK47、强制行动等不同干预时，系统能给出不同编译报告和分支轴。

v4：《天命书》/ 世界宪法
  叙事吸引子、世界法则、锚点、因果债、候选天命承载者。
  验收：干预编译器每次读取《天命书》，并用它解释兼容性、代价和分支方向。

v5：角色反抗 / 命痕与假意服从
  角色拒绝、假意服从、命痕上升。
  验收：角色能基于主观记忆拒绝干预，或表面服从、暗中布局。

v6：世界线代偿 / 锚点转移
  锚点转移、群像无主线、反派上位、失锚。
  验收：主角死亡、摆烂或觉醒后，世界能激活候选天命承载者，而不是停转。

v7：事件材料 / 记忆镜片
  把沙盘轮次中的关键事件材料化。
  验收：用户能看到某章或某个角色个人卷来自哪些事件材料、记忆和世界状态变化。

v8：章节 brief / 主线正文生成
  把沙盘结果写成真正可读章节。
  验收：沙盘 trace 能稳定生成下一章 brief，并可选生成主线正文。

v9：多视角活体小说 / Character Lens Novel
  世界正史卷、主锚点卷、角色个人卷、势力卷、事件多视角卷。
  验收：同一事件至少能生成主线视角和一个角色个人视角，且两者共享同一沙盘事实但存在主观差异。

v10：世界自演 / World Autopilot
  用户设定运行目标后，世界自动推进多轮并生成检查点。
  验收：用户可运行到指定轮数或触发条件，醒来后看到世界演化报告、检查点、角色记忆变化和可阅读文本。

v11：章节级推进
  多个角色行动轮汇总为一章级世界状态推进。
  验收：用户能看到本章发生了什么、哪些记忆被写入、哪些伏笔移动。

v12：篇章级与长篇循环
  多章节累积后，支持篇章级大势变化和长期世界线运行。
  验收：角色长期记忆、因果债和锚点变化能跨章节持续生效。
```

每一刀都必须有“读者能感到世界活了”的验收，而不是只新增服务、报告或工程看板。

#### 长任务执行禁区

后续使用 `/goal` 设定长任务时，Codex 应遵守：

```text
1. 先做叙事闭环，再做工程完美。
2. 每次只做一个能被用户感知的产品能力。
3. 新增代码必须服务沙盘、记忆、干预、反抗、章节生成。
4. GraphRAG / Zep / provider / OpenAPI / billing / release 只作为支撑，不主动扩张。
5. 能用本地 JSONL / artifact 证明的，先不用重型系统。
6. UI 不做更多工程看板，优先展示角色行动、主观记忆、世界变化。
7. 每轮完成后同步文档，但不为了文档状态表而偏离产品主线。
```

长任务目标模板：

```text
本次目标：
  做出一个用户能看到的沙盘能力。

必须产物：
  artifact / API / UI / 测试 / 文档同步。

禁止范围：
  不扩 provider，不接 GraphRAG，不做工程化面板，不改无关模块。

验收：
  能跑一个具体小说场景，并看到角色行动、记忆和世界变化。
```

候选流程：

```text
选择一个项目
  -> 选择作者模式或读者模式
  -> AI 预抽《天命书》：叙事吸引子、类型承诺、故事锚点、因果债、候选天命承载者
  -> 用户确认或微调《天命书》
  -> 输入一个变量
  -> 干预编译读取《天命书》：类型、层级、兼容性、转译策略、世界线类型、分支轴
  -> 加载角色、势力、目标、秘密、关系、领域记忆模型和当前世界状态
  -> 读取各角色在当前世界线上的主观记忆链
  -> 跑 5-10 轮沙盘推演
  -> 每轮后追加各角色本轮主观记忆
  -> 记录角色误会、命痕、反抗、假意服从或世界线残影
  -> 输出角色行动链
  -> 输出势力关系变化
  -> 输出世界状态 delta
  -> 输出伏笔触发和偏移
  -> 输出下一章 brief
  -> 可选生成正文或 2-3 条世界线
```

作者模式示例变量：

```text
老皇帝驾崩。
主角没有救那个小乞丐。
反派提前知道主角背后可能有高人。
宗门突然宣布闭山十年。
```

读者模式示例变量：

```text
给主角一个梦境提示。
让女主捡到写有未来大纲的信。
让配角重生并记得未来。
给主角一个系统。
让反派听到来自读者的一句低语。
```

## 12. UI 原型与产品信息架构

本轮纠偏生成的 UI 参考图已放入：

```text
docs/image/
```

索引见：

- [docs/image/README.md](./image/README.md)

这些原型不是最终视觉稿，也不是要求下一刀立刻大规模重写前端。它们的作用是固定一个方向：

> 未终章的 UI 不应继续长成工程状态面板，而应长成一个“可观察、可干预、可回放、可多视角阅读”的故事世界工作台。

### 12.1 总体信息架构

主导航建议围绕“世界正在运行”展开，而不是围绕底层 artifact 或 provider 展开。

本轮已定稿的主导航决策：

> 一级主导航用“世界书架 / 世界内部卷宗”组织，不采用“沙盘 / 阅读 / 干预 / 作者”四大工作区组织。

理由是：

```text
未终章的主体是故事世界，不是工具模块。
用户先进入某个世界，再选择观察、干预、阅读或作者采纳。
沙盘、阅读、干预、作者只是同一个世界里的不同操作方式。
如果一级导航按功能拆成四大工作区，产品会更像普通 AI 写作 SaaS；
如果一级导航按世界卷宗组织，产品会更像一部正在运行的活体小说。
```

因此最终骨架应是：

```text
一级：世界书架
二级：世界内部卷宗
常驻：读者干预栏
模式：作者 / 读者只影响权限、默认行为和采纳规则，不改变世界结构
```

“沙盘 / 阅读 / 干预 / 作者”不消失，而是降为场景能力：

```text
沙盘 = 世界沙盘页 + 自演控制
阅读 = 世界正史卷 / 主锚点卷 / 角色个人卷 / 势力卷
干预 = 底部常驻干预输入 + 干预编译器弹层
作者 = 作者采纳台 / 大纲对照 / Reviewer / 导出
```

建议一级入口：

```text
世界书架
  选择 / 创建 / 导入故事世界

天命书
  导入后确认世界宪法：天道大势、世界法则、当前锚点、因果债、候选天命承载者

世界沙盘
  启动世界自演，设定运行目标，查看自动推演状态

世界正史卷
  查看世界客观演化记录和章节级正文

主锚点卷
  查看当前叙事锚点的主线小说

角色个人卷
  进入某个角色的主观视角，看它自己的记忆、误会、欲望和行动

势力卷
  查看宗门、朝廷、敌国、商会等群体行动史

事件多视角
  同一事件在世界正史、不同角色记忆和后续章节中的不同形态

世界线
  查看分叉、锚点转移、代偿机制和 AU 走向

检查点
  回看、锁定、分叉、继续观察
```

工程解释层仍然存在，但应收在二级或三级：

```text
机制档案
运行日志
检索证据
Graph / Zep / provider readiness
OpenAPI / typed client
成本与模型画像
```

这些内容服务开发与调试，不应压过普通读者和作者看到的故事世界。

### 12.2 原型页面职责

#### 主工作台总览

参考图：

- [unfinale-ui-01-main-workspace-overview.png](./image/unfinale-ui-01-main-workspace-overview.png)

这是后续主体验的总览形态。它应该同时给用户三种感觉：

```text
世界正在自己运行。
角色拥有自己的镜头。
读者可以在底部随时投放变量，但世界不一定照做。
```

页面核心元素：

- 左侧：世界书架、世界正史卷、主锚点卷、角色个人卷、势力卷、事件多视角、检查点。
- 中央：世界自演报告或当前章节 / 当前事件。
- 右侧：角色镜头，展示某个角色的欲望、记忆提示、命痕、异常特征和个人卷预览。
- 底部：读者干预输入、Autopilot 控制、继续观察、锚定此刻、检查点管理。

这里的重点不是“显示更多数据”，而是让用户一眼知道：

```text
世界跑到哪里了？
谁在发生变化？
我现在能干预什么？
干预会不会造成锚点偏移？
```

#### 导入与《天命书》确认

参考图：

- [unfinale-ui-02-import-tianming-confirmation-a.png](./image/unfinale-ui-02-import-tianming-confirmation-a.png)
- [unfinale-ui-03-import-tianming-confirmation-b.png](./image/unfinale-ui-03-import-tianming-confirmation-b.png)

《天命书》确认页应成为每次导入后的必经初始化步骤，但不能做成复杂表单。

页面应该让用户看到：

```text
AI 已经读懂哪些文本？
抽出了多少人物、势力、地点、规则、伏笔和时间线？
系统预判这个世界的大势是什么？
当前故事锚点是谁或是什么？
哪些角色可能成为候选天命承载者？
如果修改《天命书》，会不会构成高等级干预？
```

交互原则：

- AI 先预抽，用户只做确认或微调。
- 修改“天道大势 / 世界法则 / 当前锚点 / 因果债 / 候选天命承载者”属于高等级操作，应有轻提示。
- 不默认锁死“无现代科技直入”等字段，避免阻止乐子人进入暴走 AU；但必须清楚提示这会造成异物入侵、因果债或 AU 偏移。
- 作者和读者模式权限相同，但作者模式采纳到正式大纲需要额外确认。

#### 世界自演控制

参考图：

- [unfinale-ui-04-world-autopilot-control.png](./image/unfinale-ui-04-world-autopilot-control.png)

世界自演控制页解决的是：

```text
我希望世界在我不看时推进到什么程度？
```

第一版应支持四类目标：

```text
运行到指定轮数
运行到指定事件
运行到指定时间
运行到锚点变化
```

必要控制项：

- 核心角色数量。
- 最大轮数。
- 允许生成的检查点数量。
- 是否自动写入角色记忆。
- 是否自动提交世界状态 delta。
- 是否保留回滚检查点。
- 是否只预演 3 轮，不产生真实变更。

必须清楚区分：

```text
普通行动自动提交。
普通记忆自动写入。
普通世界状态 delta 自动提交。
L4 / L5 改写《天命书》必须确认。
暴走 AU 必须确认。
作者模式采纳正史必须确认。
```

#### 昨夜世界演化报告

参考图：

- [unfinale-ui-05-autopilot-evolution-report.png](./image/unfinale-ui-05-autopilot-evolution-report.png)

这是 World Autopilot 的核心反馈页。用户睡醒回来，应该直接看到世界已经发生了什么，而不是看到“请确认第 1 轮”。

页面应展示：

- 运行到第几轮 / 世界内时间。
- 每个关键轮次发生了什么。
- 哪些事件写入了角色记忆。
- 哪些谣言、误会、伏笔或因果债扩散了。
- 哪些锚点稳定度下降或上升。
- 哪些角色命痕上涨。
- 可回溯检查点。
- 可从某个检查点分叉。
- 可基于演化结果生成章节或角色个人卷。

这页的产品价值是让“世界自演”可信，而不是只给一个摘要。

#### 干预编译器

参考图：

- [unfinale-ui-06-intervention-compiler.png](./image/unfinale-ui-06-intervention-compiler.png)

干预编译器是自由输入和世界规则之间的中介。它不能只是把用户输入改写成 prompt。

页面应固定展示：

```text
原始干预
干预类型
干预层级
世界法则契合度
本土化转译方式
潜在代价 / 因果债
本次专属分支轴
影响角色
预计影响范围
```

交互按钮应至少包含：

```text
确认投放
改为暴走 AU
重新编译
取消
```

文案要做叙事化包装：

```text
Intervention Type -> 因果要素
Intervention Level -> 时空波纹强度
World Compatibility -> 法则契合度
Translation Strategy -> 法则吸收方式
Branch Axis -> 未来命运线推演
```

底层仍然可以保留结构化字段，但前端不要把读者直接扔进 PM / 工程术语堆里。

#### 多视角活体小说

参考图：

- [unfinale-ui-07-character-lens-novel.png](./image/unfinale-ui-07-character-lens-novel.png)

这页是“章节只是观察镜头”的主要承载。

同一个世界事实应该可以切换成：

```text
世界正史
主锚点志
反派卷
女主卷
间谍卷
势力卷
```

右侧角色镜头应展示：

- 当前欲望。
- 深层恐惧。
- 当前记忆。
- 隐藏动机。
- 信任关系变化。
- 命痕 / 异常感。
- 查看完整记忆链入口。

底部应展示“同事件其他视角”，让用户意识到：

```text
同一件事不是只有一章正文。
每个角色都在用自己的记忆和误会书写自己的小说。
```

#### 世界线与锚点代偿

参考图：

- [unfinale-ui-08-worldline-anchor-compensation.png](./image/unfinale-ui-08-worldline-anchor-compensation.png)

世界线页不应只是树状分支。它要解释世界为什么没有停转。

页面应包含：

- 多条带权重的叙事吸引子。
- 当前世界线节点。
- 锚点偏移发生在哪一轮。
- 当前锚点承载者。
- 潜在承载者。
- 候选天命承载者的欲望契合、能力匹配、资源匹配和风险。
- 世界线代偿证据：历史代偿、物理与社会惯性、故事合约压力。

用户应该能看到：

```text
主角死亡 / 摆烂 / 觉醒后，世界为什么继续向前。
是谁接住了原本的叙事重力。
这个新锚点是自然上位，还是读者强行扶持。
```

#### 作者采纳台

参考图：

- [unfinale-ui-09-author-adoption-desk.png](./image/unfinale-ui-09-author-adoption-desk.png)

作者模式不应该让沙盘自动覆盖作者原大纲。作者看到的是“推演建议”，而不是“系统替你改稿”。

页面应做三列：

```text
原大纲 / 作者正史线
采纳方式
沙盘涌现剧情
```

可选操作：

- 采纳为正史。
- 部分采纳。
- 生成下一章 brief。
- 另开作者分支。
- 导出大纲。

Reviewer 检查应聚焦：

```text
人设一致
节奏
爽点
连续性
伏笔
```

作者最终拥有正史决定权。

#### 事件多视角与记忆证据

参考图：

- [unfinale-ui-10-event-perspective-memory-inspector.png](./image/unfinale-ui-10-event-perspective-memory-inspector.png)

这是“主观连续性”的检视页。

同一事件应拆成：

```text
世界正史记录：客观事实。
角色主观记忆：各自所见、所想、误会、盲区。
叙事去向：会进入谁的个人卷、保留为伏笔、进入下一章 brief 或成为命痕触发源。
误会图谱：谁怀疑谁，谁利用谁，谁被谁误导。
```

关键按钮：

- 生成事件多视角正文。
- 写入角色记忆。
- 从此处干预。
- 查看检查点。
- 导出本事件报告。

这页能让用户相信角色不是共享同一本正史摘要，而是各自活在自己的认知里。

### 12.3 UI 实现边界

后续实现 UI 时应遵守：

```text
第一版先做信息架构和核心交互，不追求完全复刻图片视觉。
页面文案必须中文。
不要做营销落地页。
不要让 provider、GraphRAG、OpenAPI、成本面板占据主导航。
不要把所有 artifact 原样塞进 UI。
每个页面都必须回答一个用户问题：
  世界发生了什么？
  谁为什么这样做？
  我的干预被世界理解成了什么？
  这个世界线为什么偏移？
  哪个角色记住了什么？
  下一章从哪些世界事实长出来？
```

视觉风格继续沿用 v0.7 方向：

```text
古风纸面
克制系统感
宣纸暖白
墨黑 / 朱砂 / 玉青 / 深绿 / 低饱和金
少量卡片
稳定三栏布局
动作和因果变化用轻量动效表达
```

UI 的第一原则：

> 让用户觉得自己打开的不是一个 AI 工程控制台，而是一部正在自我运行、可以被观察和干预的小说世界。

## 13. 第一刀成功标准

第一刀成功不看面板数量，而看是否出现真正的沙盘感。

最低验收可以是：

- 输入一个变量后，至少 3 个角色或势力给出各自行动。
- 每个行动都能解释其欲望、记忆、利益、关系或误判来源。
- 每个参与角色在每轮后都有自己的主观记忆记录，不混用全局正史摘要。
- 分叉后能说明新世界线继承了哪些分叉前记忆，追加了哪些分叉后记忆。
- 同一事件能写入至少 2 个角色的不同主观记忆，允许信息差和误会存在。
- 角色能基于自身记忆、误会、创伤或利益，拒绝或扭曲执行读者干预。
- 连续强干预后，至少一个角色能积累命痕 / 异常感，并在行动中体现怀疑。
- 高智商或高觉醒角色可以出现假意服从、隐瞒真实意图或反向利用读者干预。
- 能生成并确认《天命书》，至少包含叙事吸引子、类型承诺、故事锚点、因果债和候选天命承载者。
- 输出一个结构化世界状态 delta。
- 输出至少 2 个后续剧情可能性。
- 输出一个 writer 可用的下一章 brief。
- 读者强干预时，系统能给出接受、转译、拒绝、反噬或 AU 分支判断。
- 每次读者干预都生成本次专属分支轴，不再默认套用“相信 / 不信 / 半信半疑”。
- 设定级干预能明确判断是否开启 Alternate Novel / AU 或触发故事锚点转移。
- 当前锚点失稳时，系统能给出世界线代偿方向和候选天命承载者。
- 角色反抗不是文案噱头，而能体现在行动和状态变化中。

## 14. 后续讨论问题

后续纠偏可以围绕以下问题展开：

1. 角色第四面墙感知应该作为稀有事件，还是作为可配置世界规则？
2. Reviewer 第一版只评审，还是允许提出修订 brief？
3. 跨世界线残影应该只在高觉察角色身上出现，还是允许作者模式显式开启？

## 15. 一句话纠偏原则

后续所有功能都应服务这五件事：

```text
世界会运行。
角色会自主。
干预有后果。
角色可能反抗。
世界会代偿。
章节来自世界演化，而不是孤立续写。
```

如果一个功能不服务这五件事，即使技术上很高级，也应该先放到支撑层或后置队列。
