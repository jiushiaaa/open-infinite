# 未终章产品愿景纠偏稿

> 用途：保存产品方向的“为什么”。执行事实看 `../memory.md`，当前主线看 `unfinale-world-sandbox-remodel-prd.md`，后续优化看 `unfinale-current-optimization-backlog.md`。

## 1. 一句话愿景

未终章是一部会自我生长的小说世界。用户不是向模型索要一段续写，而是进入一个有命运、记忆、误判、反抗和代偿的世界，观察、干预，并把涌现结果读成章节。

## 2. 纠偏重点

| 误区 | 正确方向 |
| --- | --- |
| 把产品做成续写文本框 | 做成世界书架和世界内部卷宗 |
| 把角色当提示词里的名字 | 让角色有主观记忆、利益、误判和边界 |
| 把干预当用户命令 | 干预要被世界吸收、抵抗、扭曲或代偿 |
| 把章节当唯一真源 | 世界状态、天命书和主观记忆是真源，章节是观察窗口 |
| 把支撑层当产品主线 | provider、Graph、检索、发行只在明确触发时进入 |

## 3. 双入口

| 入口 | 用户意图 | 产品形态 |
| --- | --- | --- |
| 读者入口 | 续写断更、拯救意难平、探索平行世界 | 世界书架 -> 世界锚定房间 -> 阅读/干预/世界线 |
| 作者入口 | 压力测试大纲、观察角色自主推演、采纳涌现剧情 | 世界沙盘 -> 结果读解 -> 作者采纳台 -> 下一章 |

两个入口都属于同一个世界，不拆成“阅读工作区 / 沙盘工作区 / 作者工作区”三个一级产品。

## 4. 核心对象

| 对象 | 作用 |
| --- | --- |
| 天命书 | 记录命运锚点、候选承载者、世界惯性和可被挑战的规则 |
| 世界线 | 承载状态、分叉、代偿、检查点和章节历史 |
| 角色主观记忆 | 让角色从自己的视角记住、误判、隐瞒或反抗 |
| 卷宗 | 把世界正史、主锚点、角色、势力、事件多视角和长线证据变成可读入口 |
| 作者采纳台 | 把沙盘涌现材料转成可编辑、可定稿、可入卷的下一章 |

## 5. 当前已经落地

第一版已经覆盖世界书架、世界锚定房间、天命书、世界沙盘、主观记忆、干预代偿、世界自演、多视角正文、卷宗阅读、作者采纳、Reviewer 局部重写、编辑后定稿、确认入卷和下一轮入口。

已完成项不再在愿景稿里展开长表。追溯见 `history/project-changelog.md`；当前优化见 `unfinale-current-optimization-backlog.md`。

## 6. 接下来要变强的体验

- 角色不是轮流发言，而是多轮规划、试探、误判、隐瞒、反抗和结算。
- 章节不是事件摘要，而是有节奏、视角、动机、伏笔和回收的正文。
- 干预不是指令生效，而是进入世界规则后产生后果、阻力和代偿。
- Reviewer 不是检查清单，而是像小说编辑一样保持文风、节奏和伏笔。
- 卷宗不是列表，而是能支撑用户跨章节追踪误会、证据、势力和世界线。

## 7. 视觉方向

- 古风纸面、克制系统感、留白和档案质感。
- 品牌/产品/世界本身要在首屏可见，不做营销落地页。
- UI 优先支持阅读、扫描、比较和继续操作。
- 不把功能介绍文字塞进界面；操作控件要自然出现在任务流里。

## 8. 边界

默认不做 provider 矩阵、GraphRAG/Zep、OpenAPI 面板、发行安装包、云端商业化、计费和认证。它们可以是未来能力，但不是当前愿景的主燃料。
