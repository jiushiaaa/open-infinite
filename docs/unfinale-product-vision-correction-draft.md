# 未终章产品愿景与纠偏稿

> 用途：保存未终章的产品灵魂、设计原则和“为什么不能跑偏”。当前实现事实以 `../memory.md` 为准；执行路线以 `unfinale-world-sandbox-remodel-prd.md` 为准；主产品 PRD 见 `living-novel-engine-prd.md`；文档分层见 `index.md`。本文不是历史完成清单，也不是下一刀列表。

## 1. 原始愿望

未终章来自一个阅读小说时产生的问题：

```text
小说能不能不再只是被作者写完的静态文本，
而是一个仍在运行、可以观察、可以干预、会分叉，
甚至会反向凝视读者的故事世界？
```

传统小说主要是“读者与书”的关系；更进一步，是“读者与作者”的关系。未终章想加入第三层关系：读者、作者与故事世界本身的关系。

这个世界里的角色不应只是剧情工具。足够真实的角色应该有欲望、恐惧、误会、利益、秘密、记忆和命运惯性；当外部干预落下时，他们可能相信、误解、抵抗、利用、隐瞒，甚至意识到某种高维力量正在改写命运。

一句话：

```text
未终章 = 小说世界沙盘 + 命运干预系统 + 多视角活体小说。
```

## 2. 纠偏结论

过去项目已经完成大量底座：导入、记忆、正史账本、检索、provider、Graph 评估、发行准备、商业化边界、本地启动和真实向量检索 opt-in。这些能力有价值，但它们不是产品灵魂。

当前最高优先级是把能力重新组织成世界沙盘体验：

```text
导入 / 创世
  -> AI 预抽并确认《天命书》
  -> 多 Agent 世界沙盘轮次
  -> 每个角色写入独立主观记忆链
  -> 世界状态、因果债、锚点和候选天命承载者变化
  -> 世界自演生成检查点
  -> 读者自由干预经干预编译器投放
  -> 多视角活体小说渲染
  -> 作者模式采纳或导出沙盘涌现剧情
```

如果一个功能不服务下列目标，即使技术高级，也应放到支撑层：

```text
世界会运行。
角色会自主。
角色会记得。
干预有后果。
角色可能反抗。
世界会代偿。
章节来自世界演化。
```

## 3. 双入口，一套底层

### 3.1 作者入口：剧情沙盘

作者已有设定、大纲、章节、人设、势力关系和命运边界。作者需要的不是系统替他完全写书，而是：

- 把已有世界转成可运行资料。
- 让角色根据欲望、记忆、利益和误会行动。
- 推演世界自然会发生什么。
- 暴露大纲中的弱冲突、工具人、强行转折和遗漏伏笔。
- 把沙盘涌现剧情整理为可采纳、可改写、可确认入卷的材料。

作者模式的核心价值：

```text
让作者看到自己的世界如果真的运行起来，会长出哪些他未必预先想到的剧情。
```

### 3.2 读者入口：世界线干预

读者可以导入或进入一个故事世界，像高维存在一样投放变量：

- 拯救意难平角色。
- 改变关键事件。
- 给主角一个梦境提示。
- 向配角投放未来记忆。
- 引入谣言、信件、资源、灾难或异物。
- 观察世界如何吸收、抵抗、转译、反噬或分叉。

读者模式的核心价值：

```text
不是“想怎么改就怎么改”，而是“投放变量，看世界和角色如何回应”。
```

作者入口和读者入口共享同一套底层：世界抽取、天命书、主观记忆、多 Agent 沙盘、世界状态、叙事规划、正文生成和 Reviewer。

## 4. 核心设计原则

### 4.1 领域记忆模型是主真源

领域记忆模型不是外部数据库，也不是 GraphRAG 或 Zep 的同义词。它定义的是：

```text
在小说世界里，哪些信息应该被谁记住，
以什么身份存在，
在哪条世界线上有效，
能不能被其他角色知道，
能不能影响下一轮行动。
```

同一事件需要分层保存：

| 层 | 示例 |
| --- | --- |
| 正史事实 | Bob 偷走了钥匙 |
| Alice 的主观记忆 | 我看到 Bob 半夜经过库房，所以怀疑他 |
| Bob 的主观记忆 | 我偷了钥匙，但 Alice 应该没有证据 |
| 公开世界状态 | 钥匙失踪，库房门锁被撬 |
| 秘密 | Bob 是偷钥匙的人 |
| 误解 | Alice 以为 Bob 为反派做事，其实 Bob 是为保护她 |
| 干预痕迹 | 读者让 Alice 梦见钥匙 |
| 世界线残影 | 高觉察 Alice 梦见另一条世界线的结局 |

外部检索、Graph、向量库只能做召回增强，不能替代主真源。

### 4.2 角色主观记忆链必须独立

每个角色在每条世界线上都应有自己的记忆链：

- 分叉前记忆共享，分叉后各自追加。
- 角色只知道自己看到、听到、推测或被告知的内容。
- 秘密、误解、怀疑和信任变化要影响下一轮行动。
- 高觉察角色可以拥有世界线残影，但必须作为特殊记忆处理。

角色不是共享同一本全局摘要。一个世界是否“活”，首先看角色是否被自己的记忆改变。

### 4.3 《天命书》是世界宪法，不是剧情脚本

《天命书》记录世界长期牵引和边界：

- 叙事吸引子。
- 类型承诺。
- 当前锚点。
- 因果债。
- 候选天命承载者。
- 干预等级和世界线快照。

它不强迫角色照剧本行动，也不保证主角永远胜利。它解释的是：当锚点失稳、角色死亡、干预过强或世界进入 AU 时，世界如何继续运行、转移压力和产生代偿。

普通干预不能直接改写根天命书。L4/L5/AU 级别的改写必须进入世界线快照或代偿审计，不覆盖根世界宪法。

### 4.4 干预要被世界理解，而不是被模型服从

用户输入的不是 prompt 命令，而是投放到世界里的变量。

干预编译器要回答：

- 干预属于梦境、谣言、信件、资源、异物、系统、重生、世界法则改写还是元叙事污染？
- 当前世界能自然吸收吗？
- 需要本土化转译吗？
- 会产生什么因果债？
- 会进入 Divergent 世界线、Alternate Novel / AU，还是触发角色觉醒？
- 哪些角色会相信、怀疑、利用、隐瞒或反抗？

### 4.5 世界代偿要进入后续状态

世界不会因为主角死亡、锚点摆烂或强干预就停止。代偿应体现为：

- 地点变化。
- 资源损耗。
- 伤势和身体代价。
- 舆论和模因传播。
- 势力关系变动。
- 环境和制度压力。
- 候选锚点被推到前台。

代偿不是报告文字，而应被下一轮沙盘、检查点、多视角正文和下一章 brief 继续消费。

### 4.6 章节是观察镜头

同一世界事实可以被写成多种文本：

- 世界正史卷。
- 主锚点卷。
- 角色个人卷。
- 势力卷。
- 事件多视角。
- 作者确认入卷正文。

多视角不是重复说明同一事件，而是展示不同认知、盲区、误会和利益判断。正文要让人能连续读下去，证据链应默认折叠，必要时再展开。

### 4.7 Reviewer 是小说编辑，不是规则清单

Reviewer 应关注：

- 人物动机是否成立。
- 冲突张力是否递进。
- 世界状态、因果债和代偿是否自然入文。
- 视角是否稳定。
- 主观记忆是否真的被使用。
- 章节是否好读。

局部重写建议必须能被作者采纳，进入下一章草稿、编辑后定稿或确认入卷，而不是停在审稿报告。

## 6. 当前仍要深挖的深水区

1. 真实多 Agent 策略博弈：长期目标、势力资源、欺骗、假意服从、反向利用和临场改判还要更稳定。
2. 长期主观记忆心理模型：记忆不应只作为字段存在，而要让角色性格、信任、怀疑和创伤持续变化。
3. L5 觉醒与反抗：觉醒角色应可能试探、隐藏、误导或利用读者，而不是只报告“我察觉了”。
4. 世界线代偿持续驱动：代偿要成为未来行动的压力，不是一次性解释。
5. 世界自演的睡醒体验：醒来报告要像一夜世界真的发生过事情，而不是运行摘要。
6. 长正文与连续阅读：减少卷宗/说明文痕迹，强化文学连续性、视角切换、伏笔回收和结尾悬念。
7. 语义 Reviewer 与整章定稿：从片段级改写继续走向整章风格润色和真实模型编辑器。
8. 正文内证据锚点与误会图谱：阅读时能自然看到谁知道什么、谁误会了什么、证据从哪里来。

## 7. UI 方向

UI 应像“世界内部卷宗”，不是工程控制台。

主导航按世界组织：

```text
世界书架
  -> 天命书
  -> 世界沙盘
  -> 世界正史卷
  -> 主锚点卷
  -> 角色个人卷
  -> 势力卷
  -> 事件多视角
  -> 世界线
  -> 检查点
  -> 作者采纳台
```

不要把一级导航设计成“沙盘 / 阅读 / 干预 / 作者”四大工作区；这些只是场景能力。

视觉方向继续沿用：

```text
古风纸面
克制系统感
宣纸暖白
墨黑 / 朱砂 / 玉青 / 深绿 / 低饱和金
少量卡片
稳定三栏或阅读布局
证据链折叠，不打断正文
```

每个页面都要回答一个用户问题：

- 世界发生了什么？
- 谁为什么这样做？
- 我的干预被世界理解成了什么？
- 这个世界线为什么偏移？
- 哪个角色记住了什么？
- 下一章从哪些世界事实长出来？

## 8. 不再默认扩张的方向

以下方向都可以作为支撑层存在，但不能抢走世界沙盘主线：

- provider / cost / route matrix。
- GraphRAG / Zep / 图数据库。
- 默认 hybrid vector。
- OpenAPI / typed client 面板。
- 发行安装包和服务器在线体验。
- 认证、对象存储、队列、计费和商业化平台。
- 纯工程健康报告。
- 往 `WorkspacePage` 继续堆只读面板。

## 9. 一句话纠偏原则

每次开工前问：

```text
这件事能不能让用户更强烈地感到：
世界在运行，
角色在自主行动，
记忆在改变角色，
干预有后果，
角色可能反抗，
世界会代偿，
章节是从世界演化中长出来的？
```

如果答案是否，它就不是当前主线。
