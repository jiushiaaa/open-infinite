# LNE 后续增强清单

> 口径：这些不是当前阻塞项。它们要么已经有可跑 MVP / artifact / UI，要么属于长篇记忆增强技术；后续是否做，取决于本地试用反馈、长篇质量问题和真实用户场景。论文来源主要参考 `docs/article/reports/` 下 4 篇研读报告；开源项目来源主要参考 `Reference_projects/` 下的 `webnovel-writer`、`autonovel`、`WenShape`、`MiroFish`、`eastworld`、`AI_NovelGenerator`。

## A. 已做 MVP，但复杂产品化还没做深

| 模块 | 当前已做 | 还没做深的部分 | 建议触发条件 |
| --- | --- | --- | --- |
| ChapterBrief / 长篇摘要 | 已有章节摘要、分层记忆、canon ledger | LLM 场景级切分、细粒度事件抽取、角色状态投影、人工校正工作台 | 长篇续写明显忘远期信息 |
| Contract Audit | 已有 contract、guardrail、审计报告 | 磁盘 contract 深度接入运行时强约束 | 出现合约越界误判/漏判 |
| 状态执行 Overlay | 可 dry-run、apply、rollback | overlay 自动喂回下一轮 runner | 用户希望状态变化连续影响后续章节 |
| ActDirector / CharacterAction | 有动作计划、动作注册表、结构化字段 | `AbstractIntervention -> CharacterActionSequence -> runner 执行` 主链路 | 角色行为需要真正按动作前置/效果执行 |
| Dynamic Action Registry | 可沉淀动作别名、前置、效果、失败原因 | 可执行动作库、动作推荐、实体解析驱动 | 用户频繁输入未预设动作 |
| Narrative Diagnostics | 有节奏、张力、转折诊断 artifact | 诊断反馈 narrator，自动改写/增强下一章 | 生成文本节奏平、转折弱、早收束 |
| Emergence Nodes | 有 run 级涌现节点 | 跨 run 聚类、高价值节点推荐、模板市场、社区分享 | 用户干预产生的新路径需要沉淀复用 |
| Worldline Judge | 有分支级 deterministic 评分 | LLM 语义评审、run 级聚合评审、复杂对比评审页 | 用户需要更像编辑/读者的主观质量判断 |
| Baseline / Canon Replay | 有无干预基线、holdout、range replay、审计 UI | baseline/intervention 并排偏离分析、审计写回 canon ledger | 需要评估“偏离原作多少/是否应该纳入正史” |
| Visual Assets | Seedream 增强层、封面/头像/场景图、占位降级 | 批量队列、世界线节点缩略图绑定、图片版权/分享策略 | 视觉资产成为主要产品体验 |
| Provider / Cost | 脱敏状态、route matrix、usage、手动估算 | 预算控制、硬配额、账单事件、provider failover 策略 | 真实外部用户开始产生模型成本 |
| 本地运行体验 | Windows/macOS 启动脚本 | GitHub Release 安装包、内置 runtime、自动升级 | 非技术用户安装依赖有困难 |
| Chapter Commit / 投影健康 | 有 canon ledger、审计日志、导出 guard | 写后真源、projection/read-model 健康检查、章节提交验收 | 需要知道“哪些事实被接受、哪些投影失败” |
| Runtime Preflight | 有 release preflight、settings checklists | 创作前运行时健康检查：contract、memory、ledger、provider、rights 一屏聚合 | 长篇续写前经常缺 artifact 或状态不一致 |
| 修订与读者评审 | 有 Worldline Judge、叙事诊断、anti-slop 指标 | reader panel、adversarial edit、Elo 对比、revision brief、plateau detection | 生成质量进入主要瓶颈 |
| 设定 Cards 工作台 | 有 MasterSetting Workspace Lite | 角色卡、世界卡、风格卡的细粒度编辑与版本化 | 作者需要长期维护设定资产 |
| API / Typed Client | 有本地 HTTP API 与前端类型 | OpenAPI schema、自动生成 typed client、外部集成契约 | 后续接桌面壳、插件、外部前端或开放 API |

## B. 长篇记忆增强技术

| 技术 | 作用 | 当前状态 | 适合什么时候接 |
| --- | --- | --- | --- |
| Embedding | 把文本转成语义向量，支持“意思相近”的召回 | 未接入 | BM25 找不到换说法的相关内容 |
| 向量库 | 存储和检索 embedding，如 Qdrant / Milvus / Pinecone / Weaviate | 未接入 | 项目达到 50+ 章、百万字，语义召回压力变大 |
| GraphRAG | 用实体关系图做检索增强，适合人物/势力/道具/因果链 | 未接入 | 角色关系、伏笔因果、资源状态经常错乱 |
| Zep | Agent 长期记忆服务，可存事实、实体、关系、对话记忆 | 未接入 | 想用现成记忆后端，而不是继续自研文件型记忆 |
| Reranker | 对 BM25/向量/图谱召回结果重新排序 | 未接入 | 召回结果太多，prompt budget 塞不下 |
| Prompt Budget Pack | 把检索结果压缩打包进模型上下文 | 仅有轻量 prompt_block | 长篇检索命中多，但上下文预算有限 |

## C. 推荐接入顺序

1. 先跑现有：BM25 + canon ledger + entity aliases + runtime memory。
2. 如果召回不够，先加 embedding + 向量库。
3. 如果关系/因果/状态链容易错，再加 GraphRAG 或 Zep。
4. 如果召回结果太多，再加 reranker。
5. 最后做 prompt budget pack，把检索结果压缩成稳定上下文包。

## D. 当前不建议立刻做的重型项

| 项 | 原因 |
| --- | --- |
| 一次性接 Zep + 向量库 + GraphRAG | 难判断问题来自哪一层，调试成本高 |
| 默认替换成 LangGraph/OASIS/CAMEL | 当前 runner 还没被真实复杂样例证明不够 |
| 云端多租户 + 计费 + 对象存储一起做 | 会把本地产品验证拖进平台工程 |
| LLM 语义评审全面替代 deterministic judge | 成本、稳定性和可解释性都还需要先验证 |

## F. 论文深化推荐顺序

1. **Action Execution MVP+**：先让 `act_director_plan.json` 中的动作真正影响 opt-in 状态执行。
2. **Precondition Validator**：把动作失败原因从解释层升级为执行前检查层。
3. **Narrator Planning MVP**：新增 `turning_point_plan.json`，让章节生成前先规划关键转折和未解代价。
4. **Emergence Cluster MVP**：跨 run 汇总用户欲望路径，识别值得继续开发的涌现路线。
5. **Baseline vs Branch Graph**：把 baseline、canon、用户世界线差异结构化成分歧图。
6. **Semantic Judge Spike**：最后再引入 LLM 语义评审，先抽样、低频、可关闭。

## I. 开源项目吸收推荐顺序

1. **Chapter Commit / Projection Health**：先把“生成后哪些事实被接受、哪些投影成功、哪些投影失败”做成明确写后真源和健康检查。
2. **Runtime Preflight**：在创作前聚合 contract、memory、ledger、selected worldline、overlay、provider、rights，减少长篇续写前的隐性坏状态。
3. **Reader Panel + Adversarial Revision Lab**：当生成质量成为主要问题时，引入多视角读者评审和对抗式删改，比单纯加 prompt 更可控。
4. **LLM Profile Assignment**：真实模型使用增多后，把不同任务的模型、温度、预算、降级策略显式化。
5. **Cards Workspace**：当用户开始长期维护同一本书时，把角色卡、世界卡、风格卡变成可编辑设定资产。
6. **OpenAPI / Typed Client**：当需要桌面壳、外部前端、插件或开放 API 时，再把 HTTP 契约生成化。
7. **Bundled Release / Desktop Packaging**：本地脚本稳定后，再做 GitHub Release、内置 runtime、Windows 一键启动。
8. **GraphRAG / Zep / Temporal Memory**：继续保持触发式；只有真实长篇样例证明 BM25 + canon ledger + aliases 不够时再接。

## J. 当前不建议直接复制的开源项目形态

| 项 | 原因 |
| --- | --- |
| 直接搬 `MiroFish` 的 OASIS / CAMEL / Zep 服务栈 | 依赖重、账号和部署复杂，当前 LNE 更需要先证明自研 runner 与 artifact 闭环不够用 |
| 直接搬 `eastworld` 的 FastAPI / Redis / OpenAPI server | LNE 当前是本地文件产物 + 轻量 HTTP API，直接替换会扩大运维面 |
| 把 `autonovel` 做成一键全自动写完整本书 | LNE 的核心是读者干预与世界线演化，不是纯自动长篇生产线 |
| 把 `WenShape` 的作者工作台完整迁入 | 可以借鉴 cards、profile、打包方式，但 LNE 不应变成传统作者写作软件 |
| 直接接向量库 / reranker / GraphRAG | 先用现有 retrieval probe 证明 BM25 召回不足，再决定接哪一层 |
