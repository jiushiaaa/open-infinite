# LNE 后续增强清单

> 口径：这些不是当前阻塞项。它们要么已经有可跑 MVP / artifact / UI，要么属于长篇记忆增强技术；后续是否做，取决于本地试用反馈、长篇质量问题和真实用户场景。论文来源主要参考 `docs/article/reports/` 下 4 篇研读报告；开源项目来源主要参考 `Reference_projects/` 下的 `webnovel-writer`、`autonovel`、`WenShape`、`MiroFish`、`eastworld`、`AI_NovelGenerator`。

> 产品入口边界：前端是产品入口，API 是能力层，CLI 是工程外壳。后续增强若属于普通用户需要理解或操作的能力，必须优先设计 Web UI + API；CLI 仅保留为开发者、本地服务启动、自动化验收、批处理、JSON 输出和无人值守复跑的薄封装。

> 2026-06-04 纠偏口径：本清单是支撑层与后置增强索引，不是当前主路线。World Sandbox Loop / 世界沙盘改造 v1-v8 已形成第一版可运行闭环；当前最高优先级见 `unfinale-world-sandbox-remodel-prd.md` 的 S1-S9 深化路线：Agent 决策加深、主观记忆心理模型、动态《天命书》、干预可执行投放、L5 觉醒反抗、代偿持续驱动、自演任务化、多视角正文和作者采纳反哺章节 brief。除非用户明确要求，不再继续默认扩 GraphRAG/Zep、provider spike、真实向量检索评测、OpenAPI、发行、计费或工程健康面板。

> 2026-06-06 文档治理口径：本清单继续保留，因为它能解释支撑层为什么存在、哪些能力已闭环、哪些触发后再做；但它不承担“官方下一步”。当前下一步以 `../memory.md`、`docs/index.md` 和 `unfinale-world-sandbox-remodel-prd.md` 为准。

## C. 推荐接入顺序

1. 先跑现有：BM25 + canon ledger + entity aliases + runtime memory。
2. 先看 `Embedding / Vector Retrieval Readiness Probe`：没有失败样本时只监控，不接重型服务。
3. 如果换说法召回失败稳定复现，先用 Embedding Evaluation Samples 做 mock embedding 对照评估。
4. 如果样本数量变多，先用样本 export pack 把失败 query 变成可迁移评测集。
5. 已完成 mock evaluation report、replay report、migration pack、跨项目索引、趋势快照、GraphRAG/Zep trigger evidence、Graph Memory Spike Design Pack、Shadow Compare Pack、Shadow Case Matrix、Provider Boundary Matrix、Offline Shadow Replay Plan/Report、Provider Spike Fixture Pack、Provider Spike Readiness Gate、Provider Spike Runbook、Provider Spike Dry-run Result Template、Provider Spike Mock Result Report、Provider Spike Review Gate、Provider Spike Manual Approval Pack、Provider Spike Manual Approval Evidence Checklist、Provider Spike Opt-in Evidence Snapshot、Provider Spike Opt-in No-go Matrix、Provider Spike Opt-in Operator Checklist、Provider Spike Opt-in Review Packet、Provider Spike Opt-in Decision Ledger Preview、Provider Spike Opt-in Final Readiness Summary、Provider Spike Opt-in Human Signoff Schema Draft、Provider Spike Opt-in Config Draft、Local Provider Contract、Single Fixture Dry-run Harness、Mock-compatible Adapter 和 Manual Mock Adapter Review。
6. 已完成真实 provider 和 Vector Retrieval Pipeline：百炼 embedding、Zilliz Cloud、百炼 rerank 可真实使用；API/UI 可显式建索引和检索预览；运行时用 `LNE_RETRIEVAL_STRATEGY=hybrid_vector` opt-in。
7. 下一步如果继续检索增强，应先用真实失败样本批量 replay，决定是否推荐或默认启用 hybrid vector；默认替换 BM25 仍需另行确认。
8. 如果关系/因果/状态链容易错，先做 GraphRAG 或 Zep trigger evidence，再评估是否接入真实 GraphRAG/Zep。
9. Prompt Budget Pack 已先做轻量只读预算包；后续只有在接入 opt-in prompt 编排或需要更细的 hybrid vector 成本/上下文控制时再深化。

## J. 当前不建议直接复制的开源项目形态

| 项 | 原因 |
| --- | --- |
| 直接搬 `MiroFish` 的 OASIS / CAMEL / Zep 服务栈 | 依赖重、账号和部署复杂，当前 LNE 更需要先证明自研 runner 与 artifact 闭环不够用 |
| 直接搬 `eastworld` 的 FastAPI / Redis / OpenAPI server | LNE 当前是本地文件产物 + 轻量 HTTP API，直接替换会扩大运维面 |
| 把 `autonovel` 做成一键全自动写完整本书 | LNE 的核心是读者干预与世界线演化，不是纯自动长篇生产线 |
| 把 `WenShape` 的作者工作台完整迁入 | 可以借鉴 cards、profile、打包方式，但 LNE 不应变成传统作者写作软件 |
| 直接默认替换向量库 / reranker / GraphRAG | 真实 embedding + Zilliz + rerank 已能显式使用；默认替换 BM25 或接 GraphRAG/Zep 仍要先看真实 replay 收益 |
