# v0.6.1 — Multi-Agent Runner Protocol（设计 + 数据结构骨架）

> 状态：设计 + 协议骨架已落地（v0.6.1）；**v0.6.2 已实现 `multi_agent_stub` runner 消费本协议**（见 `orchestrator/runners/projection.py` + `multi_agent_stub.py`）。`lightweight` 仍是默认 runner。
> 前置：v0.6.0 Scene Runner Adapter（`SceneRunner` / `SceneRequest` / `dispatch_scene`）。
> 后续：v0.6.3+ 把 stub 的确定性 `build_demo_trace` 升级为真正多 Agent 推理；把 trace 接入 browse 可视化。

---

## 1. 目标

在 **不破坏现有输出契约** 的前提下，为多 Agent 推演定义一套「内部产物协议」，让未来的 runner 能表达轻量轮询表达不了的东西：

- **角色计划（AgentIntent）**：角色本回合想做什么、动机、目标对象、是否公开。
- **私下信息（PrivateKnowledge）**：只有部分角色知道的事实，不应泄漏到公开章节，除非显式 reveal。
- **误解（Misunderstanding）**：角色对某事件/某角色的错误认知，可被后续证据纠正。
- **延迟行动（DelayedAction）**：角色计划在未来某一回合（`due_round`）才执行的动作。
- **关系传播（RelationshipSignal）**：一次互动如何改变 A 对 B 的关系/态度，可链式影响第三方。
- **回合计划（AgentTurnPlan）**：单角色单回合的完整意图集合。
- **多 Agent 轨迹（MultiAgentTrace）**：整场推演的结构化记录，最终投影成 `AcceptedEvent` / `StateDelta` / `state_snapshot`。

这是「先定内部产物，再决定自研还是接外部框架」的一步：协议稳定后，自研 stub 与未来 MiroFish/OASIS 适配都可作为该协议的生产者。

## 2. 不做（本阶段刻意排除）

- 不接入任何外部服务 / 不引入新依赖（仅用已有 pydantic）。
- 不做 UI、不改 `lne browse`。
- 不改 `outputs/` 旧格式：`events.json` / `state_snapshot.json` / `chapter.md` 结构保持不变。
- 不改 `lightweight` runner 行为，不把协议接入 `dispatch_scene` 的默认路径。
- 不在本刀实现真正的多 Agent 推理循环（那是 v0.6.3+；v0.6.2 仅做 deterministic stub）。

## 3. 输出契约不变性（关键约束）

现有契约（v0.6.0 起）：

```text
SimulationResult
├── accepted_events: list[AcceptedEvent]   # 公开事件流，进 events.json，被 contract/retrieval/browser 读取
├── state_deltas: list[StateDelta]
├── state_snapshot: dict                    # 进 state_snapshot.json
├── chapter_text / summary_text
└── runner_name                             # v0.6.0 additive
```

多 Agent 协议是 runner 的 **内部中间产物**，只能：

1. **投影**为既有 `AcceptedEvent` / `StateDelta` / `state_snapshot`（公开层）。
2. 可选地把整条 `MultiAgentTrace` 以 **additive** 方式附在 `SimulationResult`（如未来加 `multi_agent_trace` 字段）或单独 artifact（如 `multi_agent_trace.json`），**不污染** `events.json` 既有键。

**私有/误解信息默认不进公开层**：只有 `revealed=True` 的条目才允许投影成公开 `AcceptedEvent`。这是「私下信息不泄漏」的硬规则，由投影函数（v0.6.2）执行，本阶段协议负责标记 `visibility` / `revealed`。

## 4. 数据结构（见 `orchestrator/runners/protocol.py`）

所有结构为 pydantic `BaseModel`，可 `model_dump()` / `model_validate()` 往返序列化。

### 4.1 可见性与枚举

```text
Visibility = "private" | "scene" | "public"
    private : 仅 owner（及 known_by 列出的角色）知道
    scene   : 在场角色可感知
    public  : 可进入公开章节/事件流
```

### 4.2 AgentIntent（角色意图）

| 字段 | 说明 |
|------|------|
| `actor_id` | 行动角色 |
| `intent_type` | 计划类型（如 plan/observe/deceive/protect/investigate） |
| `target` | 目标角色或对象（可空） |
| `motivation` | 动机（内部，不直接进正文） |
| `description` | 意图描述 |
| `visibility` | 默认 `private` |
| `confidence` | 0–1，角色对该计划的笃定度 |

### 4.3 PrivateKnowledge（私下信息）

| 字段 | 说明 |
|------|------|
| `fact_id` | 唯一标识 |
| `owner_id` | 谁掌握该信息 |
| `content` | 信息内容 |
| `known_by` | 还有谁知道（默认仅 owner） |
| `visibility` | 默认 `private` |
| `revealed` | 是否已公开（默认 False；仅 True 才允许投影成公开事件） |
| `source` | 信息来源（干预/观察/推断…） |

### 4.4 Misunderstanding（误解）

| 字段 | 说明 |
|------|------|
| `holder_id` | 持有误解的角色 |
| `about` | 误解针对的对象/事件 |
| `believed` | 角色相信的（错误）内容 |
| `reality` | 实际真相（内部对照，不进公开层除非 corrected+reveal） |
| `corrected` | 是否已被纠正（默认 False） |
| `visibility` | 默认 `private` |

### 4.5 DelayedAction（延迟行动）

| 字段 | 说明 |
|------|------|
| `actor_id` | 行动角色 |
| `action_type` | 动作类型 |
| `description` | 动作描述 |
| `created_round` | 计划生成的回合 |
| `due_round` | 计划执行的回合（须 ≥ created_round；`is_due(r)` 判定到期） |
| `executed` | 是否已执行（默认 False） |
| `visibility` | 默认 `private`，执行落地时可转 scene/public |

### 4.6 RelationshipSignal（关系传播）

| 字段 | 说明 |
|------|------|
| `from_id` | 关系发起方 |
| `to_id` | 关系指向方 |
| `change` | 关系变化描述（如 trust+/suspicion+） |
| `magnitude` | -1–1，变化强度与方向 |
| `propagated_from` | 若由其他信号链式触发，记录来源 signal_id（关系传播） |
| `visibility` | 默认 `scene` |

### 4.7 AgentTurnPlan（单角色单回合计划）

| 字段 | 说明 |
|------|------|
| `round_num` | 回合 |
| `actor_id` | 角色 |
| `intents` | `list[AgentIntent]` |
| `delayed_actions` | `list[DelayedAction]` |
| `relationship_signals` | `list[RelationshipSignal]` |

### 4.8 MultiAgentTrace（整场轨迹）

| 字段 | 说明 |
|------|------|
| `worldline_id` / `branch_seed` | 与 `SimulationResult` 对齐 |
| `turn_plans` | `list[AgentTurnPlan]` |
| `private_knowledge` | `list[PrivateKnowledge]` |
| `misunderstandings` | `list[Misunderstanding]` |
| 方法 | `public_intents()` / `pending_delayed_actions(round)` / `due_delayed_actions(round)` / `revealable_knowledge()` |

`revealable_knowledge()` 仅返回 `revealed=True` 的私下信息——这是 v0.6.2 投影函数过滤公开事件的依据。

## 5. 投影路线（v0.6.2 已实现：`projection.py`）

```text
MultiAgentTrace
  → 过滤 visibility/revealed/corrected
  → public AgentIntent / due DelayedAction / revealed PrivateKnowledge / corrected Misunderstanding
  → AcceptedEvent（公开事件流）
  → RelationshipSignal → StateDelta / state_snapshot.relationship_changes
  → narrator 渲染 chapter_text
  → SimulationResult（契约不变；trace 可选 additive 落 multi_agent_trace.json）
```

## 6. 验收（本刀）

- 协议数据结构可序列化/反序列化往返一致。
- `DelayedAction.due_round` 能表达未来回合，`is_due()` 正确。
- 私下信息 / 误解默认 `visibility=private` 且 `revealed/corrected=False`，`revealable_knowledge()` 不返回未 reveal 项。
- `lightweight` runner 与 v0.6.0 既有 218 测试不回归（协议未接入默认路径）。
