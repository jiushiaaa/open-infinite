## v0.8 当前产物边界

v0.8 已形成一条完整的“长篇记忆 + 行动规划 + 质量/涌现审计”artifact 链：

```text
import long novel
  -> source_raw/
  -> import_report.json
  -> memory/
     -> memory_manifest.json
     -> canon_ledger.jsonl
     -> consistency_report.json
  -> retrieval_context.json（canon_ledger source）

intervene
  -> act_director_plan.json
  -> dynamic_action_registry.yaml
  -> branch_*/narrative_diagnostics.json
  -> branch_*/worldline_judgement.json（按需生成）
  -> emergence_nodes.json
```

这些新增产物全部是 additive：不改变 `run_scene` 默认行为，不破坏 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 的既有契约。

## 下一步建议

如果继续 v0.8.x，优先级建议如下：

1. `entity_aliases.yaml` + entity resolution：这是让长篇记忆、动作注册表和检索不碎裂的最小公共层。
2. 前端 v0.8 artifact 面板：让用户看见导入报告、一致性审计、动作计划和涌现节点，提升产品可解释性。
3. runner consumption 第一刀：只让 runner 读取 `act_director_plan` 中低风险动作的 preconditions/effects，不做复杂执行器。
4. 长篇上传产品化：分片上传、断点续传、epub/zip 解析和任务进度。

暂不建议立刻做 Zep / OASIS / CAMEL / LangGraph 替换主线。当前更高价值的是把 v0.8 已沉淀的 artifact 变成可解释、可消费、可验证的下一轮运行输入。
