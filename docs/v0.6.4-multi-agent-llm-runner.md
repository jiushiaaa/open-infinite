# v0.6.4 — `multi_agent_llm` runner（小模型多 Agent 推演）

> 状态：已实现（v0.6.4）。把 v0.6.2 stub 的确定性 `build_demo_trace` 升级为**真正的 LLM 推演**。
> 前置：v0.6.0 Scene Runner Adapter、v0.6.1 协议、v0.6.2 投影层（`projection.py`）、v0.6.3 trace 可视化。
> 定位：**非默认** runner，`lightweight` 仍是默认；经显式 `runner_name` 或 `LNE_SCENE_RUNNER=multi_agent_llm` 启用。

---

## 1. 目标

让一个 OpenAI-compatible 的小模型一次性推演整场 `MultiAgentTrace`（角色计划 / 私下信息 /
误解 / 延迟行动 / 关系信号），再复用既有投影层与 narrator 渲染，产出与 `lightweight` 同构的
`SimulationResult`。这是「stub → 真实推理」的关键一刀：**生产**（怎么得到 trace）与
**装配**（trace → 契约对象）彻底解耦。

## 2. 不做（本阶段刻意排除）

- 不本地部署模型、不引入新依赖（复用现有 `LLMClient.chat_json`，OpenAI SDK 兼容）。
- 不接 Zep / OASIS / CAMEL / LangGraph（按 §memory 触发条件留到 v0.8+ 评估）。
- 不改 `outputs/` 旧格式与 `lightweight` 行为；不进入 `dispatch_scene` 默认路径。
- 不做并发 / 重试 / 成本控制 / trace 质量评估（那是 v0.6.5）。

## 3. 架构

```text
SceneRequest
  → generate_trace(request)
       ├─ mock / 无 API key / 不可用      → build_demo_trace（确定性，source="fallback"）
       ├─ LLM 调用或解析/校验失败          → build_demo_trace（不抛，source="fallback"）
       └─ 成功                            → _sanitize_trace(LLM trace)（source="llm"）
  → build_result_from_trace（共享装配层 assembly.py）
       → project_trace（公开层硬过滤：仅 public 意图 / revealed 私下信息 / corrected 误解 / 到期延迟行动）
       → apply_relationship_signals
       → build_state_snapshot + render_chapter
  → SimulationResult（契约不变；additive 附 multi_agent_trace）
```

- **共享装配层** `orchestrator/runners/assembly.py`：`build_result_from_trace` 由 stub 与 llm 两个
  runner 共用，消除重复，保证两种 runner 输出严格同构。
- **投影层** `projection.py` 原样复用——公开/私有的硬规则在投影层执行，runner 不重复实现。

## 4. 隐私加固（关键安全约束）

LLM 可能乱标 `visibility`，因此 LLM 产出先过 `_sanitize_trace` 再进投影：

- 补齐 `worldline_id` / `branch_seed`（缺失时用 `spec`）。
- **未 `revealed` 的私下信息**强制 `visibility=private`。
- **未 `corrected` 的误解**强制 `visibility=private`。
- **暗算/隐瞒类意图**（conceal/deceive/scheme/plot/hide/betray/spy）即便被标 `public` 也降级为 `private`。
- 延迟行动 `due_round < created_round` 时归一化为 `created_round`。

加固之后再交给投影层做公开层过滤——即使模型试图把私下低语标成 public，也不会泄漏到
`events.json` / 正文。系统提示词另外要求模型**把读者干预内容放进目标角色的 private_knowledge**，
而非任何 public 意图。

## 5. 健壮回退

`generate_trace` 返回 `(trace, source)`，`source ∈ {"llm", "fallback"}`：

- mock（`LNE_MOCK=1`）或 LLM 不可用（无 API key）→ 直接回退确定性 trace；保证 demo / 测试在无
  API 环境下仍跑通，行为与 `multi_agent_stub` 一致。
- LLM 调用异常、JSON 非法、pydantic 校验失败、`turn_plans` 为空 → 记 warning 并回退，**绝不抛**。

## 6. 用法

```bash
# 配置 .env：LLM_API_KEY / LLM_BASE_URL / LLM_MODEL_NAME（示例 DashScope qwen-plus）
LNE_SCENE_RUNNER=multi_agent_llm lne intervene tianhuang-night \
  --target lin_wan_zhou --content "今晚不要去城外竹林"

# 无 API key 或加 --mock 时自动回退到确定性 trace，仍产出可浏览的 multi_agent_trace.json
LNE_SCENE_RUNNER=multi_agent_llm lne intervene tianhuang-night \
  --target lin_wan_zhou --content "今晚不要去城外竹林" --mock
```

生成的 `multi_agent_trace.json` 可直接用 v0.6.3 的 `lne browse`「Agent 轨迹」标签页查看。

## 7. 验收

- `multi_agent_llm` 注册为非默认 runner，默认仍 `lightweight`。
- mock / 无 API → 回退确定性 trace，契约不变，`multi_agent_trace` 非空。
- FakeLLM 走真实路径时 trace 被消费并投影；隐私加固使私下信息/暗算意图/未纠正误解不进公开层。
- LLM 异常 / 空 turn_plans 回退不抛。
- `lightweight` 与既有 245 测试零回归（全量 254 passed）。
