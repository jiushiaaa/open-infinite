# 论文研读报告：STORY2GAME

> 原文：`docs/article/2505.03547v1.pdf`  
> 标题：STORY2GAME: Generating (Almost) Everything in an Interactive Fiction Game  
> 作者机构：Georgia Institute of Technology  
> 主题关键词：interactive fiction、action generation、preconditions/effects、game state、dynamic actions

## 1. 一句话概括

这篇论文提出了一个对 LNE 非常关键的思路：**不要让玩家/读者的自由行动漂浮在文本里，而要把行动翻译成带 preconditions 和 effects 的状态变更，让开放输入仍然被世界状态约束。**

## 2. 论文大概讲了什么

STORY2GAME 研究如何从一个故事生成一个可玩的文字冒险游戏。

它的流程大致是：

```text
生成故事
  -> 从故事中抽取动作
  -> 为动作生成 preconditions 和 effects
  -> 生成游戏世界图
  -> 生成可执行动作代码
  -> 玩家游玩时动态生成新动作
```

论文指出，如果游戏只有固定动作集合，故事生成会被动作集合限制；但如果完全放开玩家输入，游戏又会失去世界逻辑，玩家可能做出任何不合理行为。

因此 STORY2GAME 的解决方案是：为每个行动生成前置条件和效果，让动作能被游戏状态执行、检查、拒绝或修改。

## 3. 核心机制

### 3.1 Preconditions

Preconditions 是一个行动能够执行前必须满足的条件。

例如：

```text
玩家要打开宝箱
  -> 玩家必须在宝箱所在房间
  -> 宝箱必须存在
  -> 玩家可能需要钥匙
```

对 LNE 来说，这对应：

```text
角色想御剑飞行
  -> 角色必须达到筑基境
  -> 必须拥有飞剑
  -> 当前地点不能被禁空阵封锁
```

### 3.2 Effects

Effects 是行动执行后对世界状态的改变。

例如：

```text
打开宝箱
  -> 宝箱状态变为 opened
  -> 玩家获得玉简
  -> 触发守卫警觉
```

对 LNE 来说，effects 可以直接转成 `StateDelta` 和 `AcceptedEvent`。

### 3.3 Dynamic Action Generation

玩家可能输入故事中没有预设的动作。STORY2GAME 会动态生成这个新动作的条件和效果，并可能创建新物品、新属性、新前置行动。

例如玩家说：

```text
Distract the guard
```

系统要判断：

- 谁是 guard。
- guard 在哪里。
- distracted 属性是否需要新增。
- 是否需要前置事件。
- 执行后会影响哪些既有动作。

这和 LNE 的“读者神谕 / 角色动作”高度相关。

## 4. 评估结果

论文用 GPT-4o-mini 做实验，将故事按动作长度分组。论文报告的 action generation 编译成功率较高：

| 故事长度 | 句子编译成功率 | 全故事编译成功率 |
| --- | --- | --- |
| 5-7 actions | 0.972 | 0.875 |
| 8-10 actions | 0.937 | 0.75 |
| 11-13 actions | 0.928 | 0.625 |
| 14+ actions | 0.942 | 0.75 |

主要失败原因是 LLM 对对象识别不稳定，比如同一把钥匙一会儿叫 `Key`，一会儿叫 `Metallic Key`，导致系统不知道是否是同一对象。

这对 LNE 很有提醒意义：角色、物品、地点必须有稳定 ID，不能只靠自然语言名称。

## 5. 对未终章的参考意义

这篇论文对 LNE 的 v0.7.2 价值非常高。

我们已经规划了：

```text
CharacterAction
CharacterProbe
InterventionGuardrail
```

STORY2GAME 可以进一步提醒我们：`CharacterAction` 不能只是一个动词，还应有：

```text
preconditions
effects
state_refs
failure_reason
repair_suggestions
```

### 5.1 CharacterAction 应带 preconditions/effects

建议数据结构：

```json
{
  "action_id": "act_001",
  "character_id": "lin_wan_zhou",
  "action": "investigate",
  "target": "bamboo_forest",
  "preconditions": [
    "lin_wan_zhou.location == mountain_gate",
    "lin_wan_zhou.has_item(retreat_soul_bell)",
    "bamboo_forest.status != inaccessible"
  ],
  "effects": [
    "thread.trap_exposed += 0.4",
    "lin_wan_zhou.suspicion += 0.3",
    "mo_qing_yan.alertness += 0.2"
  ],
  "on_failure": "downgrade_to_observe"
}
```

### 5.2 干预护栏可以用 precondition 解释拒绝

用户输入：

```text
让林凡立刻御剑飞到竹林救人。
```

系统不应该只说“违反规则”，而应该给出：

```text
失败原因：
- 林凡当前境界不足。
- 他没有飞剑。
- 他不知道竹林具体位置。

可降级：
- 他可以用传讯玉简示警。
- 他可以找玄机道人求助。
- 他可以派楚明去拖延时间。
```

这会让“拒绝用户命令”变得更像世界规则，而不是系统冷冰冰地拦截。

### 5.3 动态动作生成可服务读者干预

读者可能提出系统没有预设的变量：

```text
让城中突然流传一首童谣，暗示竹林有鬼。
```

LNE 可以动态生成一个 action：

```text
spread_rumor
```

并赋予：

- preconditions：有人愿意传播、谣言有传播路径。
- effects：民众恐惧、反派警觉、目标角色怀疑。
- risks：可能让敌人提前收网。

## 6. 局限性

STORY2GAME 主要面向文本冒险游戏，不是长篇小说。

局限：

- 世界状态偏游戏对象图，不处理文学章节、情绪节奏、人物弧光。
- 动作生成关注可执行性，不关注网文可读性。
- 实验故事长度较短。
- 动态动作会带来状态表示膨胀和对象识别问题。
- 不处理读者作为高维干预者和角色反抗的问题。

## 9. 最终判断

这篇论文对 LNE **非常有参考意义**，尤其是 v0.7.2。

它给了我们一个很实用的工程原则：

> 开放输入不能直接变成正文，必须先变成可检查、可执行、可失败、可降级的动作。

这正好可以补强 LNE 的 `CharacterAction` 和 `InterventionGuardrail`，让“读者干预世界”既自由，又不失去世界规则。
