# v0.2 Import Novel — 最小闭环设计

> 版本：2026-05-28  
> 状态：设计稿（待实现）  
> 前置：v0.1.3 已收口（`intervene` → `resume continue` → `resume intervene`）

## 1. 目标

让用户上传 **3–10 章** 自己的 `txt` / `md`，经 LLM 抽取世界锚定文件，人工微调后，**复用现有** `lne intervene` / `resume` 链路——不再依赖内置《天荒城残夜》。

**本阶段不做**：网页抓取、卷级管理 UI、facts.jsonl 全量检索、MiroFish 接入、世界线 Web 浏览器。

## 2. 成功标准（v0.2.0 MVP）

| # | 标准 |
| --- | --- |
| 1 | `lne import-novel ./chapters/ --name my-story` 生成 `projects/my-story/` |
| 2 | 目录内至少含可编辑的 `world.yaml`、`characters.yaml`、`canon_chapter.md`、`anchor_proposal.yaml` |
| 3 | 抽取结果含 ≥3 角色、≥2 地点、≥3 条 `rules`、≥2 条 `open_threads` |
| 4 | 用户改 YAML 后，`lne intervene my-story ...` 与内置样例行为一致（三分叉 + 合约审计） |
| 5 | `LNE_MOCK=1` 下整条导入 + intervene 可 pytest，不依赖 API Key |
| 6 | 导入失败时保留 `source/` 原文与 `import_log.json`，错误可读 |

**v0.2.0 可延后**：从 `projects/` 跑 `resume continue` / `resume intervene`（v0.2.1）；`facts.jsonl` / 章节 summaries（v0.2.1）。

## 3. 命令面

```bash
# 导入：目录（每文件一章）或单文件（自动拆分）
lne import-novel ./my_chapters/ --name my-story
lne import-novel ./novel.md --name my-story --genre xianxia

# 查看与校验
lne list-projects
lne show-project my-story          # 摘要：角色数、规则数、干预章标题
lne validate-project my-story      # YAML/schema + 必填字段

# 复用现有链路（world id = project slug）
lne intervene my-story --target <char_id> --content "..." --mock
lne compare outputs/run_...
# resume 在 v0.2.1 明确支持 projects；v0.2.0 可先要求 copy 到 samples 或统一 loader
```

### 3.1 `import-novel` 参数（建议）

| 参数 | 说明 |
| --- | --- |
| `path` | 章节目录或合并文本文件 |
| `--name` / `-n` | 项目 slug（`[a-z0-9-]+`） |
| `--anchor` | 干预锚定章：默认最后一章；可 `last` / `3` / `chapter_003` |
| `--genre` | 题材提示（默认 `xianxia`，写入 style 草案） |
| `--mock` | 使用固定抽取模板，不调 LLM |
| `--max-chapters` | 上限 10，默认 10 |

## 4. 目录结构

**原则**：`projects/<slug>/` 在干预运行时与 `samples/<slug>/` **同构**，最大化复用 `load_sample` 逻辑。

```text
engine/
├── samples/                    # 内置样例（不变）
│   └── tianhuang-night/
└── projects/                   # 用户导入（gitignore 推荐）
    └── my-story/
        ├── source/             # 原文备份（只读参考）
        │   ├── chapter_001.md
        │   └── chapter_002.md
        ├── world.yaml          # StoryWorld 源
        ├── characters.yaml
        ├── open_threads.yaml   # 可选，或并入 world.yaml
        ├── canon_chapter.md    # 干预锚定章全文
        ├── prologue.md         # 可选：前几章压缩摘要或首章节选
        ├── canon_opening.md    # 可选：开篇节选
        ├── anchor_proposal.yaml # LLM 草案 + 置信度，供人工对照
        ├── import_meta.json    # 导入时间、模型、章节数、warnings
        └── style_hint.md       # 可选：文风约束（v0.2.0 轻量）
```

### 4.1 与内置样例字段对齐

`world.yaml` 必须能喂给现有 `StoryWorld`：

- `id`, `title`, `display_name`, `canonical_place_name`
- `source_type: imported`（区分 builtin）
- `rules[]`, `locations[]`, `factions[]`, `timeline[]`
- `divergence_point`, `scene_description`（干预节点场景描写）
- `worldline_policy`（默认 `branch_on_major_intervention`）

`characters.yaml` 必须能喂给 `CharacterAgent`：

- 至少 1 个 `present_in_scene: true` 的可干预角色
- `id` 稳定英文 snake_case（LLM 生成 + 人工可改）
- `persona`, `memory`, `relationships`, `current_state`（location / emotion / resources）

`canon_chapter.md` = 用户指定的干预锚定章 **原文**（不删减），保证叙事承接与 v0.1 一致。

## 5. 流水线

```text
┌─────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ Chapter     │ -> │ Import Extractor │ -> │ anchor_proposal   │
│ Splitter    │    │ (LLM or mock)    │    │ .yaml + 各 YAML   │
└─────────────┘    └──────────────────┘    └────────┬────────┘
                                                     │
                     ┌───────────────────────────────┘
                     v
              ┌──────────────┐    ┌──────────────────┐
              │ 用户编辑 YAML │ -> │ validate-project │
              └──────────────┘    └────────┬─────────┘
                                         v
                              ┌────────────────────┐
                              │ intervene / resume │
                              │ （现有 orchestrator）│
                              └────────────────────┘
```

### 5.1 Chapter Splitter

- **目录模式**：按文件名排序；支持 `001_标题.md`、`chapter-1.txt`
- **单文件模式**：正则拆章（`第[一二三四五六七八九十百千0-9]+章`、`Chapter \d+` 等），拆失败则报错并保留原文到 `source/merged.md`
- 章节数不在 3–10：警告或 `--force`（默认拒绝）

### 5.2 Import Extractor（单次 LLM 或分步）

**v0.2.0 推荐：两次调用**

1. **World pass**：规则、地点、势力、时间线、干预场景 `scene_description`、`divergence_point`
2. **Character pass**：角色卡、关系、当前状态、开放伏笔 `open_threads`

输入 token 控制：

- 每章截断摘要（首 800 + 尾 400 字）送入抽取
- **完整原文**只写入 `source/` 与 `canon_chapter.md`（锚定章全文）

**Mock 路径**：从 `resources/import_mock_template.yaml` 生成结构合法但内容泛化的占位，保证 CI 不依赖 Key。

### 5.3 anchor_proposal.yaml

供人工对照，**不**参与运行时加载：

```yaml
extraction_version: "0.1"
confidence: medium
warnings:
  - "未明确战力体系，已留空 rules 扩展位"
protagonist_candidates: [lin_xxx]
intervention_hints:
  - "建议在林晚舟出门前干预"
suggested_targets:
  - id: lin_xxx
    reason: "场景内可接收 whisper"
raw_notes: "..."
```

### 5.4 人工编辑检查清单

- [ ] 角色 `id` 无中文、无重复
- [ ] `rules` 含禁止 OOC / 禁止未声明金手指类约束（可抄天荒城模板句）
- [ ] `scene_description` 与 `canon_chapter.md` 末尾局势一致
- [ ] 至少一个 `present_in_scene: true` 且 `current_state.location` 合理
- [ ] `validate-project` 通过

## 6. 代码改动（最小侵入）

| 模块 | 改动 |
| --- | --- |
| `samples/loader.py` | 抽成 `StoryBundleLoader`：`load_story(slug)` 先查 `projects/` 再查 `samples/` |
| `cli.py` | 新增 `import-novel`, `list-projects`, `show-project`, `validate-project` |
| `import/`（新包） | `splitter.py`, `extractor.py`, `writer.py`, `schemas.py` |
| `orchestrator/` | **不改** 分叉逻辑；仅 world 来源从 builtin → imported |
| `tests/` | `test_import_mock.py`, `test_validate_project.py`, `test_intervene_imported_project.py` |

### 6.1 Loader 统一接口

```python
@dataclass
class StoryBundle:  # 原 SampleBundle 改名或别名
    slug: str
    source_kind: Literal["builtin", "imported"]
    world: StoryWorld
    characters: list[CharacterAgent]
    canon_chapter: str
    ...
```

`lne intervene <slug>` 对 CLI 无感：slug 在 `samples` 或 `projects` 均可。

### 6.2 环境变量

| 变量 | 说明 |
| --- | --- |
| `LNE_PROJECTS_DIR` | 默认 `engine/projects` |
| `LNE_IMPORT_MAX_CHAPTERS` | 默认 10 |
| 现有 `LLM_*` / `LNE_MOCK` | 抽取与 intervene 共用 |

## 8. 风险与边界

| 风险 | 应对 |
| --- | --- |
| 抽取漏角色/规则 | `anchor_proposal.yaml` + `validate-project` + 文档检查清单 |
| 章节拆分失败 | 要求用户提供目录模式；单文件失败时明确报错 |
| 版权 | 文档声明：仅本地个人使用；`projects/` 建议 gitignore |
| 与 resume 衔接 | v0.2.1：`meta.json` 增加 `project_slug`；loader 读 projects |
| 过长上下文 | 抽取用摘要，叙事用 `canon_chapter` 全文 + 现有 `canon_context_for_narrator` 截断 |

## 9. 实施顺序（建议 3 PR）

1. **PR-A**：`splitter` + `projects/` 写入 + `validate-project` + mock 抽取
2. **PR-B**：统一 `load_story` + `intervene` 读 projects
3. **PR-C**：真实 LLM 抽取 prompt 调优 + 文档样例 + `resume` 支持 projects（可拆 v0.2.1）
