# v1.0-beta Project Retention Policy-J 收口说明

> 日期：2026-06-01
> 范围：本地项目删除/保留策略 artifact 与 API
> 代码入口：`get_project_retention_policy()`、`write_project_retention_policy()`、`GET/POST /api/stories/<slug>/retention-policy`

## 1. 收口目标

本刀承接 Cloud Persistence Boundary-G 与 Audit Log Append Policy-I 的后续建议：先把项目原文、生成产物、holdout 私有集、审计日志和分片的保留策略沉淀为本地 artifact，再决定是否进入对象存储、数据库或真实删除流程。

## 2. 已完成

- 新增 `living_novel_engine.service.project_retention_policy.get_project_retention_policy()`。
- 新增 `living_novel_engine.service.project_retention_policy.write_project_retention_policy()`。
- 新增 `GET/POST /api/stories/<slug>/retention-policy`。
- 本地写入 `memory/project_retention_policy.json`，字段覆盖：
  - `project_retention`
  - `uploaded_source_retention`
  - `generated_artifact_retention`
  - `holdout_retention`
  - `audit_log_retention`
  - `ingest_chunk_retention`
  - `deletion_confirmation_required`
  - `notes`
- 写入策略会追加 `retention_policy_reviewed` 审计事件到 `memory/project_audit_log.jsonl`。
- 坏 slug 返回 400，缺项目返回 404，内置样例只读返回 409。
- 策略文本会拒绝疑似密钥内容，不暴露绝对路径或环境变量名。

## 3. 未做

- 不实际删除项目目录、上传原文、生成产物、holdout 或审计日志。
- 不接对象存储、数据库、持久队列、真实账号、团队空间或请求级 ACL。
- 不做跨设备同步、云端备份或自动清理。
- 不改 `run_scene` 默认行为，不改变既有 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 契约。
