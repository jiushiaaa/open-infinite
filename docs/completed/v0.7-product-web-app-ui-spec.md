## 0.0 v0.9.1 Provider Gateway Summary-A 增量（已收口）

运行设置层新增 provider/cost 摘要，为后续设置页可视化和成本聚合提供只读数据源。

- 新增 API（additive）：
  - `GET /api/settings/providers`：返回 `version`、`routing`、`providers`、`cost_policy` 和 `warnings`。
- 数据边界：
  - `providers` 当前包含主文本模型与 Seedream 视觉模型，只返回脱敏尾号、base_url、model、active/configured、fallback 与 usage 来源。
  - `routing.mode=single_provider`；未配置文本密钥或默认 mock 时走 mock，视觉模型未配置/关闭时走占位图。
  - `cost_policy` 当前只声明 token usage 来源，不内置真实价格表。
- UI 边界：
  - 本子刀尚未新增前端面板；后续可在设置抽屉或系统状态区展示。
  - 不打网络、不落盘、不返回明文 Key 或环境变量名。

## 0.0 v0.9.0-alpha Chapter Export 增量（已收口）

在阅读工作台上新增一个轻量闭环动作：用户选中世界线后，可直接导出当前章节 Markdown。

- 新增 API（additive）：
  - `GET /api/runs/<run_id>/branches/<branch_id>/chapter-export`：返回 `filename`、`content_type`、`content_md` 与 `metadata`；坏 id 400，缺章节 404。
- UI 露出：
  - `ChapterReader` 顶部新增「导出章节」按钮。
  - 导出成功/失败均在阅读区局部显示中文状态，不影响章节阅读或右侧机制档案。
- 边界：
  - 导出内容包含来源说明、AI 生成说明、世界线评审摘要和当前章节正文。
  - 不写回 `chapter.md`，不改 `run_scene` 默认行为，不导出上传原作全文或 holdout 私有正文。

## 0.0.0 v0.9.0-alpha Chapter Collection Export 增量（已收口）

在阅读工作台新增「导出合集」按钮，把当前世界线父链上的生成章节合成一个 Markdown 文件。

- 新增 API（additive）：
  - `GET /api/runs/<run_id>/branches/<branch_id>/chapter-collection-export`：沿 `meta.parent_run_id` / `meta.parent_branch` 回溯父链，返回合集 `filename`、`content_md`、`chapter_count`、章节来源和 warning。
- UI 露出：
  - 阅读区按钮组包含「导出合集」和「导出章节」。
  - 合集导出成功后局部提示“共 N 节”，失败时只在阅读区显示中文错误。
- 边界：
  - 只导出生成章节，不导出上传原文或 holdout 私有正文。
  - 父链缺失时安全截断并返回 warning，不写 artifact、不驱动 runner。

## 0.0.0.7 v0.9.0-alpha Creation Loop Alpha Closeout Report 增量（已收口）

「创作闭环」在完成度之上新增正式收口报告，让用户看到 alpha 是否可收口、还剩哪些阻塞。

- API 行为：
  - `creation_loop.closeout` 返回 `kind`、`status`、`can_close_alpha`、`ready_count`、`required_count`、`remaining_blocker_ids`、`remaining_blockers`、`evidence`、`summary` 和 `next_step`。
  - `GET /api/stories/<slug>/creation-loop-closeout` 可直接返回 `completion_status`、`actions` 与该 closeout，用于自动验收和阻塞补齐；非法 slug 返回 400。
  - `worldline_judgement` action 携带 `story_slug` payload；`select_worldline` action 携带 `run_id`、`branch_id`、`note` payload；`run_replay_range` action 携带范围回放 payload。
  - `replay_audit` action 可携带 `requirements`，用于说明缺少 `selected_worldline`、`baseline_run`、`canon_holdout` 或需要 `review_replay_risk`。
  - 当 story 为 builtin 且缺少 holdout 时，`canon_holdout` requirement 的 `status` 为 `blocked`，detail 说明需导入长篇项目后再录入 holdout。
  - `closeout` 只从现有 checklist / completion / evidence 派生，不写 artifact。
- UI 露出：
  - `WorkspacePage` 在完成度下方展示「Alpha 收口」面板。
  - ready 时显示「可收口」，否则显示「待补齐」和最多三个阻塞项。
  - 当 action 返回 `requirements` 时，完成度区显示「审计前置」及最多三项中文前置条件，帮助用户理解为什么当前只能跳转审计页。
- 边界：
  - 不自动修改版本号，不进入公开分享发布，不改 runner。

## 0. v0.7.2 Agent Interaction 增量（已收口）

  - Agent 轨迹页新增结构化动作（前置条件/效果/失败原因/修正建议）只读展示；runner 暂未产出时空态正常。

## 0.1 v0.7.3 Visual Asset Generation 增量（已收口）

在文字主闭环之上叠加一层**视觉资产增强层**（Seedream 5.0 Lite），是增强而非核心依赖：未配置 Key / 生成失败 / 关闭开关时全程古风占位，不阻塞导入/创世/干预/浏览，不改既有契约。

- 新增 API（additive）：
  - `GET /api/stories/<slug>/visual-assets`：读取项目级视觉资产清单；缺/损坏 → `status=none` 占位，不 404。
  - `POST /api/stories/<slug>/visual-assets/generate`：生成 `kinds`（cover/characters/scenes）；`force=false` 不重复已 ready；`mock=true` 或无 Key → 占位、不打外网。
  - `GET /api/stories/<slug>/assets/<rel>`：本地资产静态服务，路径安全校验（穿越 403、缺失 404）。
- artifact：`projects/<slug>/visual_assets.json`（`VisualAssets`/`AssetEntry`，仅相对路径+元数据，不含二进制），图片落 `projects/<slug>/assets/`。
- UI 露出：
  - 世界锚定页左栏新增「视觉资产」区：故事封面（无图古风印记占位）+「生成视觉资产 / 重新生成」+ 状态文案。
  - 角色卡头像（无图取角色名首字纸面印记占位）。
  - 首页书架故事卡封面缩略（无图占位）。
  - 设置抽屉「视觉资产（Seedream）」区块：开关 + 密钥（不回显明文）+ 接口地址 + 模型名。
- 原则：中文文案、无英文占位词、无图布局稳定不塌陷不抖动、加载失败回退占位、生成中状态反馈。
- 边界：世界线节点缩略图仅预留 artifact 字段 + UI 占位（未绑定 run/branch 生成）；未做真实批量队列、图片版权/分享策略、真人复刻（明确不做）。下一步 v0.7.4 Baseline & Canon Replay。

## 0.2 v0.7.4 Baseline & Canon Replay 增量（已收口）

在文字主闭环之上叠加一层**评估层**（无干预基线 + 正史回放），是评估而非干预主链路依赖：全程不打 LLM、不改 `run_scene` 默认行为与既有契约，新 artifact 全部 additive，所有失败降级为明确错误（400/404/409），不白屏、不 500。

- 新增 API（additive）：
  - `POST /api/stories/<slug>/baseline`：生成无干预基线世界线（缺 `from_run_id`/`from_branch_id`→从锚定，有→从该快照续）；返回 `run_id`/`branch_id`/`story_slug`/`summary`/`report`/`tree`。坏 slug 400、缺故事 404。
  - `GET /api/runs/<run_id>/baseline`：读 `baseline_report.json`（不存在 404、损坏 400）。
  - `GET /api/stories/<slug>/canon/holdout`：读正史 holdout manifest（无 holdout → 空 manifest，不 404）。
  - `POST /api/stories/<slug>/canon/holdout`：录入正史章节（仅 imported/genesis；builtin 400、同章 force=false 409、空内容/非法章号 400；文件名由章号派生防穿越）。
  - `POST /api/stories/<slug>/canon/replay`：用基线续写章节与某章 holdout 做 deterministic 评估（无 baseline/holdout 404、损坏 400）。
  - `GET /api/runs/<run_id>/canon-replay`：读 `canon_replay_report.json`（不存在 404、损坏 400）。
- artifact：`outputs/<run_id>/baseline_report.json` + `outputs/<run_id>/baseline/`（chapter/events/state_snapshot/summary/baseline_meta，**不含 intervention.json/causal_diff.json**）；`projects/<slug>/canon/holdout/chapter_NNN.md` + `canon/holdout_manifest.json`；`outputs/<baseline_run_id>/canon_replay_report.json`（scores=lexical/entity/thread/length/state/overall + matched/missing_entities + matched_threads + warnings + interpretation）。
- UI 露出：世界锚定页左栏新增「基线与正史回放」区块——holdout 状态（builtin 只读提示 / imported 录入 textarea）、「生成无干预基线」、章节下拉 + 「运行正史回放」、基线摘要（自然发展/角色状态/触及伏笔）、回放评分条（总分 + 5 分项 + 解释 + 缺失实体/伏笔 + 警告）。
- 原则：中文文案、无英文占位、无 holdout 时空态不报错、builtin 只读、生成中状态反馈、不阻塞主流程；强调"基线不是原作，只是角色自然发展对照；正史回放仅用于本地评估，不代表复刻原作"。
- 边界：未做 baseline↔intervention 并排偏离对比 UI、run-detail 页持久化展示报告、LLM 语义评估、百万字 holdout、版权/公开分享策略。下一步 v0.7.5 Worldline Judge。

## 0.3 v0.7.5 Worldline Judge 增量（已收口）

在世界线阅读工作台之上新增**只读评审层**：读取既有 branch artifact，生成 `worldline_judgement.json`，帮助用户判断“哪条世界线值得继续”。该层不打 LLM、不改 `run_scene`、不写回正文或状态快照。

- 新增 API（additive）：
  - `POST /api/runs/<run_id>/branches/<branch_id>/worldline-judgement`：生成/覆盖某分支评审；body 可传 `story_slug`，缺省时从 run artifact 推断。坏 id 400、缺分支/正文 404、损坏 artifact 400。
  - `GET /api/runs/<run_id>/branches/<branch_id>/worldline-judgement`：读取分支评审；不存在 404、损坏 400。
- artifact：`outputs/<run_id>/<branch_id>/worldline_judgement.json`，包含 `recommendation`（推荐继续 / 谨慎继续 / 建议归档）、总分、维度分、故事弧、转折点、优势、警告、建议。
- 评分维度：角色一致性、合约风险、分支差异、叙事动量、情绪兑现、anti-slop、续写潜力、`emergence_score`、故事弧、转折点、张力。
- UI 露出：工作台右侧解释面板新增「世界线评审」标签页，展示总分、推荐、故事弧条、维度评分、优势/警告/建议/转折点，并提供「生成评审 / 重新评审」按钮。
- 原则：中文文案、无报告空态不报错、生成中状态反馈；强调“本地 deterministic 评分，不改正文、不写回世界状态”。
- 边界：未做 LLM 语义评审、run 级聚合评审、`compare.md` 汇总、`emergence_nodes.json` 持久化、discourse-aware narrator。

## 1. 设计目标

v0.7 的目标不是把 `lne browse` 美化一下，而是把 Living Novel Engine 从开发者 CLI 变成普通用户能进入的产品入口。

第一版 Web App 必须让用户完成这条闭环：

```text
进入产品
  -> 选择故事入口：内置样例 / 导入小说 / 主题创世
  -> 进入阅读工作台
  -> 在正文附近自由输入干预
  -> 系统解释“理解成了什么”
  -> 展示动态分支轴
  -> 生成世界线
  -> 以 Causal Diff 看见旧现实与新世界线的差异
  -> 选择继续、回滚或保留观察
```

核心体验不是“点选项”，而是：

```text
用户施加变量，世界根据合约、角色、人设、记忆和资源状态自行消化。
```

## 2. 不是这几个东西

v0.7 第一版明确不做：

- 不做完整作者工作台。
- 不做纯赛博控制台。
- 不做大面积营销首页。
- 不做复杂社区、登录、支付、公开发布。
- 不做 Seedream 视觉资产的强依赖；未配置时必须可用占位图。Seedream 已在 v0.7.3 收口为增强层（降级古风占位）。
- Causal Diff 的 accept / reject / revert artifact 状态写回已在 v0.7 第三刀补齐，但仍不做正文文本合并。
- 不把所有 engine 产物一股脑塞进 UI。只展示用户理解当前决策需要的信息。

## 4. 视觉方向

### 4.1 主气质

视觉关键词：

```text
中文小说阅读器 / 纸面书案 / 克制系统感 / 低噪声 / 可解释编辑器
```

推荐：

- 背景：暖白、宣纸、浅灰、淡墨纹理。
- 主色：墨黑、朱砂、玉青、深绿、低饱和金。
- 字体：正文优先中文阅读友好的宋体/仿宋/系统 serif；UI 控件可用系统 sans。
- 卡片：少量使用，半径克制，避免满屏 AI SaaS 卡片。
- 边框：细线、浅色、纸面分隔。

避免：

- 大面积紫蓝渐变。
- 霓虹、红屏、震屏、终端刷屏。
- 过多玻璃拟态、毛玻璃、浮夸发光。
- 把 Agent 轨迹做成赛博黑客控制台。

### 4.2 动效原则

动效要服务“因果变化被看见”，不是为了炫技。

允许：

- 施加干预后，正文局部短暂墨迹散开、淡出、重新凝聚。
- 新文本以轻量打字机方式出现。
- 世界线节点短暂重排或亮起。
- 右侧状态数值出现增量提示。

禁止：

- 强闪烁。
- 长时间遮挡阅读。
- 大面积红屏或震屏。
- 每次交互都播放强仪式感动画。

动效必须有降级：

- 用户设置中可关闭“强反馈动效”。
- 系统检测到 `prefers-reduced-motion` 时默认弱化。

## 5. 核心交互流程

### 5.1 三种故事入口

产品不应要求用户必须上传小说。

入口一：内置样例

- 用户点开即可体验。
- 推荐默认进入《天荒城残夜》或最新稳定 demo。
- 适合首次上手。

入口二：导入小说

- 支持 txt/md/zip/epub 文件导入；未选择文件时保留 3-10 章粘贴模式。
- 大文件先在浏览器端分片，再通过异步 job 导入；页面展示文件摘要、切片/导入进度和失败空态。
- 上传后进入世界锚定页。
- 明确提示版权责任和本地个人探索边界。

入口三：主题创世

- 用户输入题材、主角、大概冲突和想看的味道。
- AI 生成第一章、角色、世界规则、初始合约。
- 之后和导入项目走同一套 `intervene / resume` 链路。

### 5.2 自由干预

用户在正文附近输入自然语言，例如：

```text
我不希望沈砚进入书房，以免触发机关。
```

系统不能把它当作固定按钮，也不能直接强写进正文。必须先展示干预编译结果：

```text
系统理解：
  类型：forced_action
  目标：沈砚
  意图：阻止进入书房
  落地：门外异响 / 预感 / 他人阻拦 / 角色抗拒

世界观兼容性：
  compatible / medium risk

本次分支轴：
  主动改道
  被迫延迟
  抗拒命运压力
```

对于 AK47、系统、穿越者等规则改写型干预，UI 必须明确提示：

```text
这不是普通分支，而是 Alternate Novel / AU Worldline。
原世界线不会被静默污染。
```

### 5.3 动态分支轴

UI 不再固定呈现“相信 / 不信 / 半信半疑”。

分支轴来自 `intervention_compilation.json`：

- information：相信预知 / 怀疑但调查 / 拒绝预兆。
- forced_action：主动改道 / 被迫延迟 / 抗拒命运压力 / 干预失败但觉察异常。
- resource_injection：合理吸收 / 降级转译 / 拒绝 / 开启异设。
- rule_rewrite：拒绝 / 转译 / 另开 Alternate Novel。

目录仍可以是 `branch_a/b/c`，但 UI 文案必须用动态 label 和 outcome。

## 6. Causal Diff 交互

### 6.1 交互定位

Causal Diff 是“微观世界线编辑器”，不是代码 diff。

它回答用户最关心的问题：

```text
我刚刚那句话，到底改变了哪里？
```

### 6.2 展示结构

每个 `causal_diff.json` 的 block 建议渲染成：

```text
被抹去的旧现实
  微红底 / 朱砂细边 / 删除线可选 / 字色降低

新凝聚的世界线
  浅青或淡玉绿底 / 细边 / 新文本轻量打字出现

解释条
  影响角色 / 影响地点 / 分支轴 / lineage_type / 状态变化

操作区
  确立此界线
  抹除这次改写
  回滚到干预前
```

v0.7 第三刀已补齐 accept/reject/revert artifact 状态写回。按钮应使用真实 API，但仍需明确：

- 这只是记录世界线取舍，不合并或改写 `chapter.md`。
- 失败时显示错误，不要假装已保存。
- block 级或正文合并能力未实现时必须保留边界说明。

### 6.3 视觉规则

Diff 块不能太像 IDE，也不能太像错误提示。

建议：

- 红色用于“旧现实被抹去”，饱和度低。
- 绿色/青色用于“新世界线凝聚”，饱和度低。
- 文字仍保持小说阅读舒适度。
- 差异块周围保留足够留白，避免挤压正文。

## 7. 右侧解释面板

右侧面板不是调试垃圾桶，它是“命运解释器”。

建议四个标签：

| 标签 | 数据来源 | 用户价值 |
| --- | --- | --- |
| 状态 | `state_snapshot.json` | 角色现在怎么样 |
| 检索记忆 | `retrieval_context.json` | 引擎引用了哪些正史/合约/摘要 |
| 机制档案 | `runtime_memory_context.json`、`act_director_plan.json`、`dynamic_action_registry.yaml`、`narrative_diagnostics.json`、`emergence_nodes.json`、`runner_state_execution_report.json`、`state_execution_overlay.json` | 本章生成实际消费了哪些记忆层、动作计划如何落地、动作注册表沉淀了什么、正文叙事节奏如何、哪些节点值得后续发展、哪些低风险状态变化已写入可回滚 overlay |
| Agent 轨迹 | `multi_agent_trace.json` | 角色如何计划、误解、隐瞒、延迟行动 |
| 干预编译 | `intervention_compilation.json` + `causal_diff.json` | 系统如何理解用户输入 |

### 7.1 角色状态增量

当一次干预导致状态变化，UI 应展示增量：

```text
好感 +30 (↑ +5)
心境：警惕 -> 平静
位置：书房门外 -> 天井
第四面墙：suspicious -> aware
```

v0.7 第一版如果没有前后快照 diff，可以先展示当前状态；但组件接口要预留 `previous` 与 `delta`。

### 7.2 第四面墙提示

第四面墙触发时可以高亮，但要克制：

- 正文中相关句子用局部朱砂色。
- 右侧 Agent 轨迹显示一条短 warning。
- 不使用夸张英文终端刷屏。
- 不常驻红色警报。

推荐文案：

```text
角色觉察上升：检测到异常叙事压力。
```

不推荐：

```text
[DANGER!!!] AGENT DETECTED NARRATIVE TAMPERING!!!
```

## 8. 世界线树

世界线树要同时表达宏观和微观。

宏观：

- 正史节点。
- 干预节点。
- resume continue 的 linear 节点。
- resume intervene 的新分叉。
- orphan / broken lineage 降级展示。

微观：

- 节点角标显示是否有检索记忆、运行记忆、Agent 轨迹、Causal Diff。
- 分支节点显示动态分支 label，而不是只显示 branch_a。
- Alternate Novel 节点必须有特殊标记，但不要视觉上像错误。

## 12. 给 Cursor / Claude 的实现口径

实现时请遵守：

1. 先做产品级骨架，不追求一次性做完所有炫酷动效。
2. 保持古风纸面 + 编辑器感，不做纯赛博。
3. 所有红色 warning 都要克制。
4. Causal Diff 是第一版核心展示，不要跳过。
5. 不要把 UI 绑死成“相信 / 不信 / 半信半疑”。
6. `branch_a/b/c` 是目录 ID，不是用户看到的分支名。
7. 任何新 API 都必须 additive，不破坏 `lne browse`。
8. 不要重写 engine 核心推演逻辑。
9. 缺文件、坏 JSON、无 API key 都必须有降级。
10. 视觉资产生成放到 v0.7.3，不要阻塞 v0.7 主链路。
