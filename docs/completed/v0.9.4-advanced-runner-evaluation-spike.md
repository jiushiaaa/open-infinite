# v0.9.4 Advanced Runner Evaluation Spike 收口说明

> 收口日期：2026-06-01

## 目标

v0.9.4 的目标不是接入 LangGraph、OASIS 或 CAMEL，而是先判断当前自研 runner、`multi_agent_trace` 与状态执行 overlay 是否真的暴露高级 runner 缺口：

```text
触发条件复核 -> 代表性 runner probe -> 失败样例收集 -> 是否进入高级 runner spike
```

## 已完成范围

- Trigger-A：新增只读 `evaluate_advanced_runner_trigger()` 与 `GET /api/runs/<run_id>/advanced-runner-evaluation`：
  - 读取 `runner_state_execution_report.json`、分支 `multi_agent_trace.json` 与 `emergence_nodes.json`。
  - 返回 `not_triggered` / `insufficient_data` / `triggered`、状态执行 backlog、trace warning、私域复杂度、high-value emergence、触发原因和中文下一步。
- Probe-B：新增只读 `evaluate_advanced_runner_probes()` 与 `GET /api/runs/<run_id>/advanced-runner-probes`：
  - 把状态执行候选、trace 质量、涌现节点拆成可复现 probe。
  - 返回 `pass` / `weak` / `insufficient_data`、命中数、失败样例和中文建议。
  - 对复杂 run 收集 `state_execution_backlog`、`trace_repair_warnings`、`high_value_emergence` 等失败样例。

## 边界

- 不接 LangGraph、OASIS 或 CAMEL。
- 不写新 run artifact，不替换现有 runner，不改变 `run_scene` 默认行为。
- 不破坏既有 artifact 契约：`chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json`。
- HTTP run_id 必须走安全校验；非法 run_id 返回 400，缺 run 返回 404。

## 结论

当前 v0.9.4 只完成评估与证据收集层，不触发 LangGraph、OASIS 或 CAMEL 接入。只要代表性复杂 run 仍能被当前 `SceneRunner`、`multi_agent_trace`、状态执行 dry-run 与 overlay 解释清楚，就继续保持自研 runner。后续只有在真实复杂状态流转中积累明确失败样例，并证明修复现有 trace/状态执行层后仍不足时，才进入高级 runner 实现 spike。
