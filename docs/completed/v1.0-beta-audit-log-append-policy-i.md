# v1.0-beta Audit Log Append Policy-I 收口说明

> 日期：2026-06-01
> 范围：本地项目审计日志白名单追加策略
> 代码入口：`append_project_audit_log_event()`、`POST /api/stories/<slug>/audit-log/events`

## 1. 收口目标

本刀承接 Commercial Audit Log Schema-B 的 “future append” 口径：在不接账号、不接云端不可篡改审计存储的前提下，先提供一个可验证、可回滚的本地 JSONL 追加写入口。

## 2. 已完成

- 新增 `living_novel_engine.service.commercial_audit_log.append_project_audit_log_event()`。
- 新增 `POST /api/stories/<slug>/audit-log/events`。
- 写入位置固定为 `memory/project_audit_log.jsonl`，采用追加 JSONL，不覆盖既有 artifact。
- 只允许白名单动作：`manual_note`、`rights_reviewed`、`retention_policy_reviewed`、`project_space_reviewed`、`audit_reviewed`。
- 校验 `severity` 与 `actor_type`，坏 payload 返回 400；缺项目返回 404；内置样例只读返回 409。
- `metadata` 会丢弃疑似密钥字段或密钥值，并在响应 `warnings` 中说明。
- `GET /api/stories/<slug>/audit-log` 继续聚合追加后的 JSONL 行。
- 权限矩阵草案同步将审计日志资源更新为 `read + append`，但仍 `enforcement.mode=not_enforced`。

## 3. 未做

- 不接真实账号、团队空间、认证 provider 或请求级 ACL。
- 不接云端不可篡改审计存储、对象存储、数据库或队列。
- 不自动为所有写操作补审计，只提供 opt-in 本地追加入口。
- 不改 `run_scene` 默认行为，不改变既有 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 契约。
