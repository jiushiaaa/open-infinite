# v1.0-beta State Execution Audit Hook-N 收口说明

> 日期：2026-06-01
> 范围：状态执行 overlay apply/rollback 写操作接入本地审计日志
> 代码入口：`apply_runner_state_execution()`、`rollback_runner_state_execution()`、`memory/project_audit_log.jsonl`

## 1. 收口目标

本刀延续关键写操作审计接入，把 v0.8.10-B 的状态执行覆盖层应用与回滚纳入本地项目审计日志。这样长篇项目不仅能解释状态 overlay 的报告，也能在项目级审计时间线里追踪“何时应用、何时回滚”。

## 2. 已完成

- `apply_runner_state_execution()` 成功写入 `runner_state_execution_apply_report.json` 后，会追加 `state_execution_applied` 审计事件。
- `rollback_runner_state_execution()` 成功写入 `runner_state_execution_rollback_report.json` 后，会追加 `state_execution_rolled_back` 审计事件。
- 审计事件写入导入项目的 `memory/project_audit_log.jsonl`，并记录 `run_id`、`applied_count`、`overlay_count` 或 `removed_overlay_count`。
- `GET /api/stories/<slug>/audit-log` 会继续聚合这些事件。
- 审计追加白名单新增 `state_execution_applied` 与 `state_execution_rolled_back`。
- builtin 样例继续保持原状态执行行为；因无项目审计账本，审计追加会降级跳过。

## 3. 未做

- 不接真实账号、团队空间、认证 provider 或请求级 ACL。
- 不接云端不可篡改审计存储、对象存储、数据库或队列。
- 不改变状态执行 eligibility、候选筛选、overlay 写入和回滚规则。
- 不让 overlay 自动驱动下一轮 runner，不自动写正史账本。
- 不改 `run_scene` 默认行为，不改变既有 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 契约。
