# v1.0-beta Copyright Audit Hook-K 收口说明

> 日期：2026-06-01
> 范围：项目版权/来源声明写操作接入本地审计日志
> 代码入口：`write_project_copyright_statement()`、`memory/project_audit_log.jsonl`

## 1. 收口目标

本刀承接 Audit Log Append Policy-I 与 Project Retention Policy-J 的后续建议：先把一个关键写操作接入本地审计日志，验证 `project_audit_log.jsonl` 能承载真实产品动作，而不是只提供手动追加入口。

## 2. 已完成

- `write_project_copyright_statement()` 成功写入 `memory/project_copyright_statement.json` 后，会追加 `rights_reviewed` 审计事件。
- 审计事件写入 `memory/project_audit_log.jsonl`，并带上 `artifact_path=memory/project_copyright_statement.json` 与 `license_status`。
- `GET /api/stories/<slug>/audit-log` 会继续聚合该事件。
- 现有 `GET/POST /api/stories/<slug>/copyright-statement` 行为保持不变：坏 slug 400，缺项目 404，内置样例 409，疑似密钥内容 400。

## 3. 未做

- 不接真实账号、团队空间、认证 provider 或请求级 ACL。
- 不接云端不可篡改审计存储、对象存储、数据库或队列。
- 不把所有写操作一次性接入审计；本刀只覆盖版权/来源声明。
- 不改 `run_scene` 默认行为，不改变既有 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 契约。
