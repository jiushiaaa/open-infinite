# v0.9.3 Graph Memory Evaluation Spike 收口说明

> 收口日期：2026-06-01

## 目标

v0.9.3 的目标不是接入图数据库，而是先用当前文件型记忆底座判断是否真的需要 Zep、图数据库或 GraphRAG：

```text
触发条件复核 -> 代表性检索 probe -> 失败样例收集 -> 是否进入重依赖 spike
```

## 已完成范围

- Trigger-A：新增只读 `evaluate_graph_memory_trigger()` 与 `GET /api/stories/<slug>/graph-memory-evaluation`：
  - 读取 `import_report.json`、`memory/canon_ledger.jsonl`、`memory/entity_aliases.yaml` 与 `memory/consistency_report.json`。
  - 返回 `not_triggered` / `monitor` / `triggered`、规模指标、触发原因、阈值和中文下一步。
  - 只有 50+ 章或百万字项目叠加账本、别名或审计缺口时才建议进入图记忆评估。
- Retrieval Probe-B：新增只读 `evaluate_retrieval_probes()` 与 `GET /api/stories/<slug>/retrieval-probes`：
  - 从现有 canon ledger 与 entity aliases 自动生成代表性查询样本。
  - 复用当前 `retrieve_context()`，检查 BM25 + canon ledger + entity aliases 是否命中期望 source、item 和实体。
  - 返回 `pass` / `weak` / `insufficient_samples`、命中率、top sources、失败样例和中文建议。
  - 样本不足时明确提示先补 ledger/aliases，不把样本不足误判成图数据库需求。

## 边界

- 不接 Zep、图数据库、GraphRAG、embedding、向量库或 reranker。
- 不写新 run artifact，不替换 `retrieval_context.json` 或 `runtime_memory_context.json`。
- 不改变 `run_scene` 默认行为。
- 不破坏既有 artifact 契约：`chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json`。
- HTTP slug 仍必须走 `safe_id`；非法 slug 返回 400，缺故事返回 404。

## 结论

当前 v0.9.3 只完成评估与证据收集层，不触发重依赖接入。只要代表性查询仍能被当前 BM25、canon ledger 与 entity aliases 命中，就继续保持本地文件型记忆底座。后续只有在真实长篇样例中积累明确失败 query，并证明修复 ledger/aliases 后仍召回不足时，才进入 Zep、图数据库或 GraphRAG 的实现 spike。
