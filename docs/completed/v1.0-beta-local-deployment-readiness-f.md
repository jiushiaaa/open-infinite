# v1.0-beta Local Deployment Readiness-F 收口说明

> 日期：2026-06-01
> 范围：本地部署健康检查、环境脱敏、静态资源/API 冒烟和运行步骤
> 代码入口：`get_local_deployment_readiness()`、`GET /api/settings/deployment-readiness`

## 1. 收口目标

本刀把真实外部部署前的本地就绪状态收束成一个只读报告，方便继续从“能在本地稳定启动、可验证、无密钥泄漏”往商业化加固推进。

## 2. 已完成

- 新增 `living_novel_engine.service.deployment_readiness.get_local_deployment_readiness()`。
- 新增 `GET /api/settings/deployment-readiness`。
- 报告覆盖后端 HTTP 入口、前端静态资源、运行环境脱敏、本地数据目录、API 冒烟计划、运行步骤和验证步骤。
- 环境信息只返回密钥是否存在和脱敏尾号，不返回明文密钥或环境变量名。
- `external_services_required=false`，明确本地启动不要求真实外部模型、云端对象存储、账号系统或计费系统。
- 静态资源和本地数据目录缺失时返回 `attention`，不抛 500。

## 3. 未做

- 不接云端托管、对象存储、多用户账号、商业计费、外部监控或告警系统。
- 不创建进程守护、端口占用检测或自动部署脚本。
- 不改 `run_scene` 默认行为，不写任何运行 artifact。

## 5. 后续建议

v1.0-beta 后续仍应按本地优先方式继续拆分商业化加固。下一刀不要直接接云端多租户或计费系统；建议先复核已有 scope、权限矩阵、配额观测和部署就绪报告，再定义一个可验证、可回滚的小切片。
