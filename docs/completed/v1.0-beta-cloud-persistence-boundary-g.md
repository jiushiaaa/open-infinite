# v1.0-beta Cloud Persistence Boundary-G 收口说明

> 日期：2026-06-01
> 范围：本地 artifact 到未来平台资源的映射、保留规则和迁移边界
> 代码入口：`get_cloud_persistence_boundary()`、`GET /api/settings/cloud-persistence-boundary`

## 1. 收口目标

本刀承接 Commercial Hardening Scope-A 中 `cloud_persistence.local_first_next`：先沉淀本地 artifact 目录到未来平台资源的映射表和数据保留规则，避免直接跳对象存储、数据库或云端队列实现。

## 2. 已完成

- 新增 `living_novel_engine.service.cloud_persistence_boundary.get_cloud_persistence_boundary()`。
- 新增 `GET /api/settings/cloud-persistence-boundary`。
- 报告返回 `migration.mode=not_started`、`source_of_truth=local_file_artifacts`、`external_services_required=false`。
- `resource_map` 明确 `source_raw/`、`source/`、`memory/`、`canon/holdout_private/`、`outputs/run_*/`、`_ingest_sessions/` 和 `selected_worldline.json` 的平台候选资源、敏感级别、可见性和迁移规则。
- `retention_policy` 明确项目删除、分片过期、审计追加和 holdout 私有隔离四类保留规则。
- `local_inventory` 只读统计本地项目、run 与 ingest session 数量，不暴露绝对路径或密钥。

## 3. 未做

- 不接对象存储、数据库、持久队列、跨设备恢复、云端账号或团队空间。
- 不上传文件、不迁移数据、不写 artifact、不启动外部服务。
- 不改 `run_scene` 默认行为，不改变既有 `chapter.md`、`events.json`、`state_snapshot.json`、`multi_agent_trace.json`、`causal_diff.json` 契约。
