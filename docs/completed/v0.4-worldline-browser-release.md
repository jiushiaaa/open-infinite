## 设计边界（明确不做）

- **只读**：浏览器只读取 `projects/<slug>/` 与 `outputs/run_*/`，不写入、不修改任何数据。
- **不替代 CLI**：所有干预 / 续章操作仍走 `lne intervene` / `lne resume`，浏览器只把已生成的世界线**可视化**出来。
- **不引入新依赖**：`pyproject.toml` 未变，启动一个 stdlib `ThreadingHTTPServer`。
- **不动数据结构**：完全沿用 v0.2.x 生成的 `run_*/`、`branch_*/`、`meta.json`、`intervention.json` 字段。

## 功能矩阵

| 区域 | 来源 | 备注 |
| --- | --- | --- |
| 故事列表 | `projects/<slug>/world.yaml` + `samples/<slug>/world.yaml` | builtin 与 imported 都展示，标记 `source_kind` |
| 世界线树 | 按 `meta.parent_run_id` + `parent_branch` 建立嵌套 | 孤儿 child（parent 缺失）按根处理，不会消失 |
| 章节阅读 | `branch_<id>/chapter.md` | 缺文件时显示空态提示 |
| 分支摘要 | `branch_<id>/summary.md` | |
| 分支对比 | `compare.md` | 仅 `intervene` / `resume intervene` 类型有；`resume continue` 提示"该 run 无 compare.md" |
| 角色状态 | `branch_<id>/state_snapshot.json` | 缺字段（characters / next_chapter_hook / open_threads）逐项降级 |
| 项目元数据 | `story_contract.yaml` / `canon/facts.jsonl` / `summaries/` | v0.2.2 之前的旧项目（无这三件）显示友好提示 |
| CLI 提示 | 后端为每个 run / branch 计算可复制命令 | 点击文本即复制 |

## 复现验收链路（新窗口 / 新协作者）

### 前置：环境安装

```bash
cd engine
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

pip install -e ".[dev]"
```

安装成功后 `lne` 与 `python -m living_novel_engine.cli` 等价；
若 `lne` 不在 PATH（例如未激活 venv），统一使用 `python -m living_novel_engine.cli`。

### 前置：准备 imported demo 项目

仓库提交时不带 `engine/projects/`（`.gitignore` 排除）。验证 imported 链路前先导入一份：

```bash
# 仓库内置 3 章 fixtures，足以走通整条链
python -m living_novel_engine.cli import-novel tests/fixtures/mini_novel/ \
  --name my-story --mock
python -m living_novel_engine.cli validate-project my-story
```

### 验收 demo 链路

在 `engine/` 目录执行（命令使用 `python -m` 形式以保证 Windows / Linux 一致）：

```bash
# 1. builtin sample 链路
python -m living_novel_engine.cli intervene tianhuang-night \
  --target lin_wan_zhou \
  --content "今晚不要去城外竹林，那是墨青烟设的局" --mock
# → outputs/run_<ts1>

python -m living_novel_engine.cli resume continue run_<ts1> --branch branch_a --mock
# → outputs/run_<ts2>_continue_branch_a

python -m living_novel_engine.cli resume intervene run_<ts2>_continue_branch_a \
  --branch linear --target lin_fan \
  --content "告诉林晚舟，她身后的影子来自乱葬岗" --mock
# → outputs/run_<ts3>_resume_intervene_linear

# 2. imported project 链路
python -m living_novel_engine.cli intervene my-story \
  --target zhao_xuan \
  --content "今夜不要去归云斋，韩无归在那里设了局" --mock
python -m living_novel_engine.cli resume continue run_<ts4> --branch branch_b --mock
python -m living_novel_engine.cli resume intervene run_<ts5>_continue_branch_b \
  --branch linear --target shen_bingyue \
  --content "韩无归没有说出全部真相" --mock

# 3. 启动浏览器
python -m living_novel_engine.cli browse
# 默认 127.0.0.1:8765；占用时换端口：--port 9001
# 不自动打开浏览器：--no-open
```

## 已加固的边界（codex 关注点对应）

| codex 关注点 | 对应实现 / 测试 |
| --- | --- |
| `meta.parent_run_id` / `parent_branch` 缺失或异常时树是否稳定 | `_read_json` 捕获 `JSONDecodeError`；`build_worldline_tree` 仅在 `parent_run_id in by_id` 时才标记为子，孤儿 child 作为根呈现并打 `is_orphan=true` 标记。测试：`test_corrupt_meta_does_not_break_indexing`、`test_orphan_child_run_appears_as_root` |
| imported 与 sample 是否都能展示 | `list_stories()` 合并 `samples/` 与 `projects/`，标记 `source_kind`。测试：`test_mixed_builtin_and_imported_stories_listed` |
| 没有 `compare.md` / `state_snapshot.json` / `story_contract` 时 UI 是否优雅降级 | 前端三处分别给出空态文案；后端缺失时不写入对应键。v0.4.1：前端 `renderStatePanel` 对 `characters` 字段缺失/非对象/字段空值逐项兜底。测试：`test_branch_with_missing_files_returns_safely` |
| Windows 路径 | 通过 `pathlib.Path` 拼接；`static_dir().resolve()` + `startswith()` 防止穿越。测试在 Windows 上跑过完整套件 132 passed |
| 端口占用 | `start_browser_server` 捕获 `OSError` → `BrowserServerStartError`，CLI 转为 `ClickException`，给出明确换 `--port` 提示。测试：`test_port_in_use_raises_clean_error` |
| 浏览器自动打开 | `webbrowser.open` 失败时不再向上抛；CLI 提供 `--no-open` |
| 路径遍历 / 注入 | v0.4.1：抽出独立 `validators.py`，正则 `safe_id`；所有 URL 入口集中审计（见下表）。测试：`test_browser_validators.py` 30+ 用例覆盖典型坏输入 |
| 多故事 / 多 root / 多 orphan 排序稳定 | v0.4.1：`build_worldline_tree` 显式 `sort(key=run_id, reverse=True)`，root + orphan 同层倒序确定。测试：`test_tree_root_order_is_deterministic` / `test_tree_child_order_is_deterministic` |
| 前端坏数据 / 半数据 / 无数据白屏 | v0.4.1：`api()` 统一异常返回，调用点 `showError`/`showLoading`；`unhandledrejection` 全局兜底。所有渲染函数对缺字段降级；孤儿 run 在树中显式打 `孤儿` 角标 |

### URL 参数入口审计（v0.4.1 集中化）

所有 identifier 形参数在落盘前必须经 `validators.safe_id`：

| 路径 | 经 safe_id 的参数 |
| --- | --- |
| `GET /api/stories/<slug>` | `slug` |
| `GET /api/runs?story_slug=<slug>` | `story_slug` |
| `GET /api/tree?story_slug=<slug>` | `story_slug` |
| `GET /api/runs/<run_id>` | `run_id` |
| `GET /api/runs/<run_id>/branches/<branch_id>` | `run_id` + `branch_id` |

静态资源 `/static/<rel>` 走独立通道：`Path.resolve()` + `startswith(static_root)` 拦截穿越，允许子目录。

## HTTP API 表

| Method | Path | 返回 |
| --- | --- | --- |
| GET | `/api/stories` | 故事列表（builtin + imported） |
| GET | `/api/stories/<slug>` | 单故事详情（rules / characters / story_contract / facts / summaries / runs） |
| GET | `/api/runs?story_slug=<slug>` | run 列表（可按 story 过滤） |
| GET | `/api/tree?story_slug=<slug>` | 嵌套世界线树 |
| GET | `/api/runs/<run_id>` | 单 run 摘要（含 compare_md / intervention / meta） |
| GET | `/api/runs/<run_id>/branches/<branch_id>` | 章节 / 摘要 / 状态快照 / events / child_runs |

所有 ID 字段强制匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`，不含 `..`。

## 已知限制 / 后续状态

> 2026-06-01 后续状态：本文记录的是 v0.4 只读世界线浏览器。后续 v0.7 Product Web App 已承接普通用户主入口和取舍操作，v0.8.x 长篇项目工作台与回放审计 UI 已补齐项目资产视图，v0.9.0-alpha 已补章节导出、世界线选择和续写闭环。旧 browse 仍可作为开发者只读 viewer；实时刷新 / WebSocket 仍未做。

- 没有写操作：在 UI 内启动 `intervene` / `resume` 需 v0.5+。
- 没有大文件分页：长章节直接全文渲染（mock 模式约 2000 字，真实 LLM 可能更长）。
- 树深度无限制：链式 resume 越长越深，目前依靠 `outputs/` 量级保护；当前测试基线 6 个稳定 run + 2 条三层链路无性能问题。
- WebSocket / 实时刷新没做：刷新按钮重新拉取即可。
- `test_intervene_imported_project.py::test_write_run_output_has_story_slug` 旧测试会向真实 `outputs/` 写入 `int-test` run；这是 v0.2 遗留问题，不属于 v0.4 范围。可在后续清理。
