# v0.6.5 — 多 Agent 推演工程可靠性

> 状态：已实现（v0.6.5）。在 v0.6.4 `multi_agent_llm` runner 上补**工程可靠性**，不引入新框架，不接 Zep/OASIS/CAMEL/LangGraph。
> 前置：v0.6.4 `multi_agent_llm`（小模型推演）、v0.6.2 投影层、v0.6.3 trace 可视化。

---

## 1. 目标

让 LLM 多 Agent 推演在真实环境下**可观测、可恢复、可解释**：

- 浏览器/调试能看出这次是真 LLM 推演还是回退（之前看不出）。
- 模型偶发坏输出能自动校验/修复或重试，不让 CLI 崩溃。
- 记录 token usage，为后续成本控制留位。

## 2. 不做

- 不引入新框架 / 新依赖；不接外部服务。
- 不做并发（单次同步调用即可满足当前规模）；不做精确价格计算（`cost_estimate` 先占位 `null`）。
- 不改 `lightweight` / `multi_agent_stub` 既有行为（仅 additive 给 stub 也补 `generation_meta`）。

## 3. generation_meta（生成元数据）

每次多 Agent 推演把「trace 怎么来的」记进 `multi_agent_trace.json` 的 `generation_meta` 键（additive，旧读取不变）：

| 字段 | 说明 |
|------|------|
| `source` | `llm`（真推演）/ `fallback`（回退确定性）/ `stub`（确定性 stub runner） |
| `fallback_reason` | 回退原因（`mock_or_unavailable` / `llm_error: ...` / `validator_hard_fail`） |
| `model_name` | 实际模型名（取自 `LLMClient.settings.llm_model_name`） |
| `attempt_count` | LLM 尝试次数 |
| `duration_ms` | 生成总耗时 |
| `validation_status` | `ok` / `repaired` / `fallback` |
| `validator_warnings` | 校验告警列表 |
| `usage` | `{prompt_tokens, completion_tokens, total_tokens}`，拿不到为 `null` |
| `cost_estimate` | 占位，暂为 `null` |

`lne browse`「Agent 轨迹」标签页顶部新增「推演元数据」分组，按 `source` 显示彩色徽标（真 LLM / 回退 / stub）、模型、尝试次数、耗时、token、告警。

## 4. trace 质量校验器（`trace_quality.py`）

`validate_and_repair_trace(trace, request)` 在投影前对 LLM 产出做集中检查，**绝不抛异常**：

- **硬失败 hard_fail**：`turn_plans` 为空 → 无法投影，runner 据此重试 / 回退。
- **就地修复 repaired**（私下信息不泄漏的第一道闸）：
  - 回合号归一化到 `>=1`，且 `due_round >= created_round`。
  - 暗算/隐瞒类意图（conceal/deceive/scheme/plot/hide/betray/spy）即便标 public 也降级 private。
  - 未 `revealed` 私下信息、未 `corrected` 误解强制 `visibility=private`。
  - 补齐 `worldline_id` / `branch_seed`。
- **告警 warnings**（记录不阻断）：
  - 某在场角色缺 `turn_plan`。
  - 读者干预内容未进入目标角色的 `private_knowledge`。

修复后再交给 v0.6.2 投影层做公开层硬过滤——双闸保证模型乱标也不泄漏私下信息。

## 5. 有限重试

- LLM 调用异常或 validator 硬失败时重试，重试 prompt 带上上一轮的问题（`_retry_hint`）。
- 次数由 `LNE_MULTI_AGENT_MAX_RETRIES` 控制，默认 `1`，上限 `5`，非法值回落默认。
- 全部尝试失败 → 回退确定性 `build_demo_trace`，`source="fallback"` 且记录 `fallback_reason`。

## 6. token usage

- `LLMClient` 抽出 `_complete()` 返回 `(content, usage)`；新增 `chat_json_with_usage()` 在解析 JSON 的同时回传 OpenAI usage。
- `chat` / `chat_json` 行为不变（仍只回正文 / 解析对象）。
- 拿不到 usage（mock 或响应无该字段）时为 `null`，不报错。

## 7. 验收

- `generation_meta` 写入 `multi_agent_trace.json`；browse 能区分真 LLM / 回退 / stub。
- validator：空 turn_plans hard_fail、回合归一化、可见性强制、缺计划/干预未入私域告警。
- 重试：失败后按 env 次数重试，重试成功 `attempt_count` 递增；`LNE_MULTI_AGENT_MAX_RETRIES=0` 不重试直接回退。
- usage 有则记录、无则 `null` 不报错。
- `lightweight` / `multi_agent_stub` 零回归；全量 **269 passed**；`node --check app.js` 通过。
